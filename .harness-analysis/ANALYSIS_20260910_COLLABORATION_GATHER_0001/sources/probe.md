# 扇出聚合：工作流可观测性探针

> 目标：独立读取工作流的计划、事件、工件与结果，判断运行及证据状态是否可观测，计算有明确口径的指标，定位数据缺口；在授权范围内恢复真实存在的数据，并以可追溯补丁供执行流程采纳。
>
> 本文是一份独立使用的技能执行规范，不要求执行流程来自配套文档。它也不是一张静态指标清单：探针需要完成输入适配、采集、校验、计算、缺口诊断、补数提交和闭环核对。存储、权限与消息接入仍由宿主实现。

## 2. 探针的责任与三种模式

### 2.1 探针负责什么

探针回答四类问题：预期发生什么、实际留下了什么可核验记录、哪些指标能可靠计算、哪些缺口能够通过已有证据恢复。

它能够恢复来源版本、日志时间、尝试状态、已有来源关系或确定性统计；不能把缺少业务证据变成有证据，不能替业务流程修改结论，也不能为了好看的指标删除失败分片。

### 2.2 三种独立可选模式

| 模式 | 入口 | 允许操作 | 输出 |
|---|---|---|---|
| 独立离线审计 | 导出的日志、计划、工件、报告、固定样例 | 读取冻结输入、校验、复算、列缺口；默认不访问外部来源 | 探针报告、指标结果、缺口清单、建议补丁 |
| 在线旁路观测 | 现有工作流的事件流与只读工件接口 | 增量更新快照、核对事件完整性、计算暂定指标、诊断缺口 | 有水位与版本的持续快照及最终报告 |
| 授权主动补采 | 前两种输入，加明确的来源权限与预算 | 读取允许的日志、快照、来源元数据，提交补数或动作建议 | 可溯源补丁与采纳闭环记录 |

在线模式不自动授予主动补采权限。独立审计没有执行流程接收端时，将补丁与建议写入报告即可，状态保持“未提交”或“待处理”；不得因此声称修复已完成。

### 2.3 明确不做的事情

不分发原始业务任务，不自行扩容执行者，不直接重试业务动作，不写入业务权威状态；不修改权限、预算、验收阈值和预期分片全集；不把模型语言判断包装成已发生的时间、已使用的费用或已存在的来源。

对业务执行失败可以完成一次成功的审计；对业务已经完成也可能只能给出“观测不足”。两者必须分别表示。

## 3. 独立输入契约

### 3.1 输入包

| 输入 | 需要的字段或内容 | 缺少时的行为 |
|---|---|---|
| 被观测对象 | 工作流标识、`run_id`、计划版本、任务范围 | 不能可靠关联的材料隔离，不跨任务拼接 |
| 计划快照 | 必选和可选分片、每片对象／维度义务、验收规则、截止时间、版本 | 覆盖及计划相关指标不可计算；不能从成功返回列表反推全集 |
| 尝试与工具事件 | 分片和尝试身份、开始和结束、终态、工具调用和资源记录 | 部分运行指标不可计算；缺少终态不能自动认定失败或成功 |
| 证据工件 | 卡标识、原始值、对象、版本、维度、口径、来源、血缘、时间 | 按字段建立缺口；没有证据不允许补写主张 |
| 聚合与交接报告 | 缺片、冲突、去重、接缝、`accepted`、业务表述、交接材料及记录 | 可独立复算部分结构；不能判断原报告是否保留或交接了某项信息 |
| 对照数据（可选） | 冻结基线、人工标注或独立复算的冲突集、增加执行者前后实验 | 无对照时不输出未经支持的因果增益或冲突保留结论 |
| 场景配置 | 可比键、来源族规则、接缝规则、指标版本、风险级别 | 不适用项显式关闭；未知规则不由探针臆造 |
| 探针授权 | 模式、允许读取的资源、脱敏规则、调用与费用限制、截止时间 | 没有主动权限时保持只读导入模式 |

最小输入可以只有一份日志或报告。探针仍应完成输入审计并给出可计算项与不可计算项，但不能因为“能运行”就声称“所有指标可计算”。完全没有可用输入时返回结构化输入不足报告，而不是虚构运行记录。

### 3.2 外部工作流适配

外部流程不必采用配套执行技能，但适配器至少应映射以下概念：

| 规范概念 | 允许的外部形式 | 不允许的替代 |
|---|---|---|
| 冻结预期集合 | 作业清单、批次清单、请求任务表 | 仅有成功结果清单 |
| 逻辑分片 | 文档、地区、目录、来源任务、数据窗口 | 将同一分片的三次重试当成三个分片 |
| 一次尝试 | 执行记录、调用会话、调度记录 | 用观察到的文本条数代替调用次数 |
| 工件版本 | 文件快照、数据库不可变行、内容摘要 | 只引用随时变化的“最新结果” |
| 证据来源 | 文档、查询、代码位置、数据快照 | 无法定位的“根据官方资料” |
| 冲突和限定 | 类型化问题清单、人工标注、可复算规则结果 | 只统计最终总结中还剩多少矛盾词 |
| 交接 | 已生成的交接包和发送／接收记录 | 模型说“已交付”但没有任何记录 |

无法映射的字段保持未知，并记录适配器版本。不得用默认值填补真实缺失。没有分片语义的普通链式流程，分片覆盖、独立证据和新增执行者增益可以标为不适用，保留事件、来源、失败、时延和补数观测。

### 3.3 本探针所需的证据卡字段

核心字段为 `worker_id`、`target_ref`、`target_version`、`dimension`、`value`、`claim`、`source_id`、`source_version`、`source_lineage`、`observed_at`、`confidence`、`confidence_semantics`，沿用来源二的证据卡语义。

为了复算，还需关联 `run_id`、`plan_revision`、`shard_id`、`attempt_id`、`card_id`、工件版本与摘要；按场景增加命题标识、有效时间、单位、币种、周期、分母和来源定位。归一化结果不能覆盖原值。固定样例和生产证据必须有不同的类型标签。

## 4. 输出契约：探针报告不是业务裁决

每次输出生成不可变的 `ProbeReport` 版本，至少包含下列内容。

| 字段组 | 内容 |
|---|---|
| 身份 | `probe_run_id`、目标 `run_id`、计划和报告版本、模式、探针及规则版本 |
| 输入范围 | 工件清单、摘要、事件水位、统计截止时间、过滤规则、适配器版本 |
| 探针状态 | 已完成、部分完成、输入不足或已中止 |
| 观测质量 | 完整、部分可用、不可判定及缺失范围；不是业务成功状态 |
| 指标 | 逐项值、分子、分母、单位、状态、证据引用、计算版本与限制 |
| 发现 | 问题、支撑材料、影响的节点和指标、严重程度、是否涉及必要业务证据 |
| 缺口 | 可恢复元数据、缺少业务证据、采集损坏、权限不足、来源不可核验等分类 |
| 补数 | 补丁及基准工件引用、来源、采集过程、是否已提交及采纳回执 |
| 建议 | 仅针对受影响分片的补证、重派、局部重算或人工核验建议 |
| 闭环 | 已提交、已采纳、已重验、已关闭的缺口分别计数 |
| 自身开销 | 探针读取次数、耗时、令牌和费用或未知原因 |
| 来源账本 | 每个事实、计算和诊断对应到哪份输入或确定性规则 |

指标记录结构示例：

```yaml
metric_id: M01
metric_name: 必选分片覆盖率
metric_version: 0.1.0
run_id: 样例运行一
plan_revision: 1
snapshot_id: 快照一
value: 0.6666666666666666
numerator: 2
denominator: 3
unit: 比例
status: 可用
scope: 必选逻辑分片
as_of: '2026-09-09T15:00:00+09:00'
provisional: false
evidence_refs: [计划一, 工件索引一, 局部准入记录一]
limitations:
  - 覆盖只代表取得合格局部工件，不代表结论正确或接缝检查通过。
```

该时间和数值均是格式示例。实际输出必须使用被观测运行的时间与记录，不能复制示例。

## 5. 探针独立执行流程

```text
P00 确定观测模式、目标与权限
  → P01 读取并适配输入，冻结审计快照
  → P02 核对身份、版本、事件水位与时钟
  → P03 检查数据质量与所需字段
  → P04 生成缺口台账并判断能否恢复
  → P05 在授权范围内补采或确定性复算
  → P06 按可比组核验来源、冲突与接缝记录
  → P07 计算指标，保留分子分母和不可计算原因
  → P08 形成诊断、补丁与限定范围的动作建议
  → P09 接收采纳与重验回执，更新缺口闭环状态
  → P10 输出、封存报告及自身采集账本
```

### 5.1 P00—P02：确定范围，避免错误拼接

确认是离线审计、在线旁路还是主动补采。分别生成探针自己的运行标识与被观测运行关联，不把探针工具调用当作业务执行者调用。

按运行、计划版本和工件版本建立冻结输入视图。事件先按消息标识去重，再按同一生产者序列核验；不同机器的时间戳不能代替全局事件顺序。

记录统计截止时间、已收到的水位和仍在运行的尝试。无法确定还有多少迟到事件时，相关结果标为暂定；不能声称快照覆盖了全部事实。

### 5.2 P03—P04：先查数据能否支撑指标

逐项校验模式格式、运行归属、字段类型、原始来源、时间语义、重复事件及缺失序号。坏格式与明确空值分开；没有发生、未记录、无权限读取、读取失败也分开。

建立缺口台账，写明受影响字段、工件、指标、业务节点、必要性和可恢复依据。优先级由任务规则决定，不因为一个字段容易采集就认定它最重要。

### 5.3 P05：补采不是补写答案

离线模式只访问输入包内的数据。主动模式只访问获授权来源，并受调用、费用和时间上限约束。对来源读取结果记录版本、内容摘要、采集时间与访问范围。

可从已有终态日志恢复尝试状态，从不可变快照恢复来源版本，从规范化记录复算统计值。找不到当时的日志时不能补造当时发生时间；读取当前网页不能证明历史页面内容。

无法恢复时保留空值与原因。需要新的业务调查时生成动作建议，而不是把探针当作另一位无授权的研究执行者。

### 5.4 P06—P08：复核、计算与诊断

按照当前场景的对象、版本、命题、维度、时间和取值口径分组。独立复算已知冲突时使用冻结原卡及明确规则；不得只检查被测聚合器最终保留下来的材料。

用第 7—9 节口径计算指标，输出精确分子分母与数据来源。诊断区分“日志缺失导致无法判断”和“已有记录证明某项失败”。没有对照或因果证据时，只报告关联和观察到的贡献。

补丁只描述已被来源证实的字段。执行建议只限定到受影响分片与节点，并声明所需权限和可能成本。

### 5.5 P09—P10：核对闭环并封存

探针收到采纳回执后，还要确认执行方重验了受影响节点并更新了缺口状态。只有“补丁已发送”或“补丁已采纳”都不足以计算为缺口已闭环。

独立审计没有回执时仍可正常结束，报告标明哪些修复只是建议。最终封存输入引用、指标版本、计算日志、补丁、回执与未解决缺口。探针运行完毕不改变业务裁决状态。

## 6. 与执行流程的共享接口

### 共享协议：扇出聚合补数协议/0.1.0

本节在执行流程与探针文档中保持一致，是本次设计新增的接口约定。对方不在线时，消息可以写入本地目录、数据库表或消息队列；不得把“未收到对方响应”解释为业务检查通过。

#### 一、消息信封

| 字段 | 约束 |
|---|---|
| `schema_version` | 固定为本协议版本 `0.1.0`；不兼容版本先转换，禁止静默丢字段 |
| `message_type`、`message_id` | 消息类型与全局唯一消息标识 |
| `run_id`、`plan_revision` | 必须对应同一次业务运行及冻结的计划版本；探针自己的运行另用 `probe_run_id` |
| `producer_id`、`producer_sequence` | 生产者标识及其单调递增序号；序号只在同一生产者实例内比较 |
| `node_id`、`shard_id`、`attempt_id` | 适用时填写；运行级事件可为空，不得伪造分片归属 |
| `artifact_ref`、`artifact_revision`、`artifact_hash` | 涉及工件时绑定其确切版本和内容摘要，避免读取可变“最新版” |
| `occurred_at`、`observed_at` | 事实发生时间与被观测时间分别记录；历史发生时间无法恢复时为空并说明原因 |
| `causation_id`、`correlation_id` | 前者关联直接原因，后者关联同一条补数链；首次消息可无直接原因 |
| `data_origin` | 区分原始记录、来源读取、确定性推导、历史重放；模型猜测不是可采纳的数据来源 |
| `payload`、`evidence_refs` | 类型化载荷与支撑该消息的日志、快照或工件引用；敏感正文留在受控存储 |

#### 二、五类消息

| 消息类型 | 最小载荷 | 接收者的动作 |
|---|---|---|
| `observation_event` | 事件名称、业务对象版本、事实引用、生产者权限域 | 追加观测记录；不直接更新业务权威状态 |
| `gap_request` | `gap_id`、缺口类别、目标字段、所需语义、时间范围、必要性、允许来源、截止时间与预算 | 接收方判断能否补采；无法恢复则明确返回不可恢复 |
| `data_patch` | `patch_id`、`gap_id`、目标工件及基准摘要、字段路径、补充值、来源、采集时间、校验结果 | 执行方校验后生成派生工件新版本；不覆盖原件 |
| `action_proposal` | `action_id`、关联缺口、建议动作、限定分片、权限需求、预计资源、原因 | 仅提出补证、重派、局部重算或人工处理建议；执行方自行授权与调度 |
| `apply_receipt` | 对应补丁或建议标识、采纳状态、拒绝原因、新工件引用、重验节点及结果 | 探针据此区分已提交、已采纳和已闭环，不把发出建议计为修复成功 |

采纳状态统一为：`已采纳`、`已拒绝`、`重复消息`、`待处理`。其中“已采纳”不等于缺口已经闭环；只有后续重验通过、缺口状态更新后，才能计入闭环数量。

#### 三、补数允许与禁止

允许补充的内容包括：已有日志中的尝试状态和实际时间、已有快照中的来源版本、经过核验的来源血缘关系、依据明确规则计算的单位换算及统计值。必须能回到原始记录，且使用相应版本的规则。

**以下内容不得作为补数直接写入：**原始证据卡的观点与原始数值、业务结论、`accepted`、接缝通过状态、权限、预算、预期分片集合、验收阈值。证据主张需要变化时，应提出补证建议，由执行方取得新的证据卡；计划需要变化时，应创建新的计划版本。

补数只进入派生元数据或观测侧记录。若已有值与补采值矛盾，记录差异并提交复核，不能用“补全”名义覆盖旧值。无法补出的数据保持空值，附带原因与影响。

#### 四、采纳、重验与幂等

```text
探针发现缺口
  → 在许可来源内补采或确定性复算
  → 提交补丁／动作建议
  → 执行方核验运行、计划、基准摘要、字段白名单、来源与权限
  → 追加新版本并返回采纳回执
  → 从受影响的最早业务节点重新校验
  → 生成新报告版本并更新缺口状态
```

同一 `message_id` 重复投递只处理一次；同一 `patch_id` 重试返回原采纳结果。底层可以采用至少一次投递，但不得宣称因此获得了端到端“恰好一次”执行。业务提交、版本比较和事件发布应有可恢复的一致性机制。

基准版本已经改变的补丁拒绝或重新评估，不能直接应用到当前版本。迟到事件归入其原始运行和计划版本；已封存报告不被后台改写，必要时生成带更正关系的新版本。没有采纳回执的补丁保持待处理，不能推断已经生效。

#### 五、权限与故障边界

探针默认只读。主动补采还须具备任务范围、来源白名单、调用上限和审计记录；只读不代表没有费用、没有敏感数据风险或没有外部请求风险。

探针无权自行扩容执行者、触发业务写入、批准付款、部署、下单或修改验收条件。需要这些动作时只能提交建议。探针故障可使可观测性降级，但执行流程自身的强制证据检查和权限检查不能被跳过。

探针事件进入独立观测命名空间，默认不再次触发同类探针，避免观测自身引发无穷补数循环。

#### 六、最小联动载荷示例

下面只展示三类消息的载荷关系；正式发送仍须包含前述完整信封。所有标识及版本都是固定样例，基准摘要应由宿主对实际原件计算。

```yaml

    payload:
      gap_id: 缺口B一
      target_artifact_ref: 卡B版本一
```

## 7. 指标计算的统一约束

### 7.1 统计快照与对象

每个指标绑定运行、计划版本、输入快照、规则版本和统计截止时间。计划变更前后分别计算，不把旧版失败分片从新版分母中悄悄抹掉。

必须区分逻辑分片、执行尝试、工具调用、工件版本、证据卡、独立来源族与业务运行。它们不是同一种计数单位。

默认以冻结的最终快照计算；在线快照设置暂定标记。运行时未闭合的尝试单列，不能从时延样本中静默删除超时或尚未完成者。

### 7.2 四种指标状态

| 状态 | 何时使用 | 值的处理 |
|---|---|---|
| 可用 | 当前统计范围的必要输入及规则完整 | 输出数值和完整分子分母 |
| 部分可用 | 只能计算明确的子集或只能核验部分来源 | 整体值通常为空；子集值用独立字段并标清子集分母 |
| 不可计算 | 缺少必要计划、记录、参考集或可信口径 | `value: null`，说明缺什么及影响 |
| 不适用 | 该场景没有该概念，或无可评价事件 | `value: null`，说明不适用依据 |

分母为零时不返回无穷大、零或百分之百；先判断不适用还是输入无效。零是有意义的测量结果，不能兼任“未知”。

### 7.3 汇总与时钟

跨运行汇总仅合并相同定义和范围的数据，用分子之和除以分母之和，不平均分母不同的百分比。同一运行的多个报告修订只选明确指定版本，不重复计数。分层聚合按叶子分片集合去重，不把组数当作输入数量。

持续时间优先使用同一进程或同一可信时钟域的单调时间差。跨机时间缺乏偏移校正或误差界时，应标明不确定性，不能用负耗时强行修正成零。分位数必须同时披露样本量、未完成数量和截尾规则。

### 7.4 业务闸门与观测告警分开

覆盖率低于必选计划要求、真实冲突未保留、来源无法满足必要契约等，是否阻断业务由执行方的规则决定。探针提供证据和发现，不能自行把警告升级为交易、支付、部署等动作，也不能把自身故障解释为所有业务闸门通过。

性能阈值应依据场景目标与稳定基线配置。本文不为所有场景制定统一的耗时、费用、重试或独立证据率门槛。

## 8. 原文四项核心指标的工程化口径

以下公式为本次设计给出的可复算定义；来源二提供的是指标方向，而非这些公式的完整实现。

### M01：必选分片覆盖率

**目的：**知道冻结计划中多少必选分片返回了合格工件，而不是只知道收到了多少回调。

设 R 为冻结计划中的必选逻辑分片集合；Q 为其中全部必要对象和维度义务均有合格局部工件的分片集合。

```text
必选分片覆盖率 = |Q| / |R|
缺失分片集合 = R − Q
```

合格工件需满足当前版本的局部格式、对象、口径、必要维度和来源契约。全局接缝失败不自动删除已经局部合格的分片；未决冲突也要单独展示，不能靠覆盖率掩盖。

采集点：计划冻结、工件提交／拒收、归一化与来源核验、最终报告生成。所需证据：计划快照、有效工件索引及局部准入记录。

三片中两片合格，值为 2/3；同一片重试十次也不增加分子或分母。缺少计划全集时不可计算。R 为空且任务仍被宣称为扇出任务时属于输入配置问题，不报百分之百。

可选分片另算可选覆盖率；必须同时输出必要对象／维度义务的覆盖明细。只做到分片数量齐全但内部维度缺失的分片不进入 Q。

### M02：独立证据率

**目的：**避免把三位执行者重复引用同一来源看作三份独立证据。

本指标按同一可比命题组分别计算，比较组包含对象与版本、命题、维度、有效时间及取值口径。不同维度不能混成一个投票分母。

设某组 N 为有效证据卡数量；I 为按照已声明血缘核验规则确认的不同上游来源族数量。一个来源族即使有多篇转载、多次引用或多位执行者，也只计一次。

```text
独立证据率 = I / N
```

这是**已声明来源血缘核验范围内的操作性指标**，不是对统计独立性的数学证明，更不等于正确概率。必须同时展示 N、I、同源关系和核验范围。不同域名、模型或会话不自动使 I 增加。

采集点：证据卡提交、来源定位、来源血缘分组、去重完成。所需证据：原始卡、来源关系、关系核验依据与规则版本。

同一命题下三张卡都来自同一公告，N=3、I=1，独立证据率为 1/3。会话、工作区和工具三种维度应分别显示各自来源，不能把跨维度来源合成支持“完全隔离”的票数。

**来源血缘未知的处理：**整体独立证据率设为空，另列已核验卡数、已确认来源族数、未知卡数及可核验子集值。不得把未知来源全部计为独立，也不得把子集比率冒充整体比率。没有卡时为不适用或证据不足，依任务语义说明。

全局不同来源族总数可以作为描述性计数，但不能替代同一命题的核验。跨命题汇总的组内来源族计数可能重复涉及同一来源，必须披露这一点，不能称为全局唯一来源数。

### M03：冲突保留率

**目的：**检查已知冲突是否被完整保留并进入应有的后续处理材料，而不是在压缩时消失。

设 K 为当前快照的已知参考冲突集合；K 的来源只能是人工标注、固定样例标签或针对冻结原卡的独立复算。每个冲突标识绑定同一可比命题、互斥双方及原始卡引用。

设 H 为 K 中同时满足以下条件的冲突集合：最终聚合报告保留冲突身份、双方内容、限定和来源；交接材料包含该冲突，且有交接包生成并发送的可核验记录。

```text
冲突保留率 = |H| / |K|
```

单独保留“存在争议”四个字不计入 H。已裁决冲突可以计入，但必须保留原始双方与裁决记录。不同维度差异不进入 K；该指标不是要求强行制造冲突。

采集点：原卡快照、冲突核验、最终报告、交接包及发送记录。仅读取最终总结无法构造可靠的参考冲突分母。

若无法取得交接记录，核心指标不可完整计算，可以另列“报告内保留率”，但不得称为已经送入裁决。实际执行方是否已作出裁决又是另一状态。

**已知冲突不是全部真实冲突。**独立复算只能覆盖其规则可以识别的冲突，必须报告参考集来源与范围。不能仅用被测聚合器自己发现的冲突作分母来声称整体保留率百分之百；最多标为自检范围的代理结果。K 为空时不适用，不报百分之百。

### M04：新增执行者的增量收益

**目的：**判断额外执行者增加了什么，而不是只观察总输出更多。

比较前必须冻结同一任务全集、可比口径、来源政策、质量规则与统计窗口。新增执行者负责补原有覆盖或增加原有命题的证据，而不是把任务目标换大后直接比较。

```text
覆盖增量 = 新配置覆盖率 − 基线覆盖率
来源增量 = 新配置已核验来源族数 − 基线已核验来源族数
费用增量 = 新配置总费用 − 基线总费用
时长变化 = 新配置墙钟时长 − 基线墙钟时长
```

同时保留令牌、调用、重试和聚合开销变化。来源增量按同一比较组计算，不用新增不同维度的卡假装增强原命题支持。

没有通用的单一收益总分。只有业务提前声明权重、质量门槛和效用函数，才可计算综合值；不能事后选择权重证明扩容有价值。

有冻结对照实验时，按实验设计报告结果及变动范围；只有一次运行时，可分析某位执行者提供的独有覆盖或来源，称为“观察到的贡献”，不能称为因果收益。利用移除某路结果的复算，也不能推断没有该执行者时真实调度、费用和延迟必然相同。

没有可比基线时该指标不可计算。费用增量为零、为负或未知时，不机械计算每元收益；直接报告各项差值及条件。并发时长不能拿各路时长之和替代实际墙钟时长。

## 9. 运行、数据质量与补数指标

下表除超时、拒收率、收口耗时方向来自原文外，其余均为本次补充。启用哪些项目由场景配置决定，不要求每个工作流全部开启。

| 编号与指标 | 定义与统计对象 | 必需输入与限制 |
|---|---|---|
| M05 缺席披露率 | 最终报告中正确列出的缺失必选分片数 ÷ 独立核对得到的实际缺失必选分片数 | 需要冻结 R、有效 Q 和报告；无缺片时不适用，缺计划时不可计算 |
| M06 可比口径完整率 | 必要对象、时间、单位、分母等字段满足场景契约的卡数 ÷ 当前待验卡数 | 字段不适用必须有规则；完整不等于内容正确；卡清单不完整时只报子集 |
| M07 来源链完整率 | 必须的主张—卡—来源—版本／快照定位均可回溯的卡数 ÷ 应检查卡数 | 必须来源链清单由场景定义；来源血缘独立性是另一个检查，不因地址可访问就通过 |
| M08 同源重复率 | 同一可比组内，因已核验同源关系被标记为冗余的卡数 ÷ 有效卡数 | 未核验血缘时整体值为空；保留代表卡与原卡映射，不实际删除原件 |
| M09 分片最终超时率 | 最终以超时收口的必选逻辑分片数 ÷ 冻结必选分片数 | 需权威终态与截止政策；在线仍运行时标暂定；曾超时后成功不计最终超时 |
| M10 工件拒收率 | 在选定快照被明确拒收的唯一提交工件版本数 ÷ 进入准入检查的唯一提交工件版本数 | 先按工件版本去重；待检查版本另列，终态未知时整体不完整 |
| M11 收口耗时 | 单轮聚合报告提交时刻 − 该轮 N04 聚合开始时刻 | 不含开始聚合前等待分片的时间；补数多轮分别计时，另报端到端总时长；时钟不可信时不可计算 |
| M12 接缝检查覆盖 | 已有确定结果的必需接缝规则数 ÷ 冻结必需规则数，并另列通过、失败、未知数 | 失败规则属于已检查，但绝不等于通过；无适用规则时不适用并说明 |
| M13 首次工件合格率 | 首次尝试即产出满足局部契约工件的必选分片数 ÷ 已启动首次尝试的必选分片数 | 在线首次尝试未结束时结果暂定；未启动分片另列，不能隐藏调度缺口 |
| M14 重试放大率 | 业务执行尝试总数 ÷ 已启动的唯一逻辑分片数 | 无重试且每片启动一次时为 1；探针读取不计业务尝试；无启动时不适用 |
| M15 补数闭环率 | 已通过来源核验、被采纳、完成重验且关闭的可恢复缺口数 ÷ 已到处理截止点的可恢复缺口数 | 按缺口标识去重，不按补丁条数；新发现未到期缺口另列；不可恢复业务证据缺口单列 |
| M16 关键事件记录完整率 | 已核验的关键事件实例数 ÷ 应有关键事件实例数 | 分母来自冻结计划、权威状态或生产者清单，不以已收到事件反推；缺少可信清单时不可计算 |
| M17 探针观测开销 | 探针实际读取次数、墙钟时长、令牌、费用分别报告 | 与业务分账且共享总授权上限；费用未知不填零；无对照不声称探针增加了多少业务延迟 |

“尝试超时率”可另算超时尝试数除以终态已知尝试数，但必须与 M09 分开，并披露仍运行或终态缺失的尝试。不能把逻辑分片的分母与尝试级分子混用。

对于 M10，一次工件从初审到复核应由版本和检查记录明确区分；同一版本反复投递不增加分母。对修订后的新版本检查可作为新的版本事件，但若需要衡量逻辑分片成功率，应使用 M01 或 M13，而不是借拒收率代替。

## 10. 数据缺口台账与补数规则

### 10.1 缺口类型

| 类型 | 示例 | 探针能做什么 | 不能做什么 |
|---|---|---|---|
| 可恢复元数据 | 已有快照中的来源版本未导出 | 从获授权快照取回，提交派生元数据补丁 | 给未知版本填一个看似合理的值 |
| 可恢复运行记录 | 事件导出漏行，但权威调度日志保留终态 | 读取原记录，保留原发生时间与新采集时间 | 把发现时刻当作原结束时刻 |
| 可确定性推导 | 原始金额和单位齐全，存在明确换算规则 | 记录公式、规则版本、输入引用和派生值 | 无授权汇率或时点就跨币种加总 |
| 业务证据缺失 | 某维度从未调查或没有结果 | 请求执行方补证或明确保留不足 | 自行产生业务主张并伪装成补数 |
| 来源血缘未知 | 多篇文章是否转述同一公告不明 | 在授权范围核验引用；无法确认则保持未知 | 仅靠不同网址认定独立 |
| 历史不可恢复 | 没有旧快照，来源已经改变 | 标不可恢复并说明报告受限范围 | 将当前内容倒填为历史事实 |
| 采集完整性问题 | 事件序号断裂、清单不全、时间不可信 | 请求重放、读取权威清单或降级指标 | 用收到的成功记录补出全集 |
| 授权或成本限制 | 来源存在但无读取权、预算耗尽 | 停止采集，报告限制与建议 | 绕过权限或无限扩展搜索范围 |

### 10.2 缺口记录

每条记录至少包含：缺口标识、运行和计划版本、目标工件、字段路径、原因、必要性、影响的业务节点和指标、允许来源、恢复方法、截止时间、预算、状态和证据引用。

状态为：已发现、待采集、已补采、已提交、已采纳、已重验、已关闭、不可恢复或已拒绝。状态推进须有对应事件，不因模型叙述而自动前进。

“必要性”分为业务强制数据、观测计算必要数据和可选诊断数据。业务强制数据不能因探针不可用而放行；可选诊断失败不应无条件阻塞整个任务。分类由场景政策决定，不由探针临时调低。

### 10.3 补数后重验的依赖

| 补充内容 | 通常受影响的位置 | 要求 |
|---|---|---|
| 来源定位或版本 | 局部工件准入、覆盖、归一化及其下游 | 执行方从受影响的最早节点重验，不直接改覆盖数字 |
| 对象映射、单位或分母 | 归一化、去重、冲突、接缝和报告 | 保留原值及转换依据，重建依赖工件 |
| 来源血缘 | 来源族、独立证据率、依赖独立性的裁决 | 保留旧版来源分组及变化原因 |
| 历史运行日志 | 观测侧时延、尝试和资源指标 | 若与业务权威状态矛盾，提交差异核对；不得直接覆盖业务状态 |
| 补采回执与重验记录 | 补数闭环统计、报告修订关系 | 只有重验和缺口关闭有证据时才计为闭环 |

重验结束后仍不满足要求的补丁可以已经被采纳，但缺口尚未关闭。观测数据更完整不代表业务结果更好；发现新的冲突或来源重复可能使原先看似良好的报告失去准入。

## 11. 幂等、时间、权限与故障处理

### 11.1 时间范围与迟到

在线探针保存水位及统计截止时间。迟到事件用于修订同一运行的新快照，旧快照保留。已封存业务报告是否更正由执行方或授权流程决定，探针仅报告差异与建议。

证据的采集时间、内容有效时间和事件发生时间分开。对迟到事件不能按照新采集时间挪到另一个业务周期，使失败从原统计窗口消失。

### 11.2 幂等与关联

按消息标识去重事件，按工件标识和版本去重提交，按逻辑分片去重覆盖，按缺口标识去重闭环；这四种去重不能共用一个计数单位。

同一补丁的多次发送只对应一次采纳。过期基准补丁不自动重放到新工件。观察到业务报告更新但没有补丁因果链时，不能把改善全部归因于探针。

### 11.3 权限和信息安全

来源访问遵循最小权限，返回材料不改变系统指令；未知链接和资源路径须经允许的解析器处理，不能因为它出现在证据卡里就获得访问授权。

敏感信息采用受控引用、必要脱敏和保存期限。日志保存证据摘要、动作事实、规则与来源，不采集无关私人数据，不要求存储模型私有推理过程。

探针读取也会占用连接、费用和配额，应有独立限额与全局限额。耗尽预算时先保留缺口，不通过降低可信要求继续“凑齐”。

### 11.4 探针故障

自身采集异常时生成探针失败记录及已取得的部分结果；不更改业务运行成功／失败状态。执行方可以继续完成不依赖缺失观测的工作，但不能跳过自身的强制证据与权限检查。

离线复盘没有实时数据并不构成自动失败，只需准确说明审计范围。线上缺失必要证据则仍须由执行方按证据不足处理，不能将“可观测性降级”用作放行借口。

## 12. 场景适配与可选探针组合

| 场景 | 优先启用 | 需要替换的规则 | 可关闭的内容 |
|---|---|---|---|
| 多源研究与框架核验 | 覆盖、来源血缘、口径、冲突保留、增量收益 | 对象版本、维度、来源允许范围与核验策略 | 与任务无关的金额或资金接缝规则 |
| 文档批次处理 | 必选分片覆盖、缺席披露、重复对象、超时与拒收 | 文档标识、批次、版本、审查责任 | 不进行同一命题核验时的独立证据率 |
| 数据对账 | 单位与分母、来源链、重复证据、总量接缝 | 实体主数据、周期、币种、允许转换与差额规则 | 不存在并行配置比较时的增量收益 |
| 代码和安全扫描 | 提交覆盖、版本一致、告警来源、冲突和跨模块接缝 | 仓库版本、规则库、漏洞或告警标识 | 不适用的统计置信度组合 |
| 运维排查 | 事件完整、时钟、来源、收口时延与缺口恢复 | 时间同步、服务与请求标识、因果证据要求 | 没有可靠基线的因果收益指标 |
| 一般链式或单执行者流程 | 事件、工件、失败、时延、来源与补数闭环 | 外部节点与尝试映射、最小日志和业务闸门 | 没有分片或多源命题时的扇出专用指标 |

同一个探针可以在不同场景使用不同指标配置，但指标标识相同而计算定义变化时必须升级指标版本。不能在仪表盘上保持同名却暗中换分母。

## 13. 固定样例与手工验算

### 13.1 样例一：补元数据，不补业务主张

与执行文档的教学情境一致：R={A,B,C}，三片分别负责会话、工作区和工具边界。B 的原卡已经写有工作区共享，但导出缺少必要的来源版本；不可变样例快照中保留了版本。以下数值仅用于测试规范。

| 项目 | 补数前 | 授权补数且执行方重验后 |
|---|---|---|
| 必选分片数 | 3 | 3 |
| 合格分片数 | 2 | 3 |
| M01 覆盖率 | 2/3，约 66.67% | 3/3，100% |
| 必要缺口 | B 的来源版本缺失 | 原缺口已重验关闭 |
| 工作区业务主张 | 原卡已经存在“共享” | 仍为“共享”，探针未修改 |
| 结构准入 | 不通过 | 若其余规则满足则通过 |
| 业务表述 | 必要证据尚不充分 | 保留三种维度限定，不能称为完全隔离 |

三个维度分别分析来源，不进行跨维度投票；已知真实冲突集为空时 M03 不适用，不能填百分之百。独立证据率必须按各可比组分别计算，不把三张不同维度的卡混算。

若 B 根本不存在原卡，则本样例的来源版本补丁不成立，覆盖仍为 2/3，只能提出新证据采集建议。

### 13.2 样例二：工件齐全但来源重复

这是另一个独立测试，不与三维边界案例混算。三位执行者针对同一对象、同一版本、同一维度、同一命题，各返回一张合格卡；经核验全部转述同一份原始公告。

```text
有效卡数 N = 3
已核验来源族数 I = 1
独立证据率 M02 = 1 / 3 ≈ 33.33%
同源冗余卡数 = 2
同源重复率 M08 = 2 / 3 ≈ 66.67%
```

原始卡仍保留三张，展示可以使用一张代表卡并引用另外两张。三位执行者同意不表示存在三份独立支持。

### 13.3 样例三：已知冲突被压缩掉

冻结原卡和独立参考集中共有两个真实冲突。最终报告与有记录的交接材料只完整保留其中一个，另一个被压成一致结论。

```text
已知参考冲突数 |K| = 2
完整保留并进入交接材料的冲突数 |H| = 1
冲突保留率 M03 = 1 / 2 = 50%
```

该结果只说明参考集内的保留情况，不证明未被标注的其他冲突不存在。没有交接记录时，不能套用此数值，应改报仅报告内的保留结果并标记交接未知。

### 13.4 样例四：区分来源增量与增员数量

在同一冻结任务下，基线三片中两片合格，新增执行者补齐原本缺少的一片；覆盖增量为 1/3。若它还只重复原有命题的同源引用，该命题的来源增量为零。

覆盖改善与来源改善是两个维度。费用和墙钟时长没有实测对照时保持未知，不能直接推断整体更划算或更快。

## 14. 回归与验收用例

以下为待接入实现的回归要求，不表示真实采集器和业务宿主已经通过集成测试。

| 编号 | 测试输入／故障 | 预期行为 |
|---|---|---|
| P01 | 已知三片，两片合格 | M01 为 2/3；缺席清单能定位第三片 |
| P02 | 只有成功结果，没有计划 | 覆盖不可计算；不把结果数量当作计划全集 |
| P03 | 同一分片重试并重复投递事件 | 覆盖不重复计数；重试放大率使用尝试数 |
| P04 | 同命题三卡同一上游来源 | M02 为 1/3，M08 为 2/3，原始卡仍在 |
| P05 | 三卡不同网址但血缘未核验 | M02 整体为空，列出未知来源，不自动计为三份独立证据 |
| P06 | 会话隔离、工作区共享、工具受限 | 不误标为同维度冲突，不做多数表决 |
| P07 | 两个参考冲突只完整交接一个 | M03 为 1/2，并能定位丢失的冲突 |
| P08 | 无参考冲突、无可靠参考集或无交接记录 | 分别标不适用或不可计算；不伪造百分之百 |
| P09 | 事件时间来自不可信跨机时钟 | 不输出未经校正的确定时延，记录时钟限制 |
| P10 | 读取当前网页尝试补历史版本 | 拒绝历史倒填，生成不可恢复或需历史快照的缺口 |
| P11 | 补丁已发送但没有采纳或重验回执 | 不计补数闭环，不声称业务状态已改善 |
| P12 | 补丁试图改 `accepted` 或原始主张 | 拒绝并留下审计记录 |
| P13 | 旧版本补丁到达已修订工件 | 拒绝或重新评估，不能无条件套用 |
| P14 | 没有执行流程接收端 | 独立生成报告与建议，仍可完成审计，不触发业务运行 |
| P15 | 探针预算耗尽或来源无权限 | 停止主动采集，输出部分结果与明确限制 |
| P16 | 新增执行者但没有可比基线 | 不输出因果收益；仅可报告可核验贡献 |
| P17 | 一组九片合格、一组一片失败 | 叶子覆盖为 9/10，不把两组平均为 1/2 |
| P18 | 单执行者链式流程没有分片语义 | 专用指标标不适用，通用事件与补数观测照常 |
| P19 | 观测事件再次进入被观测事件流 | 命名空间隔离，避免递归触发和虚增业务调用 |
| P20 | 聚合器与探针采用不同指标／规则版本 | 拒绝无说明的直接比较，输出版本不兼容提示 |

最终验收重点：没有计划不伪算覆盖、未知血缘不伪算独立、没有参考集不伪算冲突保留、补丁没有重验不算闭环、没有对照不声称因果收益、任何补数都能回到来源。

## 15. 独立调用任务模板

```text
执行工作流可观测性探针。
使用提供的计划、事件、工件、报告、场景规则及明确授权作为输入。
先识别可观测范围，冻结运行、计划和工件版本，不从成功结果反推预期全集。
按 P00—P10 运行；仅在授权范围内补采已有事实，未知内容保持空值。
逐项输出指标值、分子、分母、状态、证据引用和限制。
缺少业务证据时提出限定范围的补证建议，不改写主张、业务结论或验收阈值。
有执行接收端时提交符合协议的补丁并核对回执；没有接收端时独立输出审计报告。
补丁提交、补丁采纳、重验完成和缺口关闭分别记录。
最后输出探针报告、缺口台账、补丁与建议、采集账本及自身开销。
```
