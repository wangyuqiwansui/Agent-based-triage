| 四类缺口走不同流程 | 所有补证采纳都要求业务复验 | 业务未完成回执行；业务证据须业务复验；观测记录用观测修复回执；权限缺口回授权流程 |
| 补证必须有边界 | 缺少尝试、时限、路径与累计预算检查 | 增加获准来源和路径、主动读取授权、独立观测运行、期限、幂等键、累计读取与轮次预算 |

| 探针可独立检查其他流程 | 计量过度依赖执行记录形状 | 新增标准数据适配接口，无需启动执行，也无需伪造任务卡和业务验收 |
| 先跑可比基线再评估收益 | 旧时间、质量、完成率差口径未对齐 | 明确共同完成配对、全入组分母、失败成本、预声明统计方法、质量单位及计时终点 |

## 接入边界与后续顺序

1. 在实际工作流提供身份和来源核验器，认证计划、当前版本、尝试、义务集合、数据完整性及时间域。自哈希和恒真核验器不构成真实权限或事实证明。
2. 接入既有动作、事件存储与权限边界，实际验证副作用核对、条件写入、依赖恢复、可读性和隔离；参考内核只核验宿主提供的原子承责回执，不能证明底层数据库已经正确提交。
3. 由持久账本实现幂等和并发预算控制。`gap_usage` 表示本包之前的可信累计用量；当前纯校验器不会原子预占预算，也不自动重读、重试或扩权。
4. 运行 66 项原文集成场景并保存真实回执，再接入上表 14 项缺失计量。历史采纳按当时的有效时间和留存依据审计，不把后来过期改写为当时未采纳。
5. 用同一冻结任务组、输入、验收规则、资源单位和评估截点开展单体基线对照。保留失败、超时、未开始及未结束样本后，才讨论协作收益和成熟度提升。
