# 对抗评审：工作流可观测性探针

> 目标：发现执行流程缺失了哪些可验证数据，重建事件与版本关系，计算可解释指标，并把补数提案准确送回需要它的节点。
>
> 核心边界：探针补全可验证的数据，不补造事实，不代替评审，不关闭阻断，不签发批准，不执行发布。

## 1. 来源、文档定位与通用性

本文件以《Hanerss Skill Framework v0.1》和用户提供的黄佳《对抗评审：让独立异议真正约束结果》正文为依据。

框架提供认知、拓扑、工程模式的三大基座、注册表、矩阵、稳定标识和技能模板；原文提供独立异议、风险覆盖、版本绑定和放行约束等观测对象。**原文没有给出本文的完整探针流程、指标公式、补数接口或告警阈值，这些均为本设计补充。**图片仅有链接，本文不复原未提供的图中文字或图表。

本探针由“通用观测核心＋场景适配器”组成。本文件完整描述通用核心，并给出对抗评审适配器。用于其他场景时替换字段映射和特定检查，不要求那个工作流也具备评审回执。

| 层次 | 固定职责 | 可替换内容 |
|---|---|---|
| 通用观测核心 | 采集、关联、去重、数据质量、缺口、可计算性、补数、审计。 | 来源接口、字段路径、权限、时间窗口和预算。 |
| 对抗评审适配器 | 候选版本、异议、风险覆盖、评审包、批准回执、发布结果的一致性检查。 | 风险清单、规则、评审责任与具体业务动作。 |
| 其他场景适配器 | 按其自身状态机识别必要证据与控制结果。 | 路由、并行任务、数据分析、计划执行等专属对象。 |

本文为独立可实施的工作流规约，不是一个已经安装的采集服务；示例中的数值和事件均明确标注为演示或测试数据，不代表用户系统的真实表现。

## 2. 框架挂载与职责界面

### 2.1 挂载建议

建议技能标识为 `SKILL_OBSERVABILITY_0001`，本场景关联工程模式 `PATTERN_REVIEW_0001`。两者需在接入时查重并正式登记，不表示已经写入注册表。

本设计将探针主要挂到感知与治理，引用 `COG_PERCEPTION`、`COG_GOVERNANCE`；采集到报告为链式，缺口按类型分派为路由，引用 `TOP_CHAIN`、`TOP_ROUTING`。这是技能层的组织映射，不改变原文把“对抗评审”定位为协作维度、循环拓扑的归属。

工程模式仍以注册表为源；不能因为探针用了路由，就把对抗评审模式的主拓扑从循环改成路由。迁移到其他模式时，由目标模式登记关联；不要给所有工作流硬套本模式标识。【来源一：第4—5、8—9、12—18节】

### 2.2 与执行流程的分工

| 事项 | 执行流程 | 探针 |
|---|---|---|
| 冻结候选、证据、规则 | 拥有与维护。 | 读取、验证引用关系、发现缺失或不一致。 |
| 必审风险和角色授权 | 制定并确定性检查。 | 测量完成情况、核查结构证据。 |
| 评审与异议关闭 | 由授权评审者及裁决机制执行。 | 观察记录，检查是否有规则与关闭证据。 |
| 回执和实际发布 | 签发、复核、执行并核对。 | 检查绑定、时效、旁路发布迹象。 |
| 数据补全 | 验证并接收，决定是否重审。 | 从允许来源采集，形成有来源的提案。 |
| 指标、告警和数据质量报告 | 可消费结果，不把指标总分当批准。 | 生成并解释分子、分母、缺失和限制。 |

**探针报告“未发现问题”不能作为批准回执。**探针报告的“数据不足”也不等于业务必然不合格，应由执行方区分关键放行证据不足与非关键遥测缺失。

## 3. 独立启动条件与产出

### 3.1 三种运行方式

| 方式 | 最小输入 | 输出与边界 |
|---|---|---|
| 离线独立 | 一组日志、控制账本导出、工件快照及已知规则；不要求执行流程在线。 | 观测报告、可计算指标、缺口、待接收补数提案；无法验证的项目明确保留未知。 |
| 在线旁路 | 事件订阅或只读查询、场景映射、权限范围。 | 持续观测与风险发现；不阻塞普通业务节点，不拥有发布权。 |
| 按需补数 | 来自执行方的有范围请求及授权来源。 | 补数提案及状态；收到接受确认后才计为补数成功。 |

独立运行不意味着无需任何数据。只有候选正文、没有评审或发布记录时，可以检查材料缺口，不能计算真实阻断执行率或宣称已经确认发布安全。

### 3.2 输入契约

必需输入：数据源或文件清单、场景适配器、采集范围、授权、输出位置及预算。若要计算评审控制指标，还需要审查基线、规则、必审风险、结果、异议及回执等权威记录；缺失这些不必让整个探针崩溃，但受影响指标须降为不可计算。

```yaml
探针配置:
  运行方式: "离线独立"
  场景适配器: "对抗评审"
  数据范围:
    租户标识: "租户-甲"
    运行标识: ["运行-001"]
    事件起点: "运行开始"
    事件终点: "指定控制账本序号"
  输入:
    工件快照引用: ["本地工件包-001"]
    控制账本引用: ["本地账本导出-001"]
    规则包引用: ["规则-001"]
    外部发布记录引用: []
  能力范围: ["读取", "关联", "校验", "计算", "输出补数提案"]
  输出:
    观测报告: "输出目录/观测报告"
    指标记录: "输出目录/指标记录"
    缺口清单: "输出目录/缺口清单"
    补数提案: "输出目录/补数提案"
  最大采集次数: 2
  探针预算引用: "探针预算-001"
```

示例没有外部发布记录，因此不能独立排除绕过控制入口的发布；该限制必须出现在输出中，不可把空列表理解成“没有发布”。

### 3.3 标准产出

探针至少输出六类对象：观测报告、指标记录、缺口清单、风险发现、补数提案、探针自身运行记录。空结果也需要说明是“确认没有”“来源缺失”“范围不适用”还是“尚未完成”。

所有报告带数据截至点、指标定义版本、来源与覆盖情况；迟到事件或后续纠正产生新报告修订，不覆盖历史结论。

## 4. 最小共享协议

### 共享契约的适用范围

本节为两份文档共同内嵌的最小契约，契约版本为 `0.1.0`。内嵌是为了允许任一文档单独实施；两份文档同时接入时，以部署时登记的同一契约版本校验，不允许各自修改同名字段的含义。

业务执行方拥有候选工件、异议处置、裁决、授权和发布状态；探针只拥有采集任务、观测记录、指标结果与补数提案。**观测数据完整，不等于业务证据充分；业务证据充分，也不等于已经获得放行授权。**

### 关联键与时间语义

| 字段 | 含义与约束 |
|---|---|
| 租户标识 | 数据与权限隔离边界；跨租户对象不得关联或补写。 |
| 运行标识 | 一次工作流实例；重试不另建运行，重新发起业务任务则另建运行。 |
| 工件标识、工件版本 | 被评审对象及不可变版本；通用非工件流程可按适配器声明为不适用。 |
| 审查基线摘要 | 对本轮正文、证据清单、规则、风险清单、评审计划及动作边界的联合绑定。 |
| 评审轮次 | 对一个审查基线进行完整审查的一轮；规则或证据改变后必须另起轮次。 |
| 节点标识、尝试序号 | 区分逻辑节点和该节点的重试，不用重试次数扩充业务样本。 |
| 事件标识、账本序号 | 事件唯一去重键与运行内权威顺序；重复投递不产生新的业务事实。 |
| 关联事件标识 | 当前事件的直接依据、触发事件或被更正事件，不要求只有一个。 |
| 发生时间、采集时间 | 事实发生时间与探针收到时间分开保存；未知发生时间不得用采集时间冒充。 |
| 观测修订号 | 旁路观测区的并发控制版本，不等于工件版本或审批版本。 |

审查基线不包含后续才产生的评审结论，避免循环计算；回执另外绑定最终评审包摘要与闸门裁决记录。摘要只能证明绑定与变化，不能证明材料真实，也不能单独证明签发身份。

### 最小事件信封

下列为字段结构示例，示例标识不代表真实运行记录。非适用字段必须显式为空并附原因，不得随意丢弃。

```yaml
契约版本: "0.1.0"
事件标识: "事件-001"

评审轮次: 1

尝试序号: 1
账本序号: 12
关联事件标识: ["事件-009"]
```

主体身份、来源类型和账本序号必须由可信接入层验证，不能相信载荷自报。只读导出缺少验证材料时，标注“来源未验证”，不得提升为已验证事实。

### 接收与回流规则

接收方依次验证：契约兼容、身份与权限、租户、关联对象、请求仍有效、基线与轮次、来源真实性、证据时效、字段白名单、预期修订号。失败时只写拒收记录，不得部分覆盖业务对象。

幂等键使用“租户标识＋请求标识＋提案标识”；同键同内容返回原结果，同键不同内容按冲突拒绝。接受结果只能是：

| 接受结果 | 执行方动作 |
|---|---|
| 已接受为观测补充 | 追加旁路观测记录，以条件更新递增观测修订号；不修改审批依据。 |
| 已接受并触发重新评审 | 执行方登记新证据或新配置，建立新基线；旧回执失效，再恢复指定验证节点。 |
| 待人工核实 | 保存提案，不视为事实，不推进受影响的放行条件。 |
| 已拒绝 | 记录过期、错版、越权、冲突等原因；不推进工作流。 |

收到确认前，探针不得把“提案已发送”记为“数据已补齐”。执行方重启后重放接受结果，不能二次应用同一提案。迟到提案可归入旧版本历史，但不得自动作用于当前版本。

### 写入白名单与受保护字段

探针可以追加自己的观测结果，以及向执行方提交补数提案。探针不得直接修改：候选正文、业务证据清单、规则、必审风险清单、评审结论、异议状态、权限、批准状态、评审回执、发布状态。

对已有权威事实的旁路补录，保留原值、来源与补录时间；对涉及审查依据的新增、替换或纠正，必须由执行方建新基线。无法获取的历史值保持缺失；推断值仅可写入单独的“推断候选”区。

### 观测发现与控制响应

探针发现疑似硬伤时提交“风险发现”，不是自行签发否决或批准。执行方验证该发现；若发现影响当前放行依据，登记待裁决问题并暂停相关放行，再交由授权评审者确认。已经形成的阻断异议，在被授权主体按既定工作流关闭之前持续约束闸门。

探针停机不能使业务闸门跳过必要检查。必要证据不足时，执行流程即使不接探针也必须暂停；仅非关键耗时、成本等观测字段缺失时，可继续业务并记录观测降级。

## 5. 探针自身的执行流程

```text
接收观测任务与授权
    ↓
固定观察范围、规则及数据截至点
    ↓
采集并保留原始来源
    ↓
标准化、去重、关联运行／版本／评审轮次
    ↓
重建实际路径与预期责任清单
    ↓
检查完整性、一致性、时效及来源
    ├→ 非关键观测缺口 → 允许来源补录，或标注不可计算
    ├→ 关键业务证据缺口 → 提交有范围的补数提案或风险发现
    └→ 无法验证／来源冲突 → 保留未知，提出核查要求
    ↓
按适配器执行控制一致性检查
    ↓
计算指标并标注可计算性
    ↓
输出报告、缺口和提案
    ↓
在线时接收执行方回执；离线时保留待接收状态
    ↓
记录探针自身成本、失败与数据质量
```

| 节点 | 必要动作 | 产出 | 失败策略 |
|---|---|---|---|
| 探针-00：受理 | 确认数据范围、用途、租户、权限与适配器；禁止隐式扩权。 | 观测任务契约。 | 无读取权限则输出受限报告，不扩大来源。 |
| 探针-01：固定范围 | 记录截止账本序号、源系统水位、规则与指标定义版本。 | 观察快照与来源清单。 | 无结束水位则标为暂定窗口。 |
| 探针-02：采集 | 读取已授权事件、快照、评审结果及外部结果；记录来源验证方式。 | 原始观测包。 | 有限重试；失败记录不伪装为零事件。 |
| 探针-03：标准化 | 校验契约、事件唯一键、时间与类型；保留原始值和映射依据。 | 规范事件、隔离错误记录。 | 不合法记录进入隔离区，不静默丢弃。 |
| 探针-04：关联重建 | 按运行、版本、基线、轮次、操作标识关联；识别父子版本与因果。 | 版本图、责任清单、发布链。 | 无可靠关联键就标无法关联，不凭相似文本强连。 |
| 探针-05：质量检查 | 对照预期对象检查缺失、冲突、时效、重复与异常顺序。 | 字段级缺口与来源质量结果。 | 区分事实错误与缺少证明。 |
| 探针-06：补数取证 | 按白名单读取原始记录，验证内容和作用域。 | 补数提案、无法补齐原因。 | 无法取回历史证据就保持缺失。 |
| 探针-07：控制检查 | 核对阻断、风险覆盖、版本回执、异议关闭和实际发布。 | 检查结论与证据引用。 | 未知不能转成通过；疑似问题交执行方核实。 |
| 探针-08：指标计算 | 使用固定定义、样本范围与分母，输出已验证值与未知数量。 | 指标记录和可计算性状态。 | 所需输入不足则停止该指标，不停止全部探针。 |
| 探针-09：发现与建议 | 按规则组织风险发现、缺口、建议恢复节点。 | 风险发现与节点级建议。 | 语义推断必须标为候选，不冒充确定事实。 |
| 探针-10：交付回流 | 输出报告和提案；在线时验证执行方的接受／拒收记录。 | 可审计交付结果。 | 没有确认就维持待接收，不计算为补齐。 |
| 探针-11：自监控归档 | 记录采集错误、处理延迟、预算、重复事件及报告修订。 | 探针运行记录、恢复点。 | 超预算暂停探针，业务控制仍由执行方维持。 |

探针重启时从最后确认的来源游标和报告修订恢复。重放原始事件可重新计算结果，但不得再次发送已确认生效的相同补数；重算报告是新报告修订，不是新业务动作。

## 6. 采集对象与最小埋点

### 6.1 三类数据源

| 数据源 | 适合证明什么 | 不能单独证明什么 |
|---|---|---|
| 执行控制账本 | 谁在何种基线、规则和控制序号下作出何种决定。 | 外部系统一定按该决定执行；任意导出文件一定真实。 |
| 不可变工件与证据仓库 | 被审正文、来源、依赖与版本之间的对应关系。 | 源材料的业务事实必然正确。 |
| 发布目的端或业务系统记录 | 哪个动作实际生效、外部对象和幂等键。 | 该动作当时一定取得了完整内部评审。 |

必须交叉关联控制账本与外部结果，才可能发现“账本记录了拒绝，但有人走另一个入口发布”。无法获取目的端完整记录时，只能评价已知入口，不能声称系统不存在旁路发布。

运行遥测可补充时延、成本和重试，但不是控制账本的替代。关键裁决事件应完整留痕；对抽样遥测只能给出抽样范围结果或经说明的估计，不能用于证明硬约束从未被绕过。

### 6.2 挂载位置与必要字段

| 执行位置 | 建议事件 | 除共享信封外的必要载荷 |
|---|---|---|
| 任务受理 | 任务已受理 | 请求范围、目标动作、场景、风险等级、预期节点计划。 |
| 基线冻结 | 审查基线已冻结 | 正文、来源清单、规则、风险清单、评审计划和动作摘要。 |
| 责任分配 | 评审任务已分配 | 任务标识、必审风险、主体、输入清单、独立性要求。 |
| 评审完成 | 评审结果已提交 | 完成状态、使用来源、覆盖项、结论、异议引用。 |
| 问题提出 | 异议已登记 | 异议标识、严重性、规则、证据、目标基线、责任人。 |
| 问题复核 | 异议处置已裁决 | 原状态、新状态、复核主体、关闭依据、对应版本。 |
| 缺口发现 | 证据缺口已登记 | 缺口标识、字段路径、期望来源、是否影响放行。 |
| 评审封口 | 评审轮次已封口 | 必需任务集合、最终结果集合、未决事项、评审包摘要。 |
| 批准裁决 | 闸门裁决已完成 | 闸门类型、决策时控制序号、当时阻断快照、覆盖快照、结果及原因。 |
| 回执签发或撤销 | 回执已签发／回执已撤销 | 回执绑定、验证方式、期限、原因、控制修订号。 |
| 发布前校验 | 发布前复核已完成 | 请求操作、回执、当前摘要、授权检查、接受或拒绝原因。 |
| 受控提交 | 发布意图已登记 | 操作标识、幂等键、目标、动作摘要、条件提交结果。 |
| 外部结果核对 | 发布结果已确认 | 外部对象、外部操作标识、真实状态、核对依据。 |
| 版本与依赖变化 | 审查依据已变化 | 旧新摘要、变更类型、受影响回执、触发节点。 |
| 数据回流 | 补数提案已处理 | 请求与提案标识、接受结果、拒收原因、是否新建基线。 |
| 通用节点执行 | 节点尝试已开始／已结束 | 逻辑任务标识、尝试序号、状态、资源使用、时钟来源。 |

不存在的事件不能由探针伪造成当时曾发生。探针可以在现在追加“发现历史记录缺失”的观测事件，但其发生时间和含义必须是现在的检查结果。

### 6.3 字段来源层级

每个观察值都保留“原始来源、获取方式、验证结果、采集时间、适用对象、是否推断”。验证结果至少包括：已验证、来源未验证、存在冲突、已过时、无法取得。

原始审计事件优先用于证明动作；不可变工件用于证明内容；模型解释用于定位可能的问题，而不作为身份、时间、权限或真实发布状态的权威来源。工具返回“成功”也需要解释成功对象：查询成功不代表事实核查通过。

## 7. 数据补全规约

### 7.1 缺口分类

| 类别 | 例子 | 允许的补全办法 | 对执行流程的影响 |
|---|---|---|---|
| 关联缺口 | 缺失运行、工件或评审轮次标识。 | 从权威对象映射回补；无法唯一映射则保留未关联。 | 不能将未关联结果计入当前批准。 |
| 观测缺口 | 节点开始时间、输入用量、采集延迟缺失。 | 读取历史计量或运行记录；不可得则指标为空。 | 非关键观测缺失可降级。 |
| 来源缺口 | 只有摘要，没有原始快照或内容校验。 | 从允许来源取回并验证原始版本。 | 涉及审批依据时新建基线、重审。 |
| 控制缺口 | 缺少异议关闭证明、批准裁决或回执。 | 查找真实历史控制记录；若当时未发生，只能重新走流程。 | 不得补造历史批准。 |
| 冲突缺口 | 工件存储与回执指向不同版本。 | 保留双方值，核对权威来源和变更历史。 | 由执行方暂停、重审或处理事件。 |
| 时效缺口 | 实时动作依赖过时数据。 | 获取当前数据并验证，但不冒充旧时点数据。 | 更新审查基线，按适配器重新验证。 |

### 7.2 补数证据分级

| 等级 | 定义 | 可以写入哪里 |
|---|---|---|
| 权威事实 | 由相应记录拥有者提供，身份、对象和版本可验证。 | 先形成提案；执行方验收后进入相应事实或观测区。 |
| 可复算派生值 | 从已验证事实按明确公式计算，并记录输入与公式版本。 | 观测区；若用于业务判断，须明确纳入审批依据。 |
| 推断候选 | 根据不完整材料推测出来，不能直接核验。 | 独立推断区，只作补证线索。 |
| 未取得 | 无权限、无来源、过期删除、超时或无法唯一关联。 | 缺口清单，不写假值。 |

可以从真实开始和结束事件算出持续时间，不能根据“通常需要几秒”补出真实耗时。可以重新查询当前权限，不能据此证明一小时前的权限。可以取回当时的不可变快照，不能用今天相似内容替代当时的证据。

### 7.3 补数停止条件

触发任一条件即停止该采集任务并说明原因：授权不覆盖、来源越界、超出预算、达到最大尝试次数、证据无法验证、请求过期、对象已变更。停止不改变业务问题的原有状态。

如果补数必须创建业务数据、触发实际动作或获得更高权限，应向执行方提出“需要额外授权或业务操作”，而不是把它藏在只读探针里执行。

### 7.4 补全数据与补全证据的不同

把一个空字段填上文本，不代表缺口解决。只有值的来源、版本、时效、语义和接收结果都满足要求，才能将缺口标为已解决。

旁路观测补充可以不改变审批；会影响判断的证据补充必须进入新的审查基线或评审证明包。探针要输出这个影响提示，最终决定仍由执行方按共享契约进行。

## 8. 指标计算的统一口径

### 8.1 粒度与去重

| 对象粒度 | 唯一标识建议 | 统计注意事项 |
|---|---|---|
| 运行 | 租户＋运行标识。 | 多次修订不是多个独立业务任务。 |
| 工件版本 | 租户＋工件标识＋版本。 | 新正文不能与旧正文合并评价。 |
| 审查轮次 | 运行＋审查基线摘要＋轮次。 | 规则或证据变化后分开；同轮重试不另算轮次。 |
| 风险检查 | 基线＋轮次＋风险项。 | 多人重复审同一项，覆盖只计一次。 |
| 评审任务 | 基线＋轮次＋评审任务标识。 | 重试与重新分配须有区别。 |
| 异议 | 异议标识；共同问题标识另存。 | 原始提交不删除；合并计数说明口径。 |
| 闸门尝试 | 闸门决策标识。 | 按批准闸和发布闸分别统计，不混为一个比率。 |
| 实际发布 | 外部操作标识或可证明等效的幂等操作标识。 | 重复确认不能变成多次发布。 |
| 补数缺口 | 原始缺口标识。 | 同一缺口的多次请求不扩充分母。 |
| 补数提案 | 请求标识＋提案标识。 | 重复投递只计一次。 |

比较不同时间段或版本时，至少按场景、风险等级和规则版本分层；模型、数据源和发布适配器有明显差别时再分层。避免把高风险任务占比变化误判成评审能力退化。

### 8.2 每个指标必须输出的字段

```yaml
指标记录:
  指标标识: "指标-07"
  指标名称: "必审风险有效覆盖率"
  定义版本: "0.1.0"
  统计粒度: "审查基线与评审轮次"
  统计范围引用: "观察快照-001"
  分子: 3
  分母: 4
  数值: 0.75
  单位: "比例"
  可计算性: "可计算"
  未知样本数: 0
  排除样本数: 0
  排除原因: []
  来源引用: ["风险清单-001", "评审结果包-001"]
  数据截至点: "控制账本序号-40"
  报告修订号: 1
```

该结构为演示数据。一个必审项尚未完成时，分母已由计划确定，因此可以准确计算覆盖为3/4；这不是在猜测缺失值。相反，如果必审风险清单本身丢失，就不能推测分母为4。

### 8.3 四种可计算性状态

| 状态 | 含义 |
|---|---|
| 可计算 | 已知总体或明确统计范围内，所需字段与分母足以按定义计算。 |
| 部分可计算 | 仅能计算可验证子集；必须列子集分母、未知数量与范围限制，不冒充全量比率。 |
| 不可计算 | 分母、关键关联、时间或事实不足以计算；数值为 `null`，不是零。 |
| 不适用 | 场景不含该对象，或定义明确要求的条件没有发生；说明原因。 |

分母为零通常输出不适用，不输出100%。例外：在对抗评审中“必审风险清单为空”是配置错误，应输出不可计算并告警，而不是不适用；未接评审适配器的普通流程，相关指标才是不适用。

检查结论另外使用“通过、未通过、未知、不适用”，不能和指标可计算性混为一谈。一个结果可以是“指标可计算但检查未通过”，也可以是“部分可计算且已确认存在一次违规”。

### 8.4 顺序、迟到与时间

优先用运行内权威账本序号和因果关联恢复控制顺序，不凭多机器时间戳的表面先后来决定谁先批准。耗时优先使用同一时钟域的单调时钟；跨系统计算须有时钟同步依据，否则报告时间不确定性或不可计算。

观察窗口需声明事件水位和迟到策略。迟到记录保留原发生时间与实际采集时间，触发报告修订；不能改写已签发的业务回执或抹除原报告。

硬控制指标按当时的基线和控制快照计算。今天已经关闭的异议，不能让昨天带着未关闭异议的发布变成合规；反过来，今天新发生的风险也不能无依据地追记成昨天已知的阻断。

## 9. 指标字典：数据与来源

以下全部为本设计提出的指标定义。比例乘以100%可显示为百分数；实现中建议保留原始分子、分母和比例值。

| 标识／指标 | 定义与公式 | 必需数据和缺失处理 |
|---|---|---|
| 指标-01 必需控制事件完整率 | 已取得且可验证的必需事件槽位数 ÷ 按实际分支应产生的必需事件槽位数。 | 使用受理计划、实际分支记录和事件清单推导槽位；跳过节点要有理由。无法知道应有集合则不可计算。 |
| 指标-02 来源链完整率 | 具有原始来源、版本／快照、定位、内容校验和适用对象的必要证据项数 ÷ 本基线要求的证据项数。 | 分母来自审批证据要求，不是实际采到几条就算几条；只能证明可追溯，不能证明事实一定正确。 |
| 指标-03 版本绑定一致率 | 与其声明基线、工件和轮次一致的必需绑定对象数 ÷ 预期必需绑定对象数。 | 对象包括评审结果、处置证明、回执和发布引用；缺对象计未满足，分母未知则不可计算。 |
| 指标-04 关键字段缺失率 | 缺失或无法验证的关键字段实例数 ÷ 适用的关键字段实例总数。 | 实例按对象与字段计数；关键字段清单需版本化。未知来源归入未满足，并单列原因。 |
| 指标-05 可比较事实冲突率 | 存在未解决矛盾的事实字段数 ÷ 同一对象、口径和时点下具有至少两条可比较证据的事实字段数。 | 不把不同时点、不同口径当矛盾；没有双源可比字段则不适用，不代表不存在错误。 |
| 指标-06 证据时效满足率 | 满足对应时效或历史快照要求的证据项数 ÷ 所有适用时效要求的必要证据项数。 | 需有规则、数据时点和使用时点；无法证明满足的项不计分子，另列未知。 |

上述指标可同时展示两列：“条件满足数量”与“未知数量”。缺失导致的未满足，不应全部描述为已证实的业务错误。

## 10. 指标字典：对抗评审与发布控制

| 标识／指标 | 定义与公式 | 必需数据和解释边界 |
|---|---|---|
| 指标-07 必审风险有效覆盖率 | 当前基线与轮次下，具有有效完成结果的不同必审风险项数 ÷ 配置的必审风险项总数。 | 完成结果要有规则、证据与有效主体；“无异议”不是完成证明。多名评审者重复覆盖不加分。 |
| 指标-08 结构独立性证据满足率 | 已用运行时证据证明满足的独立性检查项数 ÷ 当前策略要求的独立性检查项数。 | 检查身份、上下文、来源链和权限等结构；不把该比率解释为认知独立的概率。 |
| 指标-09 阻断执行率 | 已证实当时存在未关闭阻断，且实际被闸门拒绝的尝试数 ÷ 已证实当时存在未关闭阻断的闸门尝试数。 | 需要同一时点的阻断快照和决定；批准闸、发布闸分开统计。未知状态尝试单列，不能隐形排除后宣称全量100%。 |
| 指标-10 已确认违规发布数 | 已实际生效且经核验违反至少一项放行硬条件的不同发布操作数。 | 按外部实际发布去重；无回执、错版、未关闭阻断等可多标签，但一次操作只计一次。没有目的端完整记录时不能证明总数为零。 |
| 指标-11 无效回执拦截率 | 证实缺少必需回执或使用无效回执，且在产生副作用前被拒绝的发布请求数 ÷ 证实缺少必需回执或使用无效回执的发布请求数。 | 无效包括伪造、错版、过期、撤销、错范围；缺少必需回执也纳入此指标；需要验证材料和实际执行记录。拦截成功不等于整个系统没有旁路。 |
| 指标-12 实际发布回执匹配率 | 能证明在受控提交时持有当前有效、范围匹配回执的实际发布操作数 ÷ 范围内实际发布操作总数。 | 分母由目的端或等效完整结果账本确定。缺少对应审批记录只证明无法验证，不直接推定历史上从未审批。 |
| 指标-13 新基线重审完成率 | 变更后重新申请批准的基线中，申请时全部必审项已针对新基线完成的数量 ÷ 变更后重新申请批准的不同基线数量。 | 同一基线多次申请以首次申请为该指标取点。用于诊断提交准备度，不要求每个被拒请求都达100%；实际获批基线必须满足完整重审。 |
| 指标-14 异议关闭证据完整率 | 具有合法复核主体、规则、证据、目标版本和理由的关闭记录数 ÷ 已声明关闭的异议处置记录数。 | “后继版本已修复”和“原异议不成立”分开统计；修订者自报关闭不计分子。 |
| 指标-15 首轮批准率 | 首版首轮完整裁决即获批的运行数 ÷ 已有首版首轮完整裁决的运行数。 | 完整裁决包括批准、要求修改、升级或终止；尚待评审或待补证的运行单列。此指标不是安全目标。 |
| 指标-16 发布责任链可追溯率 | 能从实际发布追溯到发布意图、回执、裁决、评审结果与原始证据的操作数 ÷ 范围内实际发布操作总数。 | 关联链条齐全仍不证明每个判断正确；需要每一环的真实对象而非拼接文本。 |

### 10.1 硬约束与统计指标的不同

对一个准备获批或发布的具体基线，执行方应直接检查：没有未关闭硬阻断、必审项完成、当前回执有效、动作已授权。不能改成“过去一个月平均指标达标就放行当前版本”。

在证据与采集范围完整的前提下，本设计把“阻断执行率100%、无效回执拦截率100%、已确认违规发布数为0”作为应满足的控制不变量，而不是来源材料已经验证过的运行成绩。低风险和高风险任务都不能用平均值豁免某个真实违规。

### 10.2 不得误读的指标

异议数量多，可能是候选差，也可能是评审更认真；数量少，可能是质量高，也可能是共同盲区。首轮批准率高，也可能是闸门太松。评审意见一致，既可能是结论可靠，也可能是同源错误。

因此不设“阻断越少越好”“一致率越高越好”“评审人数越多越独立”之类优化目标。多来源只统计可追溯的不同来源族，不把多个页面转述同一个上游事实算成多份独立证据。

## 11. 指标字典：效率、补数与探针自身

### 11.1 执行效率

| 标识／指标 | 定义与公式 | 必需数据和解释边界 |
|---|---|---|
| 指标-17 节点首尝试成功率 | 首次尝试即成功的逻辑节点任务数 ÷ 终态为成功或失败且实际启动过的逻辑节点任务数。 | 逻辑任务按运行、基线、轮次、节点及任务标识区分；未启动、条件跳过、外部取消不进分母，须单列数量，不悄悄并入成功。 |
| 指标-18 重试放大系数 | 终态为成功或失败的逻辑节点任务的实际尝试总数 ÷ 这些逻辑节点任务的数量。 | 无重试时为1；修订后的新评审属于新逻辑任务，不当作传输重试。未结束任务另列暂定统计。 |
| 指标-19 单轮评审时长 | 本轮完整裁决时点－本轮首次分发评审时点；输出中位数和第95百分位。 | 包含该轮等待取证时间，另拆等待与执行；未完成轮次以当前年龄另列，不塞入已完成分布。 |
| 指标-20 已计量预算消耗率 | 同一计量维度的已确认消耗量 ÷ 当前任务批准的该维度预算。 | 调用数、输入输出用量、处理时长等分别统计，不混单位；缺计量数据时只报已知下限或不可计算。预算为零却有消耗时作为配置／预算异常。 |

中位数取排序后的中间值，偶数样本取中间两值的平均数；第95百分位默认取排序后第“向上取整的0.95乘样本数”项。分布必须显示样本数；不同算法实现可更换，但要更新定义版本。样本少时仍可给样本分位数，不把它宣传成稳定服务水平。比如不足20个样本加上“小样本”标记，是本设计的可调展示规则，不是原文规定。

### 11.2 补数与边界

| 标识／指标 | 定义与公式 | 必需数据和解释边界 |
|---|---|---|
| 指标-21 已终结缺口补齐率 | 已由执行方确认使用有效事实解决的缺口数 ÷ 已进入补数且已终结或截止时间已到的不同缺口数。 | 成功、拒绝、无法取得、超时均保留；截止前尚在处理的缺口单列。独立离线、没有接收方确认时，不把提案计作已补齐。 |
| 指标-22 已接受补数耗时 | 执行方接受并确认缺口解决时点－该缺口首次有效请求时点。 | 仅对已解决缺口计算分布，同时报告失败数和未决年龄，避免只看幸存成功样本。 |
| 指标-23 补数提案拒收率 | 被执行方拒绝的不同提案数 ÷ 已有终态接受结果的不同提案数。 | 待接收不计分母但必须显示数量；按错版、越权、过期、冲突、来源不足分解。高拒收率可能证明边界在起作用，不能一味压低。 |
| 指标-24 探针越权写入生效数 | 经权威记录确认，由探针身份直接修改受保护业务字段且已生效的次数。 | 被成功拦截的尝试另外统计，不计生效数。写权限日志不全时不能声称零越权；合法的补数提案由执行方应用不属于探针直接写入。 |

“已终结缺口补齐率”不能替代“关键证据是否足够”。总共补齐九个耗时字段，但一个发布权限证明仍缺失，不得放行。

### 11.3 探针自身运行

| 标识／指标 | 定义与公式 | 必需数据和解释边界 |
|---|---|---|
| 指标-25 重复投递率 | 接收次数中被确认是已见相同事件的次数 ÷ 原始接收总次数。 | 幂等处理前统计；同一标识不同内容是冲突，不是正常重复。至少一次投递机制下存在重复并不自动是业务错误。 |
| 指标-26 探针处理延迟 | 观测结果持久化时点－该输入在探针入口被接收时点。 | 使用探针自身同一时钟域；不冒充业务事件从发生到可见的全链路延迟。后者要额外证明跨源时钟一致。 |
| 指标-27 探针对执行时长的增量影响 | 在可比成对测试中，对每对计算“接入探针耗时－不接探针耗时”，并报告差值及相对差值分布。 | 需固定候选、规则、任务结构和环境并重复测试；没有基准不能计算，单条生产日志不能证明因果开销。 |

探针可以单独报告自身调用次数、资源使用、采集失败与当前积压，不必把所有项目都变成比例。执行流程与探针的资源账分开保存；不要把观察自身产生的事件无限计入业务工作量。

## 12. 检查策略、告警与处置建议

### 12.1 控制不变量

本设计建议在证据足够时对以下情况立即产生高优先级风险发现：已实际生效的发布违反硬阻断；工件与回执错版；未经授权的主体关闭异议；探针直接写入受保护业务字段；受保护动作绕过发布入口。

“没有采到回执”首先属于证据缺口；只有在足够完整的权威记录、规定必需回执及实际动作证据下，才能进一步确认违规。报告要区别“已确认异常”和“疑似异常”。

执行方可预先配置规则：收到特定、可验证的发现后，由自己的控制模块暂停相应动作。这种暂停来自执行方的授权策略，不是探针获得了自由裁决权。模型生成的风险解释不能自行扩展暂停范围。

### 12.2 可调整的运行告警

| 现象 | 建议报告方式 | 不应自动做的事 |
|---|---|---|
| 评审耗时上升 | 按任务风险和规则版本分层，拆分执行、等待证据与人工等待。 | 为提速删除必审风险或降低独立性要求。 |
| 重试放大 | 指出具体节点、错误类别与重复来源。 | 无限重试或无限增派评审者。 |
| 补数拒收增多 | 分解错版、并发、时效和权限问题。 | 扩大探针权限以减少拒绝。 |
| 来源链变短或同源集中 | 给出共同上游来源与受影响结论。 | 用增加模型数量伪装独立取证。 |
| 首轮批准率变化 | 同时观察违规、缺口、风险组合与抽检结果。 | 把提高通过率当作唯一目标。 |
| 探针积压或预算耗尽 | 报告覆盖下降与未完成范围，暂停非关键采集。 | 停止执行方自身的必要控制检查。 |

这些告警阈值应由场景基线与资源预算配置，本文不给出伪装成行业标准的统一耗时、成本或重试阈值。

### 12.3 评审质量校准需另有真值集

日志可以证明“某项评审执行了”“某次阻断生效了”，不能直接证明评审者没有漏掉真正的语义问题。评估误报或漏检时，需使用独立标注的测试集或授权人工复核结果，并保留标注争议与范围。

```text
离线缺陷检出率 = 被正确发现的真实缺陷数 ÷ 标注确认的真实缺陷数
离线误报占比 = 经复核不成立的已报告问题数 ÷ 经复核的已报告问题总数
```

没有独立标注就输出不可计算。不能用模型自信、其他评审者同意或最终“批准”状态充当真值；也不能把后来环境改变造成的新问题算作当时必然可见的漏检。

## 13. 输出报告与机器结果

### 13.1 报告固定结构

报告应先说明“可以确认什么、不能确认什么”，然后列关键异常与缺口、当前版本的风险覆盖和控制检查、效率与探针开销、补数状态、来源与计算口径。

报告需要明确两个结论层级：数据质量结论和控制观察结论。不输出“本工件可以发布”这一审批结论；即使所有检查都显示满足，也应描述为“在当前数据范围内，所列控制检查均有满足证据，最终放行由执行方完成”。

### 13.3 指标记录与明细分层

低基数维度如场景、风险等级、规则版本可用于汇总；运行标识、工件摘要、异议文本等高基数内容放入明细与追踪记录，避免直接作为所有指标的标签。

敏感正文、个人信息、密钥及完整令牌不得进入公共指标或告警。需要诊断时使用受控引用与脱敏片段，并保存访问授权。

## 14. 联动时序与补数接受状态

### 14.1 执行流程单独运行

执行方自行核对证据、评审与回执，记录最小控制事件；没有探针也能完成完整裁决。采集失败造成非关键指标缺失时，执行方按已声明策略降级；关键放行证据仍不得缺失。

### 14.2 探针单独运行

操作者提交范围明确的日志与快照，探针产生报告和提案。缺少规则就不能判断某个动作是否违反该规则；缺少外部结果就不能判断是否真实发布。离线补数提案可作为待处理工件输出，但没有接收方签认，不写“已回填”。

### 14.3 在线交互运行

```text
执行方 → 事件输出 → 探针：建立运行、版本和轮次关联
执行方 → 补数请求 → 探针：定位缺口及允许来源
探针 → 只读取证与校验 → 补数提案
执行方 → 验证提案与当前控制状态
        ├→ 仅观测补充：追加旁路数据，恢复原节点
        ├→ 改变审查依据：创建新基线，重开评审
        ├→ 待人工核实：维持受影响条件暂停
        └→ 拒绝：返回原因，保持原数据
执行方 → 接受结果事件 → 探针：更新补数状态及指标
```

“恢复原节点”只适用于没有改变判断依据的补充。涉及正文、证据、规则、风险清单、评审计划或动作范围时，不得从发布节点直接续跑。

### 14.4 反馈控制和防循环

每个缺口保留一个原始标识，补数请求、提案、重试、接受结果都关联它。对同一缺口重复发现时合并任务，不不断创建新的补数链。

探针事件标注来源角色为探针；默认不触发同一个探针再次为自身遥测缺口启动无限补数。设置有限的请求深度、重试次数、总预算和截止点。预算数字由部署策略给定，不由模型自行提高。

## 15. 通用场景适配器

| 场景 | 保留的通用能力 | 增加的场景对象 | 应标为不适用的部分 |
|---|---|---|---|
| 对抗评审 | 事件、来源、缺口、时效、补数、成本。 | 风险项、异议、评审轮次、回执与发布链。 | 按实际业务确定，不默认关闭任何核心评审检查。 |
| 普通链式任务 | 同上。 | 前后节点输入输出、依赖与完成状态。 | 没有评审时，异议和回执指标不适用。 |
| 路由任务 | 同上。 | 路由候选、选中路径、拒绝或回退原因。 | 没有独立真值时，不计算“首次路由正确率”。 |
| 扇出聚合 | 同上。 | 子任务标识、父目标、分支完成、去重与聚合验收。 | 子任务完成不自动等于父目标满足；没有评审回执则该类指标不适用。 |
| 数据分析流程 | 同上。 | 数据版本、口径、查询、样本窗口、派生公式。 | 不把来源齐全当作结论真实或因果成立。 |
| 计划或代码执行 | 同上。 | 计划版本、执行环境、测试结果、变更和副作用。 | 没有独立评审模块时不伪造评审人数和通过率。 |

适配器至少声明：对象字段映射、预期事件、状态机、关键字段、来源优先级、时效规则、指标启用集合、允许补数来源、受保护字段、接受接口及恢复节点。

适配器不改变共享契约的权限边界；若一个场景确实需要有写权限的修复工具，应将其作为独立业务节点注册和授权，而不是扩展只读探针的隐含职责。

## 16. 示例：同样的评审意见，控制效果不同

### 16.1 两组人工构造的演示事件

本例只验证指标定义与控制差异，不是原文仓库的实测数据。

评论模式组：第一版有两个必审风险，两个评审结果均完成，并提出两项有证据的阻断。发布检查只检查正文存在，仍允许发布；完整目的端记录确认实际生效，没有必需的有效回执。

闸门模式组：第一版同样有两项阻断，发布请求被拒。第二版重新评审，两项必审风险完成且阻断已解决，取得有效回执并实际发布。之后第三版试图借用第二版回执，被发布入口拒绝；此前第二版的历史发布记录不被抹去。

| 指标 | 评论模式组 | 闸门模式组 | 解释 |
|---|---:|---:|---|
| 第一版必审风险有效覆盖率 | 2/2＝100% | 2/2＝100% | 检查完成不等于没有阻断。 |
| 发布闸阻断执行率 | 0/1＝0% | 1/1＝100% | 只统计当时明确存在阻断的发布请求。 |
| 已确认违规发布数 | 1 | 0 | 这里假定两组目的端记录均完整可验证。 |
| 实际发布回执匹配率 | 0/1＝0% | 1/1＝100% | 闸门组只实际发布了已通过的第二版。 |
| 第三版错版回执拦截 | 未设置该测试 | 1次请求，1次拒绝 | 说明不能用第二版批准给第三版放行。 |

如果移除目的端记录，表中的违规发布数和实际发布回执匹配率就不能继续保留原来的确定值；应改为不可计算或仅限可验证子集。数据删减必须改变结论的可证明范围。

### 16.2 补数不等于填满所有空格

另一个演示窗口包含三个已经终结的缺口：节点耗时可从真实历史事件复算并被接受；原始来源快照被取回、验证，并由执行方接受后触发新基线重审；历史模型用量从未保存，无法取得，保留缺失。

因此“已终结缺口补齐率”为2/3，约66.67%。第三项不能按常见用量填数以做出100%。假设另有一个截止前尚未结束的补数任务，应单列为待处理，不悄悄当失败，也不提前算成功。

如果上述两个提案只完成发送、没有执行方接受确认，已确认补齐数仍为零；离线报告应展示“两个待接收提案”，而不是“两个已补齐缺口”。

## 17. 验收与回放测试

以下为实施验收规约，不宣称本次已运行真实系统。

| 用例 | 输入或扰动 | 预期输出 |
|---|---|---|
| 探针验收-01 | 只给候选正文，无控制账本。 | 能独立运行并输出缺口；控制效果指标不可计算。 |
| 探针验收-02 | 两名评审者都覆盖同一风险，另一项无人检查。 | 覆盖按风险去重，不按评审人数得出100%。 |
| 探针验收-03 | 零次阻断场景。 | 阻断执行率不适用，不填100%。 |
| 探针验收-04 | 对抗评审必审清单为空。 | 配置错误；不能用零分母证明全部通过。 |
| 探针验收-05 | 关键源没有接入。 | 标明未验证范围，不输出全系统“零违规”。 |
| 探针验收-06 | 同一事件重复投递十次。 | 业务计数仍为一次；重复投递计入探针自身统计。 |
| 探针验收-07 | 同一事件标识对应不同载荷。 | 记录冲突，隔离调查，不按普通重复静默吞掉。 |
| 探针验收-08 | 事件乱序、跨机器时钟偏移。 | 按权威序号和因果恢复；无法可靠计算的耗时置空。 |
| 探针验收-09 | 今日关闭了昨日发布时未关闭的异议。 | 昨日控制检查仍按昨日快照，不被今日状态洗白。 |
| 探针验收-10 | 只有现在的权限记录，要求补历史权限。 | 保留历史未知；不把现在状态当历史证明。 |
| 探针验收-11 | 新版本收到旧版补数。 | 不回填当前版；拒收或归历史。 |
| 探针验收-12 | 补数提案声称“不改变基线”，实际改了来源。 | 执行方重新判定影响并重审，不能信任自报布尔值。 |
| 探针验收-13 | 探针试图直接修改批准或异议状态。 | 权限阻断；记录企图，不将拒绝误算成生效写入。 |
| 探针验收-14 | 只生成补数提案，没有接受确认。 | 维持待接收，不算补齐。 |
| 探针验收-15 | 无法取回历史使用量。 | 数值为空，附缺口，不用估算覆盖真实字段。 |
| 探针验收-16 | 没有不接探针的对照运行。 | 增量时长影响不可计算；可另报自身处理耗时。 |
| 探针验收-17 | 没有独立缺陷标注。 | 不报告真实漏检率、误报率或语义准确率。 |
| 探针验收-18 | 只有部分抽样遥测。 | 不能据此证明全部发布符合硬约束。 |
| 探针验收-19 | 探针崩溃后重放已确认提案。 | 幂等返回，不重复应用，不重复计数。 |
| 探针验收-20 | 日志内容含要求读取凭据或发布的指令。 | 按数据处理，不执行，不扩大能力。 |
| 探针验收-21 | 补数导致探针自身反复产生新缺口。 | 合并原缺口，受预算与深度限制，不无限反馈。 |
| 探针验收-22 | 高风险任务占比上升，首轮批准率下降。 | 先分层展示，不直接归因为模型退化。 |

最低回放集应同时包含通过、拒绝、证据不足、错版、来源冲突、重复投递、迟到、并发变更、外部结果不确定等样本。仅测试正常路径，无法证明独立异议真的约束了放行。

## 18. 存储、安全与部署建议

探针原始观测包、规范化事件、指标定义、报告修订、缺口和提案应可独立持久化；业务工件、回执和控制状态由执行方存储。可以部署在同一服务内，但使用不同能力边界和写入接口。

敏感数据只读、最小化采集，按租户和用途隔离。日志正文、错误栈与来源片段也可能包含凭据或个人信息；脱敏后再进入模型分析和报告。不要采集隐藏推理过程，结构化理由和证据引用足以支撑本设计。

控制账本与关键授权证据不抽样；普通运行遥测是否抽样由场景决定，并在报告中披露。保留期由部署治理确定；证据到期删除后，后续历史检查可能不可计算，必须保留这一限制，而不是补造历史数据。

最小部署可以是读取本地导出的单次任务，也可以是订阅服务端事件的旁路工作流。跨进程、消息队列、MCP或普通接口只是运输与接入选择，不改变读取、校验、补数提案和执行方验收的职责分离。
