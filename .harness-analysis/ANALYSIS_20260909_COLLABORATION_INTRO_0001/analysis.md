## 工程诊断

| 工程切片 | 改动前证据与缺口 | 本次结果 | 实现边界 |
| --- | --- | --- | --- |
| 协作模式选择 | `references/registry.json` 已注册交接链、扇出汇聚、对抗评审、层级委派；协作导论缺少共同协议入口 | 总纲定义模式组合、13 个执行节点及收益与准入条件分离 | 不强制并行、模型调用或评审；路由与编排仍为扩展候选 |
| 任务到结果到验收 | 四个单元已有设计级边界说明，但没有共享协作记录 Schema 与跨记录执行校验 | 本地 `2.0.0` Schema；绑定任务、工件、回执的标识、版本、摘要、范围和参与者 | 参考内核只判定公开记录，不派发 Agent 或执行业务 |
| 异议与交接 | 缺少可直接测试的协作放行判断 | 当前版本评审、阻塞异议裁决、局部与全局验收、接收者承责分别检查 | 真实身份、来源真实性与完整清单由宿主核验 |
| 独立观测 | 现有推理、反思和工具探针不足以表达协作专属补证闭环 | 独立快照接口、11 个探针节点、34 项口径、补证与采纳回执校验 | 六项指标有计算实现，28 项仍需适配器；未知不补零 |
| 契约治理 | 缺少两份协作文件的一致性校验 | 注册表登记模块；节点和指标从模块目录生成；共享字段从同一 Schema 生成；总校验器接入 | 新增契约不升级既有推理、反思和工具协议 |

已有并行调度、计划执行、工具调度与反思运行时继续承担各自职责。协作总纲引用这些能力，但没有用推理分支评选替代工作分工，也没有把生成评审模块的意见直接当作协作交付许可。
