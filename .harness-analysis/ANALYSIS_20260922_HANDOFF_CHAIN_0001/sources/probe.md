# 交接链：工作流可观测性探针

> 目标：重建每次交接的版本、责任、证据与结果，定位缺失数据，返回可验证的观测补全，而不接管业务执行。
>
> 本文不是一份静态指标清单，而是一套包含输入、采集、重建、检查、计算、补全、反馈和输出的可执行规约。只提供契约、事件、快照或工件，也可以独立运行；不必先阅读配套执行文档。

## 一、来源、定位与边界

### 1.1 与原框架的关系

本文依据用户提供的黄佳第 35 讲《交接链：让状态、责任与证据一起抵达下一棒》，以及 `hanerss_skill_framework_v0_1.md` 的三大基座、注册表、坐标与模板结构。

原框架规定注册表是源数据、矩阵是视图、工程模式是可挂载资产、能力单元是执行化产物。本文将探针作为“治理 × 编排”的观察与补全能力，主要观察“协作 × 链式”的交接模式，不另造一套基座体系。

`PATTERN_XXXX` 是待注册占位符，和配套执行文档指向同一交接模式，不能按课程编号直接当作正式模式编号。两份文档的协议版本为 `1.0`，它与框架版本、文档版本、阶段契约版本及业务状态版本分别管理。

指标公式、事件契约、观测补丁和测试均为本次工程化设计，不是原框架已有实现。没有提供运行记录时，只能做静态审查，不能生成假装来自真实系统的观测结果。

### 1.2 独立目标

探针必须能回答五个问题：下一棒拿到哪一版；这版由谁根据什么产生；接收是否正式成立；失败停在哪个版本；恢复或补全还缺什么证据。

业务是否应当批准、付款、签署或发布，由执行流程及有权责任人决定。探针可以发现错误或给出暂停建议，但不能替代这些决策，也不能代替运行时创建接收回执。

### 1.3 权限边界

| 动作 | 是否允许 | 限制 |
|---|---|---|
| 读取获授权事件、快照、工件和账本 | 允许 | 按任务、安全域、资源与有效期约束 |
| 重新计算摘要、耗时、指标和依赖关系 | 允许 | 保留输入证据与规则版本 |
| 只读查询外部操作真实状态 | 条件允许 | 必须有明确授权、查询适配器与调用预算 |
| 返回缺口、来源冲突和观测补丁 | 允许 | 绑定具体任务、版本和工件 |
| 直接写入已核查事实或业务完成状态 | 禁止 | 只能由业务阶段验收后正式提交 |
| 推进版本、切换责任人或提升权限 | 禁止 | 由执行运行时与治理系统处理 |
| 为确认状态而重新付款、发布、部署 | 禁止 | 这属于新副作用，不是观察 |
| 用推断或模型自述补成正式回执 | 禁止 | 必须保留未知状态 |

发现严重异常不意味着探针可以自行修复业务。实时旁路只能发出告警；同步交互时，由执行流程的既定闸门决定暂停。离线审计更不能声称阻断已经发生的事件。

## 二、三种运行方式

| 模式 | 输入 | 主要产出 | 对执行链的影响 |
|---|---|---|---|
| 离线独立审查 | 导出的契约、日志、快照、工件、回执 | 版本链重建、指标、缺口、责任与恢复建议 | 不影响原执行，不重放真实副作用 |
| 实时旁路观察 | 只读事件流及授权引用 | 滚动报告、等待与未知状态告警 | 不拥有业务阻断或放行权 |
| 有界交互补全 | 指定节点的补全请求与授权数据 | 观测补丁、来源证明、无法补全原因 | 执行流程复验后选择采纳或拒绝 |

探针可以同时提供旁路报告和请求式补全，但两条路径的权限与预算应分开。不得为了补齐报告无限查询，或把同步业务链挂在一个没有截止时间的观测任务上。

### 2.1 按数据充分程度降级

| 可用材料 | 能够给出的结论 | 不能给出的结论 |
|---|---|---|
| 只有流程和契约 | 静态风险、缺失字段、埋点建议 | 实际通过率、耗时、真实事故数量 |
| 只有自然语言日志或课程输出 | 文本显示的阶段与版本变化 | 持久提交、真实接收、权限有效、内容正确 |
| 有可信事件、清单和阶段回执 | 可核验的版本、责任与提交关系 | 无内容时的全稿语义正确性 |
| 加上实际工件、证据与外部回执 | 更完整的绑定、内容、来源与效果检查 | 超出材料、权限、时间范围的总体保证 |

材料越少，报告越应突出未知项。没有足够数据时，交付一份精确的缺口清单，比虚构满分指标更有价值。

## 三、独立运行所需的最小业务语义

### 3.1 状态、尝试与副作用分开

正式接力棒是不可变版本；阶段只能提交候选增量；接收方验收通过且运行时持久化提交后，才创建下一版并转移控制权。拒绝不会因该尝试推进版本；重发同一已接收候选应返回原回执。

`v2→v2` 表示该尝试没有成功提交，不表示系统必须把当前头指针写回 v2。若其他合法提交已使头版本前进，应分别记录尝试输入版本、该尝试结果和当前头版本。

正式版本没有变化，也不能证明没有外部副作用。发布、付款或部署可能已经完成，只是回执未抵达；探针应把这一情况重建为“结果未知，待查证”，而不是“未执行”。

### 3.2 关联身份

| 字段 | 语义 |
|---|---|
| `tenant_id`、`workflow_id`、`task_id`、`chain_id` | 安全域与业务作用域，必须共同参与关联 |
| `stage_instance_id` | 同一逻辑阶段实例，重试时不变；循环的新一轮另建实例 |
| `attempt_id` | 一次实际执行尝试 |
| `handoff_id` | 一份不可变候选交接包；重发不换，修改后新建 |
| `operation_id` | 一次外部业务意图；不能因网络重试而变化 |
| `event_id` | 事件去重身份，不等于上述任一业务身份 |
| `control_epoch` | 执行资格代次，拒绝接管前的迟到执行 |
| `input_version`、`output_version` | 该尝试的正式输入版本与提交结果版本 |

不能只用阶段名称关联，因为同名阶段可能重复执行。也不能只用时间相近关联，因为并发任务可能共享执行者。

## 四、输入与最小事件协议

### 4.1 输入清单

```yaml
运行模式: 离线独立审查
审查范围:
  tenant_id: 示例租户
  workflow_id: 示例工作流
  task_id: 示例任务
  chain_id: 示例交接链
  起止时间: 由调用者提供
  截止观察时间: 由调用者提供
输入:
  工作流与阶段契约: []
  正式状态清单: []
  阶段回执: []
  事件记录: []
  候选与正式工件: []
  事实和证据引用: []
  外部操作账本及回执: []
  权限与验收策略版本: []
  待处理补全请求: []
约束:
  授权来源: []
  禁止副作用: true
  查询预算: 由调用者提供
  最大补全轮数: 2
  截止时间: 由调用者提供
输出要求:
  - 指标必须包含口径、分母、未知项和证据
  - 不可验证的项目标记未知
  - 改进建议与运行事实分开
```

契约和清单不仅用于检查，还用于确定“本来应当存在什么”。不知道必需工件、关键主张和应有回执的全集，就不能把已采集记录作为完整性分母。

### 4.2 与执行流程一致的事件字段

```yaml
protocol_version: "1.0"
event_id: 唯一事件身份
event_type: 交接提交
source_system: 已登记的事件生产系统
source_sequence: 来源系统在约定流内的持久序号
occurred_at: "<事件发生时间，含时区>"
recorded_at: "<来源持久化时间，含时区>"
tenant_id: 安全域
workflow_id: 工作流身份
task_id: 任务身份
chain_id: 交接链身份
stage_instance_id: 逻辑阶段实例
attempt_id: 执行尝试身份
handoff_id: 候选交接包身份
operation_id: null
input_version: 2
output_version: null
input_manifest_digest: "<输入清单摘要>"
artifact_refs: []
receipt_ref: null
actor_identity: 已认证执行者
receiver_identity: 目标接收者
control_epoch: 7
contract_version: "1.0"
policy_version: "<本次策略版本>"
reason_code: null
evidence_refs: []
```

**公共传输类型约束：** 协议版本和各类身份使用非空字符串；状态版本、控制权代次和来源序号使用非负整数，尚未产生或确实不可用的可选值使用空值。`scope`、`target` 使用对象，引用与观测集合使用数组，时间使用带时区的标准时间字符串。摘要需注明算法并绑定固定内容；本文模板中的占位符不是合法生产值。未知协议大版本应拒绝，扩展字段只进入已声明扩展区。


探针可追加 `ingested_at`、采集批次、归一化规则版本与可信度标签，不得覆盖来源原始时间或事件内容。没有来源序号时显式记录为空，不能由到达顺序伪造。

### 4.3 必须识别的事件类型

| 类别 | 类型 |
|---|---|
| 阶段执行 | 阶段开始、候选工件完成、交接提交 |
| 验收提交 | 验收通过、验收拒绝、验收未知、正式提交、责任转移 |
| 外部操作 | 操作意图准备、操作发送、结果确认成功、结果确认失败、结果未知、查证、补偿 |
| 数据补全 | 补全请求、补全返回、补丁采纳、部分采纳、拒绝、过期 |
| 恢复终结 | 重试、检查点恢复、人工升级、取消、任务终结 |

“验收通过”是接收意见，“正式提交”是权威账本确认，两者不能合并计数。“外部发送成功”也不能代替“外部效果已确认”。关键产出应保存在可恢复的任务工件与账本中，而不是只依赖临时消息。[外部资料乙]

## 五、探针自身的工作流

```text
确定权限与审查范围
    ↓
采集契约、事件、快照与引用
    ↓
归一化、去重、处理迟到与乱序
    ↓
重建版本链、责任链、证据链与外部操作链
    ↓
运行一致性、绑定、内容和恢复探针
    ↓
按固定口径计算指标并标记未知
    ↓
对缺口进行有界查证或确定性补全
    ↓
返回观测补丁／告警／审查报告
    ↓
记录采纳结果与自身观测质量
```

### 节点零：检查观察资格

固定目标安全域、任务集合、时间窗口、观察截止时间、允许来源、访问权限、脱敏策略、预算和输出目的。没有明确权限，不追踪越域引用，不抓取未知链接，不把业务凭证转交给其他模型或提供方。

静态审查可从文档开始；真实观测必须注明数据来源与采集方式。遇到未知协议或无法迁移的契约，返回不支持或部分可观察，不自行猜测字段含义。

### 节点一：采集与保留原始证据

读取原始事件、正式回执索引、版本清单与工件引用；记录分页游标、来源水位和采集截止点，避免遗漏分页或恢复后重复计算。原始证据与归一化视图分开存储。

只读适配器必须真正不产生业务副作用。查询接口若会触发重试、补单或状态迁移，就不能作为普通观察来源使用。

### 节点二：去重与时间处理

按来源和 `event_id` 去重；同身份同内容是重复投递，同身份不同内容是完整性异常。业务决策按 `handoff_id` 归并，外部效果按 `operation_id` 和远端真实交易／发布身份归并，不能把多个回执副本算成多次效果。

版本和因果关系优先于日志到达顺序。跨节点时间没有可信同步或误差范围时，不计算精确跨节点时延；负时延不能直接截断为零。能够使用同一可信节点或单调时钟测量时，记录所用计时方式。

实时报告设置迟到容忍窗口和观察水位，未收齐的结果标为暂定。迟到事件到达后更新报告版本和变更原因，保留旧报告的观察截止点。取消、超时与长期未完成项单独统计，不能静默从分母消失。

### 节点三：重建四条关联链

| 链 | 重建依据 | 必须发现的异常 |
|---|---|---|
| 版本链 | 输入／输出版本、清单摘要、父版本关系、正式回执 | 无权威提交的推进、缺失版本、重复后继、错误回退 |
| 责任链 | 已认证接收者、正式提交、当前责任、控制权代次 | 发送即转责、长期无人负责、重叠有效资格、旧资格晚到 |
| 证据链 | 事实身份、生产者、来源、工件摘要、核验版本 | 来源丢失、失效事实、旧审批、内容与声明不一致 |
| 外部操作链 | 业务意图、载荷、发送、远端回执、查证和补偿 | 同键不同载荷、重复效果、长期未知、未闭合补偿 |

缺失事件时，先查正式快照和回执索引。查到原本存在的权威记录，可以追加恢复的观测引用；查不到就保留断点，不能根据版本差推测并伪造每次历史提交。

存在分支时按分支和父版本重建依赖图。只有带明确聚合规则的提交才视为合并，不能把两条分支简单排序成线性链。

### 节点四：运行探针检查

每个检查输出“通过、失败、未知、不适用”，同时记录检查规则、目标工件、证据、执行时间与限制。来源标签由可信采集路径确定，不能接受日志自称“我是权威系统”。

工件实际摘要应从固定版本内容重算。语义检查须读取实际关键内容及其支撑事实；只看到两个摘要字段相等，最多支持字段一致，不能支持稿件真实正确。标题、摘要、表格、附件和发布载荷都应按业务契约纳入范围。

### 节点五：计算指标并生成缺口

先冻结指标适用对象，再计算分子、分母、未知项与覆盖率。每个比率同时返回计数；缺少分母来源时返回不可计算，不给出看似精确的百分比。

指标只描述材料支持的结论。频繁拒绝可能意味着上游质量差，也可能意味着闸门有效，必须与错误逃逸和最终结果联合解释。

### 节点六：有界补全

按“已有账本→固定工件→权威来源只读查询→确定性派生”的顺序查证，具体来源优先级由业务契约决定。不同权威在不同字段上有不同职责；银行回执不能证明审批合规，审批票不能证明钱已到账。

补全达到轮数、时间、调用数或费用限制即停止，并报告剩余缺口。冲突来源不能用多数投票硬凑成一致事实；应保留版本、时间和权威范围，交有权阶段裁定。

### 节点七：交付并观察反馈

离线模式交付报告和可复算指标；实时模式交付带观察截止点的告警；交互模式返回绑定请求的补丁。仅收到执行流程的正式采纳回执后，才统计为已采纳。

执行流程如何处置，由它自己的权限和策略决定。未收到反馈应标为待确认，不写成已修复。探针发现历史错误后，修复通常需要新业务事件，而不是改写旧日志。

## 六、探针清单与证据要求

| 探针 | 检查对象 | 判定所需证据 | 主要发现 |
|---|---|---|---|
| 契约完整性 | 阶段输入、输出、接收者、失败策略 | 固定版本契约与字段所有权规则 | 边界不明、必填缺失、未知扩展 |
| 作用域一致性 | 任务、安全域、资源、接收者 | 已认证身份与授权范围 | 跨任务拼接、越域读取或交接 |
| 版本连续性 | 候选和正式提交 | 清单摘要、父版本与权威回执 | 无依据推进、双重提交、错误回退 |
| 字段所有权 | 阶段增量和事实生产者 | 身份、契约、增量内容 | 编辑覆盖核查结果、伪造审批 |
| 事实有效性 | 实际消费的事实集合 | 事实版本、适用范围、撤销和替代记录 | 旧结论复活、过期事实继续使用 |
| 工件完整性 | 实际工件内容与声明摘要 | 不可变内容、重算规则和审批摘要 | 内容被替换、摘要自报未复算 |
| 内容支持关系 | 标题、正文、表格、关键载荷 | 实际内容、支撑事实、核验范围 | 新摘要配旧正文、限定条件丢失 |
| 接收成立性 | 接收方签收与责任转移 | 验收身份、正式提交、控制权记录 | 把发送成功当接收成功 |
| 恢复正确性 | 失败、检查点和重试范围 | 最后正式回执、证据有效性、恢复事件 | 从半成品恢复、不必要地全链重跑 |
| 幂等与查证 | 外部业务操作 | 稳定意图身份、载荷、远端效果证明 | 重复效果、同键异载荷、未知即重发 |
| 补全可信性 | 补全请求、补丁和采纳 | 来源、目标版本、字段白名单、采纳回执 | 推断冒充事实、过期补丁被接受 |
| 观察完整性 | 采集流与应有记录 | 权威索引、序号、水位、分页范围 | 事件缺失、乱序未处理、自身失明 |

“通过”是限定在所列对象、时间和证据范围内的判断，不是对整个系统永久可靠性的保证。内容检查由模型辅助时，应记录检查器版本、输入和可核查的结论摘要，不索取或保存模型私有思维链。

## 七、指标口径与计算规则

### 7.1 统一口径

每次指标计算固定作用域、工作流／契约／策略版本、观察截止时间、对象集合与迟到处理规则。跨风险等级或不同阶段职责的指标不直接混合比较。

计数先按业务对象去重。分母为零返回“不适用”；本应有分母但对象全集未知返回“不可计算”。未知、待确认、取消、超时和不适用分别保留。只在已知样本上计算的比率必须同时显示覆盖率，不能冒充全量比率。

阶段实例是一次逻辑工作；交接尝试是一份候选包；传输重发是一条包的重复投递。这三层不能混在一起。例如一次编辑修订提交了两份不同候选包，属于两次交接尝试；同一包因为网络抖动投递三次，仍只算一次。

### 7.2 交接质量与恢复指标

| 指标 | 公式或计算方法 | 分母与解释边界 |
|---|---|---|
| 交接尝试接收率 | 已正式接收的唯一候选包数 ÷ 已有终局接收／拒绝决定的唯一候选包数 | 未决候选另报数量与年龄；仅有验收意见不算正式接收 |
| 阶段首次交接通过率 | 第一份候选就被正式接收的阶段实例数 ÷ 第一份候选已有终局决定的阶段实例数 | 这是交接首过，不是包含提交前失败的整体执行首过 |
| 阶段最终交接通过率 | 在指定结算窗口内最终被接收的阶段实例数 ÷ 应在窗口内结算的阶段实例数 | 按契约截止结算，失败和超时不能被剔除；未到期另列 |
| 交接提交放大率 | 唯一候选包数 ÷ 至少提交过候选包的阶段实例数 | 不含传输重发；不能替代模型调用、算力或费用放大率 |
| 过期输入拦截率 | 提交前被拦截的已确认过期候选数 ÷ 经独立核查确认过期的候选总数 | 分母同时包含已拦截与已逃逸；必须报告核查覆盖率 |
| 旧事实逃逸率 | 正式接收后确认使用失效事实的工件数 ÷ 已完成事实有效性检查的正式工件数 | 未检查工件另列；只查摘要不能当成已完成内容检查 |
| 内容核验覆盖率 | 已完成契约要求内容检查的关键工件数 ÷ 契约要求检查的关键工件数 | 标题、附件和载荷等须按所声明范围覆盖 |
| 来源链完整率 | 具有完整、可展开且身份可验证来源链的必需事实数 ÷ 契约要求的必需事实数 | 完整来源链不等于事实真实或内容正确 |
| 工件摘要复核覆盖率 | 从实际固定内容重算过摘要的必需工件数 ÷ 应复核的必需工件数 | 摘要相同与摘要已复核分别统计 |
| 局部恢复成功率 | 在时限内复用有效上游成果并只重做必要部分的恢复事件数 ÷ 已到结算期限的适用恢复事件数 | 上游已经失效的事件单独分类，不强求只重做当前一棒 |
| 有效检查点复用率 | 恢复时实际复用的仍有效前序阶段数 ÷ 恢复时可复用的有效前序阶段数 | 按恢复事件记录候选集合，避免不同链长误导比较 |

提交前执行失败应通过“阶段执行尝试次数、执行首过率和资源成本”另行衡量。没有阶段开始及失败事件时，不得从交接日志推算这些指标。

### 7.3 版本、责任与副作用安全指标

| 指标 | 计算方法 | 解释边界 |
|---|---|---|
| 非法版本推进数 | 确认没有合法接收与正式提交依据的版本推进数量 | 缺失日志先标未知并查账本，不直接定罪 |
| 重复正式提交数 | 同一候选包对应多次正式提交的额外提交数 | 回执重复投递不算重复提交 |
| 越权字段提交数 | 已正式接收且确认越过字段所有权的增量数量 | 被成功拦截的尝试另计 |
| 责任转移证据完整率 | 同时有合法验收者、提交回执和对应控制权记录的转移数 ÷ 应发生的正式转移数 | 计划接收者不能替代实际接收者 |
| 无主交接数量与最长年龄 | 超过允许等待时间且找不到有效责任归属的交接数量和持续时间 | 保留原责任人的正常等待不自动算无主 |
| 过期资格操作数 | 使用失效控制权代次仍被接收的提交或外部写入数 | 需有网关／接收端证据，不只看本地锁 |
| 重复外部效果数 | 对每个唯一业务意图，累计超出允许次数的已确认远端效果数 | 必须识别远端真实效果身份；多个回执副本不能重复算 |
| 未决外部操作数与年龄 | 已发送但未确认最终效果的唯一业务操作数及等待年龄 | 结果未知不计为成功，也不自动计为未执行 |
| 查证完成时延 | 首次记录结果未知至权威结果被确认之间的时间 | 时钟不可比较时返回未知；未完成者报告当前年龄 |
| 补偿未闭合数量与年龄 | 已提出且必须完成、但尚无完成证据的补偿数量及年龄 | 补偿尝试完成不等于补偿效果完成 |

安全指标不依赖单一“健康分”抵消。一次已确认越权提交，不能用很多次正常交接把其平均成“总体正常”。

### 7.4 等待、补全与探针自身指标

| 指标 | 公式或计算方法 | 解释边界 |
|---|---|---|
| 接收接缝时延 | 候选包提交至正式接收提交的时长，报告中位数、百分之九十五分位 | 接收和拒绝分组；等待未结束者另列，不静默丢弃 |
| 未决交接数量与年龄 | 已提交但没有终局接收／拒绝决定的唯一候选包数及年龄 | 结合观察水位判断，防止把迟到误判为丢失 |
| 证据化补全完成率 | 在截止前被采纳且有合格证据的缺失观测字段数 ÷ 已到截止期限的请求缺失字段数 | 以请求最初的字段集合为准，不能补容易的新字段扩大分子 |
| 观测补丁采纳率 | 已采纳或按字段统计已采纳部分的有效补丁数 ÷ 已完成评估的有效补丁数 | 单位必须固定；过期、越权、待确认分别列出 |
| 非法补丁被采纳数 | 已确认过期、越权或无来源但仍被采纳的补丁数量 | 需要执行侧采纳回执，不能只靠探针发送日志 |
| 事件采集覆盖率 | 已采集且唯一匹配的应有权威记录数 ÷ 独立权威索引确定的应有记录数 | 无独立索引或完整序号范围时不可计算 |
| 探针阻塞开销 | 执行侧明确等待探针的时间区间之并集 | 并行请求不能简单相加；旁路耗时不全算业务阻塞 |
| 探针资源成本 | 探针自己的查询数、读取量、计算量和计费记录 | 不与执行模型费用混算；费率缺失则金额未知 |
| 报告修订量 | 因迟到证据或纠错而改变的指标／发现数量 | 每次变更记录原因与新观察截止时间 |

分位数默认采用最近秩法：将 n 个有效样本升序排列，取第 `ceil(0.95 × n)` 个作为百分之九十五分位。样本数必须一起显示；样本极少时不据此制定服务承诺。实现改用其他算法时固定算法版本，不混用比较。

### 7.5 单项指标输出结构

```yaml
指标名称: 阶段首次交接通过率
指标定义版本: "1.0"
作用域: "<任务与窗口>"
统计单位: 阶段实例
分子: null
分母: null
数值: null
状态: 不可计算
已知对象数: null
未知对象数: null
不适用对象数: null
待结算对象数: null
覆盖率: null
观察截止时间: "<含时区时间>"
计算规则: 第一份候选正式接收的实例数除以第一份候选已有终局决定的实例数
证据引用: []

```

适用但材料不足用“不可计算／未知”；业务本身不需要该检查才用“不适用”。数值零意味着在明确覆盖范围内观察到零次，不意味着系统全量零事故。

## 八、补全执行流程的数据

### 8.1 可以补什么，不可以补什么

| 缺口 | 允许的补全 | 不允许的替代 |
|---|---|---|
| 缺少契约中已声明的阶段说明 | 从固定契约版本补入观测元数据 | 将计划配置当作真实执行记录 |
| 缺少正式接收回执引用 | 从授权账本查询原回执并验证关联 | 依据“对方已回复”新造一张签收票 |
| 缺少工件摘要检查结果 | 读取指定不可变版本，重算并保留方法 | 用当前文件摘要代替未知历史文件摘要 |
| 缺少等待时间 | 从可比较的真实时间戳确定性计算 | 根据日志顺序猜测精确耗时 |
| 缺少证据可访问性结果 | 只读检查指定引用及权限 | 来源可打开就宣告事实为真 |
| 缺少外部操作状态 | 查询原业务意图的权威状态，返回原证据 | 再执行一次操作试试看 |
| 存在冲突事实 | 返回各来源、版本、时间和适用范围 | 自动挑一个“更像真的”作为正式事实 |
| 没有数据 | 返回未知、原因、责任人与建议来源 | 用默认值、平均值或模型编造填满表格 |

### 8.2 观测证据的四种状态

| 状态 | 定义 | 是否可直接支撑关键业务放行 |
|---|---|---|
| 直接观测 | 来自可验证原始事件、固定工件或权威查询 | 仍需执行侧检查权威范围、时效与业务适用性 |
| 确定性派生 | 由可信输入通过固定公式或算法计算 | 只能支撑相应派生结论，不能扩大到其他事实 |
| 推断 | 基于模式、概率或不完整材料形成的解释 | 不可以，只作为排查线索 |
| 未知 | 未采集、无权限、不支持、冲突或证据不足 | 不可以，按业务风险暂停或转人工 |

高置信度不是权限，模型给出百分之九十九置信度也不能替代审批或银行回执。观测数据的字段名也不赋予权威性，例如 `approved: true` 必须有相应审批来源才能被当作已审批证据。

### 8.3 补全请求协议

以下结构与执行文档使用同一协议。具体时间、摘要和引用由实际运行提供。

```yaml
protocol_version: "1.0"
request_id: 补全请求一
scope:
  tenant_id: 示例租户
  workflow_id: 示例工作流
  task_id: 示例任务
  chain_id: 示例交接链
target:
  stage_instance_id: 编辑实例一
  handoff_id: 编辑交接包二
  expected_version: 2
  expected_manifest_digest: "<目标清单摘要>"
  artifact_digests: ["<待校验工件摘要>"]
field_paths:
  - observations.artifact_integrity
  - observations.evidence_availability
purpose: 补充接收方验收所需的观测证据
allowed_sources: [已登记工件库, 已登记审计账本]
permission_ref: 只读授权引用
allow_deterministic_derivation: true
max_rounds: 2
max_cost: 由场景提供
deadline_at: "<截止时间>"
```

请求不能授权探针修改核心业务字段。读取来源、最大查询次数、超时和费用应由执行策略具体化；“允许派生”只允许确定性计算，不是允许补造事实。

### 8.4 补全补丁协议

```yaml
protocol_version: "1.0"
patch_id: 观测补丁一
request_id: 补全请求一
scope:
  tenant_id: 示例租户
  workflow_id: 示例工作流
  task_id: 示例任务
  chain_id: 示例交接链
target:
  stage_instance_id: 编辑实例一
  handoff_id: 编辑交接包二
  expected_version: 2
  expected_manifest_digest: "<目标清单摘要>"
  artifact_digests: ["<待校验工件摘要>"]
observations:
  - field_path: observations.artifact_integrity
    value: null
    evidence_status: 未知
    evidence_refs: []
    source_digest: null
    observed_at: "<观测时间>"
    valid_until: "<适用截止时间>"
    method: 因只读访问被拒绝，未完成内容摘要复算
    rule_version: "1.0"
recommendation: 暂停依赖该证据的验收，交由有权限的责任人处理
```

`scope` 和 `target` 必须逐字段匹配原请求。尖括号内容是模板占位值，真实接口必须使用实际身份、时间、摘要与引用，不能直接传输占位文本。

每份补丁不可变；相同补丁重发应由 `patch_id` 去重，同标识不同内容必须拒绝。补丁只追加观测数据，不修改原事件、旧版本或业务状态。

### 8.5 执行侧采纳检查

执行侧检查请求身份、作用域、目标阶段与候选包、预期版本、清单和工件摘要、字段白名单、来源权威、有效期、权限和预算。

返回数据与当前目标不一致时，拒绝本次采纳并记录 `stale_probe_patch`。旧补丁可以用于旧版本审计，但不能因此变成当前版本证据。纯观测追加不推进接力棒；涉及正式业务证据时，由有权阶段生成新的业务增量，再走正式验收与提交。

采纳回执至少包含补丁身份、处理时间、逐项采纳结果、拒绝原因和执行侧目标版本。探针收到后才能统计补全成效。

### 8.6 补全示例：从 v2 继续，不替执行流程做决定

假设编辑交接在 v2 因版本绑定被拒绝。探针读取拒绝回执和实际工件，查明工件仍使用已替代的主张，并返回错误主张位置、所用事实版本、当前有效事实引用和来源证据。

执行流程接收这份诊断后，由编辑重新生成实际内容，提交新候选包；接收方重新验收，通过正式提交才进入 v3。探针不直接修正 `verified_claims`，不把失败回执改成成功，也不把头版本加一。

这个闭环补全的是“为什么失败、依赖哪一版、修复需要哪些事实”的数据，而不是用一份探针报告替代业务完成。

## 九、告警、处置与防止反馈失控

| 等级 | 典型情况 | 探针动作 | 执行侧动作 |
|---|---|---|---|
| 严重 | 已确认越权提交、重复外部效果、工件被替换、无依据版本推进 | 返回确切对象、证据、影响范围和紧急告警 | 依既定权限暂停后续高风险操作，查证或转人工 |
| 高 | 关键证据缺失、外部结果未知超过时限、责任无法确认 | 返回缺口、等待年龄和可查询来源 | 暂停依赖未知状态的下一步，保留责任人 |
| 中 | 首过率持续下降、有效上游成果大量重跑、接缝等待增加 | 按原因和阶段分组诊断 | 调整契约、上下文、路由或预算，先评审再生效 |
| 低 | 非关键指标缺失、旁路采集延迟、补丁重复投递 | 标注覆盖率和采集质量 | 允许按策略降级，不关闭业务硬闸 |

严重级别表达的是处置优先级，不等于探针拥有新的权限。无法确定是否违规时，报告“高风险未知”，不要为了方便告警而把未知伪装成已确认事故。

安全不变量以零容忍的单事件规则处理；性能阈值依据业务风险、阶段职责、样本量与服务目标设定，不能给所有场景统一要求首过率百分之九十五或恢复时延五秒。

同一目标、同一规则、同一根因的告警合并，保留首次发现、最近发现、计数和处置状态。补丁采纳率不能成为越高越好的目标；正确拒绝不可信补丁也是成功的治理行为。

探针不得自行修改生产契约、授权范围、模型路由或风险阈值。优化建议应形成版本化变更，经过评审、测试、逐步启用和可恢复发布。否则“自动优化”可能把有效闸门优化掉。

## 十、通用场景适配

| 场景 | 优先检查 | 应补全的数据 | 不应越界的判断 |
|---|---|---|---|
| 研究与发布 | 旧主张、标题正文冲突、稿件与来源版本 | 主张引用、实际内容摘要、核验范围、发布确认 | 不因引用很多而认定全部真实 |
| 客服与升级 | 工单身份、责任转移、处理结果 | 接收回执、已处理动作、剩余问题 | 不从“客户满意”推断退款到账 |
| 合同流转 | 正文附件版本、签署主体、审核覆盖 | 审核对象、签署工件引用、归档证据 | 不把签署动作当作法律审核完成 |
| 构建与部署 | 实际制品、扫描与批准版本、环境 | 制品摘要、部署状态、恢复点 | 不把流水线结束当作线上生效 |
| 核算与付款 | 批次、审批、收款对象、业务意图 | 原操作状态、权威回执、对账结果 | 不从已审批推断已付款 |
| 跨会话长任务 | 检查点、未决操作、当前责任 | 上次正式状态、失败原因、继续前提 | 不从进度摘要推断所有工作已验收 |

适配器改变数据源、工件类型与业务规则；指标的单位、缺失值规则、证据状态和无副作用边界保持不变。特定场景不需要的指标按契约标为不适用，不删除核心数据质量说明。

## 十一、课程输出的离线分析示例

### 11.1 已提供的材料

```text
研究：v0 → v1，接收
核查：v1 → v2，接收
编辑尝试一：v2 → v2，拒绝，stale_claim_binding
编辑尝试二：v2 → v3，接收
发布：v3 → v4，接收
```

该示例只使用用户给出的课程轨迹，没有运行课程仓库或查询真实发布系统。为演示计数，按课程描述将五行视为五份不同候选包、四个逻辑阶段，并将“接收”按示例定义解释为成功提交。真实系统需用身份和权威回执确认这些前提。

### 11.2 在上述演示前提下可计算的值

| 指标 | 计算 | 演示结果 |
|---|---|---|
| 交接尝试接收率 | 4 份接收候选 ÷ 5 份有决定候选 | 80% |
| 阶段首次交接通过率 | 研究、核查、发布共 3 个首次通过阶段 ÷ 4 个阶段 | 75% |
| 阶段最终交接通过率 | 4 个最终通过阶段 ÷ 4 个应结算阶段 | 100% |
| 交接提交放大率 | 5 份候选包 ÷ 4 个提交过候选的阶段 | 1.25 倍 |
| 文本记录的旧绑定拒绝次数 | 一条 `stale_claim_binding` | 1 次 |

这些只是演示口径值，不应直接写入真实系统的生产指标。

### 11.3 不能由该轨迹确定的值

工件是否真实重算摘要、标题正文是否全部核验、来源链是否完整、是否存在未记录的错误逃逸、权限是否正确、外部发布是否成功、是否重复发布、等待时延和真实成本，均为未知。

即使文字显示一个错误被拦住，也不能计算全量旧事实拦截率，因为未发现或未记录的错误候选集合并不已知。版本最终为 v4，也不能单独证明远端发布完成。

### 11.4 诊断与建议

已见问题是编辑第一次沿用了旧绑定；已见恢复位置是 v2，随后存在一次成功修订。可建议检查编辑上下文是否混入旧主张、内容检查是否覆盖标题，以及摘要是否由可信服务重算。

上述原因是待验证假设，不是由五行日志证明的根因。补充实际输入清单、失败候选、修订候选、核验记录及正式回执后，才能确认。

## 十二、探针验证用例

| 用例 | 输入变化 | 必须产生的结果 |
|---|---|---|
| 无任何运行数据 | 只给契约文档 | 静态审查与埋点缺口；运行指标不可计算 |
| 重复事件 | 同一事件重复导入 | 业务计数不变，自身重复采集计数增加 |
| 事件身份冲突 | 同一事件身份包含不同内容 | 完整性告警，不任选一份静默覆盖 |
| 日志乱序与迟到 | 拒绝事件晚于重试成功抵达 | 按版本和因果重建；报告带修订记录 |
| 缺失正式回执 | 有验收意见，没有提交证明 | 接收状态未知，触发只读查证 |
| 伪造权威来源 | 日志自称已审批，无认证凭据 | 不承认其权威性，保留证据缺口 |
| 摘要造假 | 新摘要字段配旧正文 | 内容检查失败；若不能读取正文则未知 |
| 并发版本变化 | 旧尝试拒绝时头版本已前进 | 不误判应将全局头回退 |
| 外部成功、本地超时 | 有原意图和远端成功证明 | 识别需要补记回执，不建议重复执行 |
| 远端未找到但存在索引延迟 | 查询契约不支持立即确定未执行 | 保留未知，不准把未找到当成可重发证据 |
| 相同效果多个回执副本 | 同一远端效果重复出现 | 不增加重复业务效果数 |
| 过期观测补丁 | 目标工件或正式版本已变化 | 建议拒绝采纳；不得迁移成当前事实 |
| 部分可见数据 | 只能读取一部分必需工件 | 报告覆盖率、未知项与权限限制 |
| 不可比较的时钟 | 跨主机时间偏移产生负时延 | 时延未知或区间估计，不能截断成零 |
| 补全预算耗尽 | 继续查询才能填满字段 | 停止，输出未解决字段和责任人 |
| 旁路发现严重历史违规 | 违规早于告警时间 | 明确发现与违规时间，不声称事先阻断 |
| 执行侧拒绝补丁 | 返回正式拒绝回执 | 不统计为已修复；记录拒绝原因 |

以上为设计验收用例，不代表已在实际运行环境执行。探针上线前，应使用可控样本验证误报、漏报、事件丢失恢复和自身开销，并保留版本化结果。

## 十三、独立使用入口与交付模板

### 13.1 交给探针执行者的任务指令

```text
依照《交接链：工作流可观测性探针》审查提供的材料。
先声明运行模式、材料范围、授权来源、观察截止时间和限制。
没有运行数据时只做静态审查，不生成实际通过率或耗时。
按事件、候选包、阶段实例和外部业务意图分别去重关联。
重建版本链、责任链、证据链和外部操作链。
只对有证据的项目作确定判断，其余标记未知或不适用。
计算指标时列出分子、分母、未知项、覆盖率与规则版本。
需要补全时只读查询或做确定性派生，不执行业务副作用。
补丁绑定目标任务、版本、工件和来源；等待执行侧采纳回执。
输出事实、待验证解释和建议动作，不把建议写成已经执行。
```

### 13.2 报告结构

```yaml
报告身份: "<唯一身份及版本>"
运行性质: 真实观测／课程演示／静态审查／测试样本
运行模式: 离线独立／实时旁路／有界交互
审查范围: "<任务、安全域、时间窗口>"
观察截止时间: "<含时区时间>"
材料与来源:
  契约版本: []
  正式清单: []
  权威回执: []
  实际工件: []
  外部证据: []
数据质量:
  去重结果: 未知
  采集覆盖率: 未知
  缺失记录: []
  时钟与迟到限制: []
重建结果:
  最后可验证正式版本: null
  当前责任人: 未知
  版本断点: []
  未决外部操作: []
发现:
  已确认事实: []
  已确认违规: []
  未知或证据不足: []
  待验证原因假设: []
指标明细: []
数据缺口:
  - 缺失字段: "<需要补什么>"
    影响: "<哪些判断不能成立>"
    允许来源: []
    责任人: "<谁有权补充>"
    建议处置: "<有界查证或转人工>"

```

报告应能定位到具体版本、工件、回执和责任人。只能输出“成功率下降”而无法解释分母、证据和恢复位置，不算完成探针任务。

### 13.3 最小完成条件

一次探针运行完成，不要求所有缺口都填满，但必须明确审查范围，保留证据引用，输出可解释的未知项，完成已承诺且有条件执行的检查，并记录预算终止或权限限制。

一次有界补全完成，不等于业务已修复；一次告警关闭，也不等于原错误不存在。业务修复结果须从新的正式回执或外部效果证据中验证。

## 十四、治理、成本与资料说明

探针默认记录标识、摘要、时间、规则、来源引用和必要的结论，而不是全量敏感正文。凭证、客户信息、银行账号和合同细节应按授权最小化读取与保留；摘要本身也不能自动视为匿名化。

指标标签只使用有限取值，例如工作流类别、阶段、原因码、风险等级和规则版本。任务身份、工件身份和用户信息保留在受控追踪记录中，避免无界标签和隐私外泄。

基础审计是执行流程的责任，旁路观测可以采样，但关键提交和外部效果的权威记录不得仅以采样方式保存。采样报告必须说明采样规则，不能据此宣布未观测到的全量事件为零。
