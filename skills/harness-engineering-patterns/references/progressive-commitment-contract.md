# Progressive Commitment Contract / 渐进承诺共享契约

Version / 版本: `0.1.0`; status / 状态: `draft`; implementation / 实现: `specification_only`.

## Purpose and Identity / 用途与身份

Use with the [execution flow](progressive-commitment-execution-flow.md) and [independent probes](progressive-commitment-observability-probes.md) when a concrete capability earns wider autonomy through verified evidence. This specializes the [governance contract](governance-contract.md), [approval gate](approval-gate-contract.md) and [blast radius contract](blast-radius-contract.md). / 当具体能力需要凭核验证据逐步扩大自主范围时，与执行流程和独立探针配合使用；本契约细化治理、审批门与爆炸半径契约。

Canonical identity remains `PATTERN_0048`, `CELL_GOVERNANCE_PARALLEL`, `COG_GOVERNANCE__TOP_PARALLEL`. The supplied `PATTERN_GOVERNANCE_0003` and `PROBE_GOVERNANCE_0003` are source aliases. Their chain and loop coordinates describe sequential transitions and cross-run feedback; they do not move this named pattern or promote blank cells. Each stage still merges independent required checks. See the [source map](progressive-commitment-source-map.json) for unchanged source fingerprints and interpretation changes. / 保留现有模式、单元及治理并行主坐标。附件编号仅作为来源别名；链式与循环坐标描述顺序迁移及跨运行反馈，不迁移命名模式或晋升空白单元。每阶段仍须汇合必要的独立检查；来源指纹及解释修订见映射文件。

These documents specify behavior, not a deployed controller, issuer, calculator or normative Schema. Existing [capability-credential.schema.json](../schemas/capability-credential.schema.json) represents Skill routing qualification; it does not implement this action-authority credential, nor grant external execution rights. Integration needs a distinct versioned adapter and conformance tests. / 文档规定预期行为，不代表控制器、签发者、计算器或规范 Schema 已部署。已有能力凭证 Schema 表示 Skill 路由资格，不实现本模式的行动权限凭证，也不授予外部执行权；接入需要独立版本化适配器与一致性测试。

## Authority and Two Clocks / 权责与两只钟表

The executor proposes and acts within an existing grant; the credential authority alone issues or revokes; an independent trusted verifier validates outcomes; a scoped approver accepts a locked promotion batch; the incident controller freezes affected authority. Probes append observations and recommendations only. These are system responsibilities, not permission for an assistant to call business tools merely because this document names them. / 执行者提出请求并在已有授权内行动；只有凭证权威签发或吊销；独立受信验证者核验结果；范围匹配的审批者批准锁定晋级批次；事故控制器冻结受影响权限。探针只追加观察和建议。这些是系统职责，文档列出业务工具并不授权助手调用它们。

| Axis / 轴 | State and permitted progression / 状态与允许推进 |
| --- | --- |
| `task_stage` / 单次任务阶段 | Read → proposal → checks → rehearsal → shadow → limited effect → current-scope expansion, following a preapproved risk profile. Success advances only this task. / 读取、提案、检查、演练、影子、受限效果、当前范围扩大，遵循预先批准的风险配置；成功仅推进本次任务。 |
| `authority_level` / 跨任务权限等级 | `observe → suggest → shadow → limited → autonomous`; progression requires new scoped evidence, approval and credential issuance. / 观察、建议、影子、受限、自主；晋级需要新的范围证据、审批与凭证签发。 |
| `control_state` / 控制状态 | `active / frozen`; freeze overrides any level. Investigation or compensation needs separately scoped authority. / 活动或冻结；冻结优先于任何等级，调查或补偿须另有范围明确的权限。 |

Autonomy remains bounded by exact capability, environment, tenant, tools, resources, data, limits, time and human-required exceptions. Full production means the full **approved scope**, never unlimited authority. A shorter task ladder must be a versioned approved profile with recorded applicability, not an ad hoc skipped stage; cross-level promotion exceptions require explicit policy and stronger independent evaluation. / 自主仍受具体能力、环境、租户、工具、资源、数据、额度、时间及人工例外约束。全量生产只指完整的**已批准范围**，绝非无限权限。短任务阶梯须为带适用依据的已批准版本化配置，不得临时跳步；跨级权限晋升须有明确策略和更强独立评测。

## Object and Identity Contract / 对象与身份契约

Authenticate tenant, actor and source at trusted ingress. Use nonempty IDs and exact versions, nonnegative revisions, timezone-qualified UTC timestamps and canonical encoding/hash versions. Empty allowlists deny; absent scope never means unlimited. Hash integrity alone proves neither source authenticity nor authorization. / 在可信接入认证租户、主体及来源；使用非空标识、精确版本、非负修订、带时区 UTC 时间与规范编码哈希版本。空允许列表为拒绝，缺失范围不代表无限；单纯哈希完整性不能证明来源可信或已授权。

Credential states are `draft → active → expired / revoked / superseded`; terminal credentials never reactivate. Promotion states are `collecting → eligible → locked → pending_review → approved → pending_issue → issued`, with `rejected / invalidated` exits. Renewals, recovery and same-level scope widening require their own reviewed revision; renaming them cannot bypass evidence or revocation. / 凭证从草稿到有效，再进入过期、吊销或被替代终态，不得重新激活。晋级从收集、达标、锁定、待审、批准、待签发到已签发，可拒绝或失效退出。续签、恢复及同级扩范围均须独立评审修订，不得靠改名绕过证据或吊销。

## Admission and Independent Merge / 准入与独立汇合

Effective scope is the intersection of current credential, system hard policy, tenant/task/tool/data boundaries, approved task stage, applicable exact-action approval and remaining shared budget. Comparable limits take the minimum; deny overrides allow; incompatible units or unresolved mandatory evidence block. Parent and child scopes intersect and share conserved reservations, rather than copying parent quota. / 有效范围取当前凭证、系统硬策略、租户任务工具数据边界、获准阶段、适用精确动作审批及剩余共享预算的交集；可比限额取最小，拒绝优先，单位不兼容或必要证据未决时阻断。父子范围取交集并共享守恒预留，不复制父额度。

Before each effect, including each expanded batch, merge credential, approval, budget, tool/data isolation, idempotency, concurrency/retry, business precondition and recovery checks against one action digest and policy snapshot. Every required check has an owner, evidence contract, deadline and verdict; failed, missing, expired or timed-out checks block. Record optional and nonapplicable checks with reasons. Parallel execution or majority vote cannot erase a veto. / 每次效果（含每个扩批）前，针对同一动作摘要与策略快照汇合凭证、审批、预算、工具数据隔离、幂等、并发重试、业务前置及恢复检查。每项必要检查都有负责人、证据契约、期限及裁定；失败、缺失、过期、超时均阻断。可选或不适用检查记录理由；并行执行或多数票不能消除否决。

Persist a bound admission/intent before submission; use the blast-radius authority for atomic multidimensional reservation and durable intent idempotency. Immediately at gateway dispatch recheck the live credential revision, control epoch, expiry, approved payload and required gates; planning-time success cannot substitute. Exact retries return the durable result; changed payload with the same intent/key is a conflict. Admission and external APIs are separate failure boundaries; never claim end-to-end exactly-once without downstream guarantees. / 提交前持久化绑定准入与意图；多维原子预留和持久意图幂等由爆炸半径权威负责。网关派发时即时复核凭证修订、控制代次、到期、获批载荷和必要闸门，规划时通过不能替代。精确重试返回持久结果，同意图键异载荷冲突；准入与外部 API 分属不同失败边界，缺少下游保证时不得声称端到端严格一次。

Keep `mechanical_status`, `effect_certainty` (`none / confirmed / partial / unknown`), `business_verdict` (`pass / fail / pending / conflict`) and `compensation_status` separate. Timeout is unknown, not proven failure or nonexecution. Reconcile using authoritative receipts before retry; partial results remain per-object, with unresolved exposure retained. Compensation is a new authorized effect and never erases the original result or consumed budget. / 机械状态、效果确定性、业务裁定和补偿状态分开。超时为未知，不能视为确定失败或未执行；重试前以权威回执对账，部分成功保留对象级结果与未知暴露。补偿属于新的获批效果，不抹去原结果或已消费预算。

## Evidence and Promotion Commit / 证据与晋级提交

1. Append every outcome, including failure, refusal, unknown and correction. Deduplicate immutable event delivery separately from logical effect evidence. One run may contain several capability outcomes, but retries, child results and reused receipts from the same business trial form one evidence cohort per capability/window. Identical content is a duplicate candidate, not sufficient proof that distinct genuine trials are identical. / 追加所有结果，含失败、拒绝、未知及纠正。不可变事件投递去重与业务效果证据去重分开；一次运行可含多个能力结果，但同一业务试验的重试、子结果及复用回执在每个能力窗口只构成一个证据组。内容相同只是疑似重复，不能据此合并不同真实试验。
2. Grade evidence against the target stage, version, environment, scope and risk slices. Shadow/synthetic/sandbox evidence can satisfy designated preproduction tests, but never counts as real production success. Crossing into limited production requires a separately approved bounded pilot; do not demand unauthorized production actions to earn the first production credential. Production-to-autonomy evidence must come from already authorized real operation. / 依据目标阶段、版本环境范围风险切片评估证据。影子、合成、沙箱证据可满足指定上线前测试，不能计为真实生产成功。进入受限生产须另行批准小范围试点，不能要求先越权执行生产来获得首张生产凭证；向自主晋级的生产证据来自已有授权的真实运行。
3. Freeze an ordered evidence snapshot, target scope and policy; store both digest and authoritative source/ledger watermarks. A locked digest alone does not detect later failures. Review and issuance must re-read fresh failure/incident indexes and authority state. Pending, conflicting, stale, inferred or untrusted evidence cannot satisfy success requirements. Required quantity, slice diversity, expiry and soak duration are capability policy parameters, not universal magic numbers. / 冻结有序证据、目标与策略，同时保存摘要及权威来源账本水位。摘要不变不能发现后续失败；评审和签发均复读最新失败事故索引与权限状态。未决、冲突、过期、推断或不受信证据不能满足成功要求；数量、多样性、有效期及观察期由能力策略配置。
4. Serialize issuance against the subject/capability authority revision and incident epoch. In one authority transaction/equivalent, recheck evidence eligibility, late relevant failures, versions, fresh source watermarks, approver authority/expiry and scope; consume approval once, activate the bound successor and supersede the predecessor, then durably publish change events. CAS conflict, relevant new failure, target change or unknown freshness invalidates/requeues the application; it never permits stale issuance. / 签发与主体能力权限修订、事故代次串行化。在同一权限事务或等价边界中，复核证据资格、相关迟到失败、版本、最新来源水位、审批者权限到期范围；一次性消费批准、激活绑定的新凭证并替代旧凭证，持久发布变更事件。CAS 冲突、相关新失败、目标变化或新鲜度未知时令申请失效或重新排队，不能陈旧签发。
5. Issued scope must be contained in requested, approved, evidence-supported and hard-policy scopes. Narrower approval is allowed only with a newly sealed approved-scope binding and coverage recheck; it does not mutate the submitted request. Duplicate issuance returns the original credential. / 签发范围必须包含于请求、批准、证据支持及硬策略范围内。审批缩小范围须另行封存获批范围绑定并复核覆盖，不修改原请求；重复签发返回原凭证。

If outcome stores and authority stores cannot share a transaction, use an authority-visible invalidation revision/barrier fed by durable ordered delivery; stale or unconfirmed source freshness blocks issuance. Specify the operational detection lag. Never describe asynchronous replication as instantaneous knowledge of an undiscovered failure. / 若结果库与权限库不能共用事务，应通过持久有序投递建立权限侧可见的失效修订屏障；来源陈旧或新鲜度未确认时阻断签发。明确运行中的检测滞后，不把异步复制描述成即时获知尚未发现的失败。

## Freeze, Revocation and Recovery / 冻结、吊销与恢复

Serialize authoritative freeze/epoch advancement with issuance and gateway admission/dispatch. After that boundary no new affected dispatch is permitted. Signed credential bodies and cache invalidation broadcasts alone cannot enforce this: gateways require authoritative epoch checks or a documented bounded freshness lease whose loss blocks affected writes. A lease-based deployment must state its maximum residual exposure; it cannot claim immediate global revocation. / 权威冻结及代次递增须与签发、网关准入派发串行化；该边界之后不得新增受影响派发。仅靠凭证签名正文或缓存广播不足以实现：执行点须检查权威代次，或采用明确新鲜度上限且失联阻断写入的租约。采用租约时须声明最大残余暴露，不能声称即时全局吊销。

Track detection, authoritative freeze, revocation commit, each required gateway acknowledgment and first proven rejection separately. Fix the gateway roster at the incident boundary and track missing/offline members; newly joining gateways synchronize the current epoch before accepting work. Effects already submitted before freeze can settle later: reconcile and compensate under separate authority; later settlement alone is not a post-revocation dispatch violation. / 分别记录发现、权威冻结、吊销提交、各必要执行点确认与首次已证拒绝。冻结时锁定执行点清单并追踪缺失离线成员；新加入执行点先同步当前代次。冻结前已提交效果可迟后结算，须对账及另行授权补偿；迟后结算本身不等于吊销后越权派发。

Reset the recovery baseline after containment and approved remediation. Retain earlier failures and successes for audit, but do not score them toward restoration. Revoke dependent child grants, test the incident and neighboring risks, obtain recovery approval, issue a new limited/safe credential and progress under the approved recovery ladder. Expand freeze scope only on evidence of wider compromise. / 遏制与获批修复后重建恢复基线；旧成功失败保留审计但不计入恢复成绩。吊销依赖子授权，重测事故及邻近风险，取得恢复批准，签发新的受限或安全等级凭证并依恢复阶梯推进；只有更大范围失控的证据才扩大冻结。

## Events and Probe Interaction / 事件与探针交互

Events carry `schema_version`, canonical `pattern_id`, source alias, authenticated tenant/source/actor, immutable event ID, source sequence, trace/run/task/step, parent event, action/intent, credential/capability/subject/model/tool/policy versions, baseline/authority revision/control epoch, event type, independent states, occurred/recorded times, source/evidence refs, canonical payload digest and verification state. Missing context remains an explicit gap; control events may have no business run but must identify their authoritative subject and scope. / 事件携带 Schema 版本、规范模式及来源别名、认证租户来源主体、不可变事件标识、来源序号、链路运行任务步骤父事件、动作意图、凭证能力主体模型工具策略版本、基线权限修订代次、类型及独立状态、发生记录时间、来源证据引用、规范摘要与核验状态。缺失上下文明确记为缺口；控制事件可无业务运行，但必须识别权威对象范围。

Separate `action_intent_recorded`, `dispatch_committed`, `tool_completed` and `business_verified`; an ambiguous “action started” event cannot prove ordering. Also record required-check results/merge, outcome revisions, window locks, promotion decisions/invalidation, credential lifecycle, freeze/acknowledgment and closure. Tenant + source + event ID deduplicates exact delivery; same identity/different content is quarantined. Source sequences and authoritative transaction revisions establish causality; wall-clock order alone does not. / 分开发出意图记录、派发提交、工具完成及业务核验，含混的“动作开始”不能证明顺序。还记录必要检查及汇合、结果修订、窗口锁定、晋级决策失效、凭证生命周期、冻结确认与关闭。按租户来源事件标识去重，异内容同标识隔离；以来源序号及权威事务修订建立因果，不能只靠时间排序。

The consumer independently verifies source authenticity, scope, digest, freshness and conflicts before appending enrichment.
