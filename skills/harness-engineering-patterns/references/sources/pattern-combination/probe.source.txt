# 工作流可观测性探针

## 1. 文档定位

本文件将传统“可观测指标”改造成一组可插拔、可独立运行、可与执行流程交互的工作流可观测性探针。

探针的目标不是简单统计调用次数、时延和错误率，而是重建一项任务为什么这样展开、依据什么作出判断、谁批准了哪一个动作、动作实际影响了什么、失败后从哪里恢复，以及最终凭什么认定任务完成。

本探针可以：

- 独立接入任意工作流，读取事件、日志、状态快照和工件；
- 离线分析一次已经结束的运行；
- 在线观察正在执行的任务；
- 向执行流程请求补齐缺失的状态、证据、权限或验收数据；
- 生成异常发现、追踪报告和治理建议；
- 在显式授权下，将严重发现提交给治理入口，由治理入口决定是否暂停或阻断。

探针默认不修改业务状态、不执行真实动作、不替代审批，也不把缺失数据推测成事实。

---

## 2. 设计目标

### 2.1 核心目标

1. 让任务、状态、证据、权限、责任和结果能够在同一条运行链路中关联。
2. 发现工作流执行数据缺失，并通过补全请求向执行流程索取原始记录。
3. 区分“没有发生”“没有采集”“采集失败”和“不可获得”。
4. 支持链式、路由、并行、编排、循环和层级拓扑。
5. 支持资料研究、故障排查、业务办理及其他可扩展场景。
6. 让每个异常发现带有事实依据、影响范围、严重程度和建议处理方式。
7. 不依赖特定模型、工具、平台、接口或部署形态。
8. 以追加事件和版本引用为基础，支持审计、恢复和复盘。

### 2.2 非目标

本探针不负责：

- 替代执行器完成业务任务；
- 替代审批人作出高风险决定；
- 直接改变任务目标、计划或权限；
- 收集模型的隐性思维过程；
- 通过日志数量证明系统安全；
- 为了提高完整率而编造缺失字段；
- 将所有低价值内部动作都记录成高成本事件；
- 用单一全局阈值覆盖所有业务场景。

## 3. 与 Hanerss Skill Framework 的对应关系

### 3.1 认知基座映射

| 认知项 | 探针职责 |
|---|---|
| 感知 | 接收事件、日志、快照、证据和外部系统结果 |
| 记忆 | 保存运行历史、事件链、状态版本、证据引用和异常发现 |
| 推理 | 关联事件、计算指标、识别缺口和判断异常条件 |
| 反思 | 比较计划与实际、输入与输出、动作与结果、评审与修订 |
| 协作 | 关联分支、角色、委派、聚合和交接责任 |
| 治理 | 检查审批、权限、范围、额度、阻断策略和审计要求 |

探针通常不直接承担行动认知；只有在被授权发送通知、补全请求或治理建议时，才产生受限动作。

### 3.2 拓扑基座映射

| 拓扑项 | 主要观测重点 |
|---|---|
| 链式 | 前后步骤顺序、版本传递、输入输出完整性 |
| 路由 | 候选路径、选择依据、未选路径、重新路由条件 |
| 并行 | 分支启动、分支完成、重复、冲突、聚合和缺失 |
| 编排 | 节点依赖、就绪条件、等待状态、调度和恢复 |
| 循环 | 每轮目标、信息增益、重试差异、预算和退出条件 |
| 层级 | 委派边界、子任务责任、父目标覆盖、结果回收 |

### 3.3 工程模式与 Skill 的关系

本探针可以作为独立工程模式登记，也可以包装成可复用 Skill。针对不同业务，只需要更换：

- 事件适配器；
- 必需字段；
- 探针组合；
- 阈值与严重度；
- 补全来源；
- 治理联动策略；
- 报告模板。

## 4. 运行方式

## 4.1 独立离线模式

适用于已经结束或中断的工作流。

输入可以是：

- 日志文件；
- 任务记录；
- 工具调用记录；
- 数据库快照；
- 评审记录；
- 审批记录；
- 业务系统查询结果；
- 工件目录。

探针完成以下工作：

1. 识别并关联任务、运行、节点和分支；
2. 重建时间线和状态迁移；
3. 标记缺失字段和低置信关联；
4. 运行探针规则；
5. 生成一次性复盘报告。

独立离线模式可以发现问题，但无法要求已经结束的执行流程实时补数，除非原始系统仍提供查询接口。

## 4.2 独立在线模式

适用于没有使用标准执行流程，但能够输出日志、事件或快照的系统。

探针通过适配器持续接收数据，建立自己的只读运行视图。必要时可以主动查询状态，但不写回业务系统。

## 4.3 交互增强模式

与《模式组合_执行流程_v0.1.md》共同运行时：

1. 执行流程发送标准事件；
2. 探针实时检查链路完整性；
3. 探针发现缺口后发送数据补全请求；
4. 执行流程返回原始记录、引用或不可获得原因；
5. 探针生成异常发现；
6. 执行流程、评审者或治理入口决定是否修订、暂停、重新审批或继续。

## 4.4 治理联动模式

只有显式配置治理策略时，探针才能把某些异常提升为阻断候选。例如：

- 真实动作没有有效审批；
- 实际目标对象超出批准范围；
- 动作版本与审批版本不一致；
- 关键分支缺失却准备宣告完成；
- 循环已超过硬预算；
- 外部结果未核验却准备发布。

即使如此，探针也只提交“阻断请求”，由治理入口执行最终控制。

## 5. 观察模型

探针围绕八条观察线工作。

| 观察线 | 核心问题 |
|---|---|
| 任务线 | 原目标、交付物和验收条件是否被完整执行 |
| 状态线 | 任务当前在哪里，为什么等待，失败后从哪里继续 |
| 证据线 | 关键结论、决策和评审能否回到原始材料 |
| 决策线 | 为什么选择这条路径，什么结果会让它改变 |
| 动作线 | 实际调用了什么，影响了什么，结果是什么 |
| 权限线 | 谁允许了哪一个版本、对象、范围、额度和时段 |
| 责任线 | 谁负责当前节点、交接后由谁继续、问题由谁关闭 |
| 结果线 | 最终业务结果是否满足验收，而不只是技术调用成功 |

这八条线共同构成可追责的运行史。

## 6. 数据来源与置信等级

### 6.1 数据来源

探针可以从以下来源采集数据：

1. 标准工作流事件；
2. 状态存储快照；
3. 计划和任务图；
4. 工具调用与响应；
5. 原始文档、日志和测试结果；
6. 工件与版本库；
7. 审批、权限和策略系统；
8. 消息、通知和交接记录；
9. 最终业务系统查询；
10. 人工补充说明。

### 6.2 置信等级

| 等级 | 定义 |
|---|---|
| 高 | 来自权威源，具有稳定标识、版本和完整原始记录 |
| 中 | 可关联到权威源，但部分字段由适配器推导 |
| 低 | 仅从文本日志或时间相近关系推断，缺少稳定标识 |
| 未知 | 数据不足，无法可靠判断 |

探针报告必须区分事实、计算结果和推断。低置信关联不得用于自动阻断高风险动作，除非有其他治理证据支持。

## 7. 标识与关联规则

## 7.1 最小标识集合

```yaml
trace_id: 端到端链路标识
run_id: 一次运行标识
task_id: 任务标识
plan_id: 计划标识
plan_version: 计划版本
node_id: 当前节点
parent_node_id: 父节点
branch_id: 并行或层级分支
attempt_id: 节点的一次尝试
actor_id: 执行主体
artifact_id: 工件标识
artifact_version: 工件版本
evidence_id: 证据标识
decision_id: 决策标识
action_id: 动作标识
approval_id: 审批标识
review_id: 评审标识
handoff_id: 交接标识
```

### 7.2 关联原则

1. 同一任务的恢复运行保留 `task_id`，产生新的 `run_id`。
2. 同一节点重试保留 `node_id`，产生新的 `attempt_id`。
3. 计划修改产生新的 `plan_version`。
4. 工件修改产生新的 `artifact_version`。
5. 审批必须绑定具体 `action_id`、目标对象和输入版本。
6. 评审必须绑定具体工件版本。
7. 分支事件必须带 `branch_id`，聚合事件必须列出被回收分支。
8. 交接必须同时关联交付版本和接收责任。

### 7.3 缺少稳定标识时

适配器可以生成临时标识，但必须：

- 标注生成规则；
- 标注置信等级；
- 保留原始记录定位；
- 避免把时间相近但无因果关系的事件强行合并；
- 在补充到真实标识后建立映射，而不是覆盖历史记录。

## 8. 统一事件信封

每条事件采用追加写入，不直接修改历史事件。纠错通过新事件表达。

### 8.1 必需字段


### 8.2 条件字段


### 8.3 载荷要求

载荷应记录可审计的业务事实，例如：

- 输入和输出引用；
- 证据来源；
- 决策摘要；
- 候选路径；
- 选择依据；
- 权限检查结果；
- 真实动作参数摘要；
- 工具响应；
- 验收结论；
- 错误分类。

不得要求记录模型完整的隐性思维过程。需要的是可以复核的结论、依据、规则和结果，而不是私有推理草稿。

## 11. 核心探针目录

本版本提供十四个通用探针。不同场景可以只启用其中一部分。

---

## 11.1 任务边界与交付完整性探针

**探针标识：** `PROBE_TASK_001`

### 观测目标

确认执行结果仍对应原任务，必需交付物没有被静默遗漏。

### 依赖数据

- 任务目标；
- 必需交付物；
- 验收条件；
- 任务边界更新事件；
- 最终输出；
- 完成事件。

### 计算项

```text
交付覆盖率 = 已满足的必需交付项数量 ÷ 必需交付项总数
验收覆盖率 = 已有明确结论的强制验收项数量 ÷ 强制验收项总数
未说明缺口数 = 缺失且未给出原因的必需项数量
```

### 异常条件

- 完成事件早于全部强制验收项；
- 任务原要求三个对象，最终只包含两个且未说明；
- 计划修改后任务范围扩大，但任务契约未更新；
- 输出格式合法，但没有回答任务核心问题。

### 输出

- 缺失交付物；
- 受影响验收项；
- 建议返回节点；
- 是否应阻止完成声明。

---

## 11.2 链路、分支与聚合完整性探针

**探针标识：** `PROBE_TOPOLOGY_001`

### 观测目标

确认链式、并行、层级和聚合关系完整，所有必需分支都被正确回收。

### 依赖数据

- 计划图；
- 父子节点关系；
- 分支启动、完成、取消和聚合事件；
- 聚合输入清单；
- 节点完成条件。

### 计算项

```text
分支回收率 = 已形成可聚合结果的必需分支数量 ÷ 已启动的必需分支数量
孤立节点数 = 无有效父节点、无入口或无出口的节点数量
聚合缺口数 = 聚合清单中缺少的必需分支数量
重复分支率 = 语义上重复且未产生新增价值的分支数量 ÷ 总分支数量
```

### 异常条件

- 分支未完成却被聚合器视为完成；
- 子任务完成但结果没有回到父任务；
- 取消分支没有原因；
- 多个分支输出口径、时间或版本不一致；
- 聚合结果没有列出输入分支。

### 输出

- 缺失、重复或冲突分支；
- 聚合完整性；
- 建议补跑、取消或人工确认的分支。

## 11.3 状态一致性与可恢复性探针

**探针标识：** `PROBE_STATE_001`

### 观测目标

确认任务状态、计划状态、节点状态和外部效果一致，并能够从中断处恢复。

### 依赖数据

- 状态迁移事件；
- 状态版本；
- 节点状态；
- 外部动作结果；
- 恢复点；
- 任务暂停和恢复记录。

### 计算项

```text
状态一致率 = 一致的状态读取次数 ÷ 总状态读取次数
版本冲突数 = 写入时发现读取版本已过期的次数
可恢复节点率 = 具有有效恢复点的长时节点数量 ÷ 长时节点总数
重复执行风险数 = 恢复后可能再次产生相同外部效果的节点数量
```

### 异常条件

- 任务标记完成，但存在运行中节点；
- 动作已经生效，状态仍显示未执行；
- 恢复后重复调用不可幂等动作；
- 计划版本变化后仍使用旧状态继续；
- 多个存储各自维护冲突状态。

### 输出

- 冲突状态和可信来源；
- 需要冻结的节点；
- 恢复建议；
- 可能重复产生的外部效果。

## 11.4 依赖满足与非法跨步探针

**探针标识：** `PROBE_DEPENDENCY_001`

### 观测目标

确认节点只在依赖、权限、预算和前置条件满足后执行。

### 依赖数据

- 计划依赖；
- 节点就绪事件；
- 节点开始事件；
- 前置条件检查；
- 权限和审批状态；
- 预算状态。

### 计算项

```text
依赖违规次数 = 未满足必需依赖却启动节点的次数
就绪误判率 = 被标记就绪但实际缺少条件的节点数量 ÷ 就绪节点数量
跨步次数 = 跳过必需节点直接执行后续动作的次数
```

### 异常条件

- 备份未成功就开始导入；
- 原因未确认就开始大范围修改；
- 审批未通过就调用写入工具；
- 流程轮到该步骤，但当前状态已发生变化；
- 计划依赖仅存在于提示词，实际调度器未检查。

### 输出

- 缺失依赖；
- 非法启动节点；
- 需要回退的位置；
- 是否应暂停真实动作。

## 11.5 证据覆盖与原文回溯探针

**探针标识：** `PROBE_EVIDENCE_001`

### 观测目标

确认关键结论、决策、评审和动作依据能够回到有效原始材料。

### 依赖数据

- 关键结论清单；
- 证据引用；
- 原文位置；
- 来源版本和时间；
- 证据失效或冲突事件。

### 计算项

```text
证据覆盖率 = 有有效证据支持的关键结论数量 ÷ 关键结论总数
原文回溯率 = 可定位到原始片段的关键结论数量 ÷ 关键结论总数
失效证据占比 = 已失效证据引用数量 ÷ 总证据引用数量
单源依赖率 = 仅由单一来源支持的高风险结论数量 ÷ 高风险结论数量
```

### 异常条件

- 关键结论只引用摘要，不引用原文；
- 原文位置无法访问或版本不明；
- 来源已经失效但下游结论未重新检查；
- 评审者与生成者只能看到同一份压缩摘要；
- 动作依据来自低置信推断。

### 输出

- 无证据结论；
- 不可回溯结论；
- 失效来源；
- 建议补取的原始材料。

## 11.6 压缩损失与例外保留探针

**探针标识：** `PROBE_COMPRESSION_001`

### 观测目标

发现摘要、压缩或聚合过程丢失例外、否定、适用范围、生效时间和条件限定。

### 依赖数据

- 原始材料；
- 摘要或压缩结果；
- 关键实体、日期、数值、否定词和例外项；
- 下游生成结果；
- 评审问题。

### 计算项

```text
例外保留率 = 摘要中保留的关键例外数量 ÷ 原文关键例外总数
限定条件保留率 = 摘要中保留的适用范围、日期和条件数量 ÷ 原文对应数量
关键事实差异数 = 原文与摘要在对象、数值、日期、否定和条件上的差异数量
```

### 异常条件

- 原文写“定制商品除外”，摘要只保留“支持七天退货”；
- 原文有生效时间，摘要未保留；
- 原文仅适用于部分对象，摘要扩大为全部对象；
- 聚合时用统一结论覆盖了地区差异；
- 下游输出的确定程度高于证据。

### 输出

- 被遗漏的例外和限定条件；
- 受影响的结论、评审和动作；
- 建议重新压缩或直接回取原文。

## 11.7 假设验证与调查转向探针

**探针标识：** `PROBE_HYPOTHESIS_001`

### 观测目标

确认调查步骤能够区分候选解释，并在证据否定原假设时及时转向。

### 依赖数据

- 候选假设；
- 检查选择；
- 预期区分结果；
- 实际结果；
- 假设更新；
- 后续路由。

### 计算项

```text
有效检查率 = 能区分至少两个候选解释的检查数量 ÷ 总检查数量
假设更新及时率 = 否定证据后在下一步更新假设的次数 ÷ 否定证据次数
无关检查率 = 与当前候选原因无明显关系的检查数量 ÷ 总检查数量
```

### 异常条件

- 检查结果否定超时假设，下一步仍继续增大超时；
- 同一假设被多次否定仍未更新；
- 检查只收集更多数据，却不说明要区分什么；
- 调查已经足够明确，但仍继续无目的搜索；
- 原因未确认就进入高影响修复。

### 输出

- 已被否定但仍在使用的假设；
- 低区分度检查；
- 推荐返回调查或进入规划的判断。

---

## 11.8 循环、重试与预算探针

**探针标识：** `PROBE_LOOP_001`

### 观测目标

限制无效循环、重复重试和嵌套预算膨胀。

### 依赖数据

- 循环标识；
- 每轮目标；
- 输入和输出摘要哈希；
- 修改差异；
- 新增证据；
- 尝试次数；
- 时间、费用和工具调用；
- 任务级及局部预算。

### 计算项

```text
预算消耗率 = 已消耗预算 ÷ 可用预算
重复尝试率 = 输入、参数和动作近似相同的尝试数量 ÷ 总尝试数量
信息增益停滞轮数 = 连续没有新增证据、状态变化或有效差异的轮数
重试收益率 = 成功解决局部问题的重试数量 ÷ 总重试数量
嵌套放大倍数 = 实际总尝试数量 ÷ 外层声明的最大尝试数量
```

### 异常条件

- 连续多轮输入、参数和输出基本相同；
- 内层循环绕过任务级预算；
- 重试没有新增修复差异；
- 等待审批被当作失败反复重试；
- 自愈循环试图绕过人工审批；
- 超预算后仍继续调用工具。

### 输出

- 当前预算和预测耗尽点；
- 无进展循环；
- 建议停止、返回调查、重新规划或人工接管。

## 11.9 动作前置条件与结果核验探针

**探针标识：** `PROBE_ACTION_001`

### 观测目标

确认真实动作在正确条件下执行，并通过独立查询证明业务结果。

### 依赖数据

- 动作提议；
- 目标对象；
- 输入版本；
- 前置条件检查；
- 工具调用和响应；
- 外部效果；
- 调用后查询；
- 补偿或撤销记录。

### 计算项

```text
前置检查覆盖率 = 已完成的必需前置检查数量 ÷ 必需前置检查总数
后置核验率 = 已进行独立结果核验的真实动作数量 ÷ 真实动作总数
接口成功但业务失败数 = 工具返回成功但业务验收失败的动作数量
可补偿覆盖率 = 具有明确补偿路径的高风险动作数量 ÷ 高风险动作数量
```

### 异常条件

- 真实动作前未检查当前状态；
- 工具返回成功后没有查询目标系统；
- 查询结果与预期不一致却仍标记完成；
- 部分成功没有记录实际影响对象；
- 高风险动作没有补偿或人工处理方案。

### 输出

- 缺失的前后检查；
- 技术成功但业务失败的动作；
- 需要补偿、复核或重新执行的对象。

## 11.10 审批、权限与爆炸半径探针

**探针标识：** `PROBE_GOVERNANCE_001`

### 观测目标

确认审批只对指定动作、对象、版本、范围、额度和时段有效，实际影响没有越界。

### 依赖数据

- 审批请求和决定；
- 动作标识；
- 目标对象；
- 输入版本；
- 允许范围；
- 数量、金额、地区、时间等额度；
- 实际影响清单；
- 权限检查。

### 计算项

```text
审批匹配率 = 与审批对象、版本和范围完全匹配的动作数量 ÷ 需审批动作数量
未授权动作数 = 没有有效审批或权限的真实动作数量
实际影响比 = 实际影响对象数量 ÷ 批准对象上限
范围越界数 = 实际影响但未被批准的对象数量
过期审批使用数 = 使用已过期审批的动作数量
```

### 异常条件

- 计划变化后沿用旧审批；
- 审批一个部门，实际修改多个部门；
- 审批某版配置，执行时使用另一版；
- 权限允许调用接口，但业务范围不允许当前对象；
- 实际影响超过数量、金额、地域或时长上限。

### 输出

- 失配字段；
- 越界对象；
- 需要停止、补偿或重新审批的动作；
- 当前影响范围与批准范围对比。

---

## 11.11 评审覆盖与问题闭环探针

**探针标识：** `PROBE_REVIEW_001`

### 观测目标

确认评审对象版本正确、评审材料充分、发现的问题得到处理，并且评审真正约束放行。

### 依赖数据

- 评审请求；
- 工件版本；
- 评审标准；
- 原始证据；
- 评审问题；
- 修订版本；
- 问题关闭记录；
- 发布或放行事件。

### 计算项

```text
评审覆盖率 = 已被评审的强制对象数量 ÷ 强制评审对象总数
问题闭环率 = 已验证关闭的问题数量 ÷ 评审问题总数
旧版评审沿用数 = 工件变化后仍使用旧评审结论的次数
证据独立率 = 能独立回取原始证据的评审数量 ÷ 评审总数
```

### 异常条件

- 评审只看摘要，无法访问原文；
- 工件修订后没有重新核对受影响部分；
- 评审提出严重问题但发布仍继续；
- 问题被标记关闭，却没有修订或豁免依据；
- 生成者和评审者共享同一未经核对的错误材料。

### 输出

- 未覆盖对象；
- 未闭环问题；
- 失效评审结论；
- 是否应阻止放行。

## 11.12 交接责任与版本完整性探针

**探针标识：** `PROBE_HANDOFF_001`

### 观测目标

确认工作在角色、权限或上下文变化时，状态、责任、证据和正确工件版本一起抵达下一方。

### 依赖数据

- 交接包；
- 交付版本；
- 接收者；
- 已完成事项；
- 未完成事项；
- 证据引用；
- 恢复点；
- 接收确认；
- 责任转移事件。

### 计算项

```text
交接完整率 = 已填写的必需交接字段数量 ÷ 必需字段总数
接收确认率 = 已明确接收的交接数量 ÷ 交接总数
错误版本交接数 = 接收者使用的版本与交接版本不一致的次数
责任悬空数 = 交接后没有明确责任人的事项数量
```

### 异常条件

- 只发送结论，没有证据和当前状态；
- 接收者拿到旧版工件；
- 未说明剩余责任和失败返回点；
- 交接已创建但无人接收；
- 交接后原执行者和接收者都认为对方负责。

### 输出

- 缺失字段；
- 版本不一致；
- 悬空责任；
- 需要退回或重新交接的事项。

## 11.13 终态验收与完成真实性探针

**探针标识：** `PROBE_ACCEPTANCE_001`

### 观测目标

防止把“流程走完”“工具成功”或“有一个结果”误判为业务完成。

### 依赖数据

- 验收条件；
- 任务、证据、状态、权限和结果检查；
- 最终业务查询；
- 未解决问题；
- 完成事件。

### 计算项

```text
强制验收通过率 = 已通过的强制验收项数量 ÷ 强制验收项总数
完成声明真实性 = 完成声明与实际验收结果是否一致
未解决高风险问题数 = 完成时仍未关闭的高风险问题数量
```

### 异常条件

- 完成事件存在，但强制验收项未全部通过；
- 外部系统实际状态与交付物不一致；
- 关键证据仍缺失；
- 存在未说明的失败分支；
- 存在未补偿的越权或部分成功动作。

### 输出

- 不满足的完成条件；
- 虚假完成或过早完成发现；
- 建议退回节点或人工确认项。

## 11.14 成本、时延与人工接管价值探针

**探针标识：** `PROBE_EFFICIENCY_001`

### 观测目标

判断新增模式、评审和治理层是否带来足够收益，而不是只让架构更复杂。

### 依赖数据

- 端到端时延；
- 模型、工具和人工成本；
- 错误率；
- 返工；
- 人工接管次数和时点；
- 有无该组件的对照运行；
- 最终业务质量。

### 计算项

```text
单位成功成本 = 总成本 ÷ 通过验收的任务数量
返工率 = 进入修订或重做的任务数量 ÷ 总任务数量
人工接管率 = 需要人工接管的任务数量 ÷ 总任务数量
早期接管收益 = 早期停止避免的后续成本和风险
组件净收益 = 组件带来的质量或风险改善减去时延、费用和维护成本
```

### 异常条件

- 评审几乎不发现问题，却显著增加即时任务时延；
- 多 Agent 分支重复研究，成本增加但结论无新增；
- 长任务没有进度记录，导致中断后重复调查；
- 治理层阻断大量低风险动作，但没有降低实际事故；
- 某组件只提高局部指标，却降低端到端成功率。

### 输出

- 建议保留、调整、按风险启用或撤销的组件；
- 需要对照实验的环节；
- 成本和质量之间的主要取舍。

## 12. 数据补全机制

工作流可观测性探针不仅报告缺失，还可以向执行流程发出结构化补全请求。

## 12.1 缺口分类

| 缺口类型 | 示例 |
|---|---|
| 标识缺口 | 工具调用没有 task_id 或 node_id |
| 状态缺口 | 有动作记录但没有状态迁移 |
| 证据缺口 | 结论没有原文引用 |
| 决策缺口 | 有路由结果但没有选择依据 |
| 权限缺口 | 有写入动作但没有审批引用 |
| 责任缺口 | 有交接但没有接收者 |
| 结果缺口 | 接口成功但没有业务查询 |
| 版本缺口 | 评审、审批或动作未绑定工件版本 |

## 12.2 补全请求结构

```yaml
请求标识: DATA_REQUEST_0001
探针标识: PROBE_EVIDENCE_001
trace_id: TRACE_0001
run_id: RUN_0001
task_id: TASK_0001
关联对象:
  类型: 关键结论
  标识: CLAIM_0004
缺失字段:
  - 原文位置
  - 来源版本
请求原因: 当前结论只有摘要引用，无法独立核对
候选来源:
  - 原始检索结果
  - 证据台账
  - 知识库访问记录
严重程度: 高
期望响应:
  - 原始证据引用
  - 不可获得原因
禁止处理:
  - 不得根据摘要反向编造原文
```

## 12.3 补全响应结构

```yaml
响应标识: DATA_RESPONSE_0001
请求标识: DATA_REQUEST_0001
响应状态: 已补全 | 部分补全 | 不可获得 | 无权访问
补充数据引用:
  - EVIDENCE_0042
来源: 证据台账
置信等级: 高
不可获得原因: null
是否改变业务状态: false
```

## 12.4 补全规则

1. 优先返回原始数据或稳定引用，不返回未经标注的二次推测。
2. 不可获得时必须明确原因，不用空值假装“没有问题”。
3. 补全响应不自动改变任务结论。
4. 新证据与旧结论冲突时，应触发重新评审或重新规划。
5. 补全请求必须受原任务权限和敏感数据策略限制。
6. 探针应记录补全前后判断差异。
7. 数据完整率不得通过伪造默认值提高。

## 13. 与执行流程的交互协议

## 13.1 标准交互

```text
执行流程：发送任务、计划、节点、证据、动作、审批和验收事件
探针：关联事件并运行探针
探针：发现缺口后发送数据补全请求
执行流程：返回原始引用、状态快照或不可获得原因
探针：更新异常结论和严重程度
探针：发送异常发现或阻断请求
执行流程或治理入口：决定继续、修订、等待、重新审批、补偿或终止
执行流程：发送处理结果
探针：关闭、保留或升级异常
```

## 13.2 异常发现结构

```yaml
发现标识: FINDING_0001
探针标识: PROBE_GOVERNANCE_001
严重程度: 严重
状态: 待确认
关联任务: TASK_0001
关联动作: ACTION_0005
事实:
  - 审批对象为部门甲
  - 实际动作目标包含部门乙
依据:
  - APPROVAL_0002
  - ACTION_EVENT_0098
影响:
  - 可能修改未获批准的部门配置
建议:
  - 暂停动作
  - 查询实际影响
  - 必要时补偿并重新审批
是否请求阻断: true
置信等级: 高
```

## 13.3 处理结果结构

```yaml
处理标识: FINDING_RESOLUTION_0001
发现标识: FINDING_0001
处理决定: 已阻断 | 已修订 | 已豁免 | 误报 | 待人工
决定主体: GOVERNANCE_GATE_01
依据: 待填写
后续动作:
  - 查询实际影响
  - 重新审批
状态变化: 运行中 -> 等待审批
```

## 13.4 软提示和硬阻断

| 类型 | 默认行为 | 适用示例 |
|---|---|---|
| 信息 | 记录在报告中 | 低风险字段缺失 |
| 警告 | 通知执行者，不阻断 | 预算接近上限 |
| 高风险 | 请求复核或暂停 | 关键证据不可回溯 |
| 严重 | 向治理入口发起阻断请求 | 未授权写入、范围越界 |

阈值必须按业务风险配置，不使用统一固定值。

## 14. 不同拓扑的探针布置

## 14.1 链式拓扑

必须观察：

- 步骤顺序；
- 上一步输出版本；
- 下一步实际读取内容；
- 缺失、过期或格式合法但语义不足的输入；
- 失败返回位置。

优先启用：依赖探针、证据探针、动作探针、验收探针。

## 14.2 路由拓扑

必须观察：

- 候选路径；
- 路由依据；
- 当前证据；
- 未选路径；
- 重新路由条件；
- 路由后是否扩大权限或范围。

优先启用：任务探针、假设探针、治理探针。

## 14.3 并行拓扑

必须观察：

- 分支边界；
- 分支输入和口径；
- 启动、完成、取消；
- 重复劳动；
- 聚合完整性；
- 冲突处理。

优先启用：拓扑探针、证据探针、成本探针、交接探针。

## 14.4 编排拓扑

必须观察：

- 计划版本；
- 节点依赖；
- 就绪条件；
- 调度决定；
- 等待原因；
- 状态一致性；
- 恢复点。

优先启用：状态探针、依赖探针、动作探针、治理探针。

## 14.5 循环拓扑

必须观察：

- 每轮目标；
- 与上一轮的差异；
- 新证据；
- 信息增益；
- 尝试预算；
- 退出原因。

优先启用：假设探针、循环探针、成本探针。

## 14.6 层级拓扑

必须观察：

- 父目标；
- 委派边界；
- 子任务完成条件；
- 子任务权限；
- 结果回收；
- 父目标覆盖；
- 责任交接。

优先启用：任务探针、拓扑探针、交接探针、治理探针。

## 15. 场景探针组合

## 15.1 资料研究

### 建议启用

- 任务边界与交付完整性探针；
- 链路、分支与聚合完整性探针；
- 证据覆盖与原文回溯探针；
- 压缩损失与例外保留探针；
- 评审覆盖与问题闭环探针；
- 终态验收探针；
- 成本探针。

### 重点数据

- 每个调查方向的问题清单；
- 原始材料位置；
- 来源版本和生效日期；
- 摘要与原文差异；
- 缺失分支；
- 冲突证据；
- 评审回取原文记录。

### 典型异常

- 三个地区只返回两个；
- 摘要漏掉例外；
- 评审只看摘要；
- 不同分支使用不同时间口径；
- 缺少出处却输出确定性结论。

---

## 15.2 故障排查

### 建议启用

- 状态一致性与可恢复性探针；
- 依赖满足与非法跨步探针；
- 假设验证与调查转向探针；
- 循环、重试与预算探针；
- 动作前置条件与结果核验探针；
- 评审覆盖与问题闭环探针；
- 终态验收探针。

### 重点数据

- 候选原因；
- 每次检查要区分的假设；
- 日志和测试结果；
- 已排除原因；
- 修改差异；
- 回归测试；
- 原行为约束；
- 失败后返回调查还是局部自愈。

### 典型异常

- 假设被推翻仍继续修改同一方向；
- 测试失败后无差异重试；
- 删除权限检查换取测试通过；
- 外层与内层循环预算相乘失控；
- 修改完成但没有回归原要求。

---

## 15.3 业务办理

### 建议启用

- 任务边界与交付完整性探针；
- 状态一致性与可恢复性探针；
- 依赖满足与非法跨步探针；
- 动作前置条件与结果核验探针；
- 审批、权限与爆炸半径探针；
- 交接责任与版本完整性探针；
- 终态验收探针。

### 重点数据

- 业务差异；
- 目标对象；
- 方案和配置版本；
- 备份状态；
- 审批对象、版本和范围；
- 实际影响清单；
- 导入后查询；
- 补偿和交接记录。

### 典型异常

- 备份未完成就导入；
- 计划变化后沿用旧审批；
- 只批准一个部门却影响多个部门；
- 接口成功但目标系统仍是旧配置；
- 等待审批被自愈循环反复绕过。

---

## 15.4 简单固定流程

简单流程不需要启用全部探针。建议只保留：

- 任务完整性；
- 动作结果核验；
- 必要的治理检查；
- 终态验收。

避免探针成本高于任务本身。

## 17. 存储、顺序与一致性

### 17.1 事件存储

建议采用追加写入。历史事件不直接覆盖，纠错以新事件表达。

### 17.2 顺序处理

并行系统可能出现时钟偏差和乱序。排序优先级建议为：

1. 来源内单调序号；
2. 因果父子关系；
3. 状态版本；
4. 发生时间；
5. 接收时间。

探针不得仅凭接收时间推断业务顺序。

### 17.3 幂等

事件应具有稳定事件标识。重复接收时只更新接收状态，不重复计算业务动作。

### 17.4 迟到事件

迟到事件可能改变既有判断。探针应：

- 保留旧判断；
- 生成修订判断；
- 标记受影响报告；
- 必要时重新打开已关闭异常。

### 17.5 状态重建

探针状态是只读重建视图，不替代执行流程的权威状态。二者冲突时应标记冲突并请求核对，而不是直接覆盖。

---

## 18. 安全、隐私与数据最小化

1. 只采集完成可追溯和治理所必需的数据。
2. 敏感内容优先保存引用、摘要哈希或脱敏片段。
3. 原始证据的访问权限不得因接入探针而扩大。
4. 补全请求必须经过同一任务的权限检查。
5. 审批、身份、金额、个人信息和密钥应分级保护。
6. 不采集模型完整隐性思维过程；记录决策摘要、候选方案、采用依据和结果即可。
7. 工具参数中的秘密字段必须遮蔽。
8. 报告对不同角色显示不同粒度。
9. 数据保留期限按业务、法规和审计要求配置。
10. 删除或归档时保留必要的引用关系和删除证明。

---

## 19. 采样策略

不是所有事件都需要同等采集强度。

### 19.1 必须全量记录

- 任务边界变化；
- 计划版本变化；
- 真实外部动作；
- 审批和权限决定；
- 高风险证据变化；
- 交接；
- 强制验收；
- 阻断、补偿和人工接管。

### 19.2 可以采样

- 低风险只读查询；
- 高频但结果同质的内部状态读取；
- 不影响决策的调试信息；
- 已有聚合计数的重复技术事件。

### 19.3 采样要求

- 采样策略必须可查询；
- 报告必须说明哪些数据被采样；
- 缺少事件时不能直接推断“没有发生”；
- 高风险动作不得因成本原因采样丢失；
- 采样变化应产生配置事件。

---

## 20. 阈值与严重程度配置

阈值应由场景、风险等级和任务规模决定。

### 示例

| 场景 | 指标 | 建议处理 |
|---|---|---|
| 资料研究 | 原文回溯率低于强制要求 | 阻止发布或要求补证 |
| 故障排查 | 连续三轮无信息增益 | 停止局部循环并返回调查或转人工 |
| 业务办理 | 范围越界数大于零 | 立即发起阻断请求 |
| 长任务 | 可恢复节点率不足 | 在下一次中断前补建恢复点 |
| 即时咨询 | 评审增加时延但几乎无问题发现 | 降级为抽样评审或撤销 |

具体阈值由业务配置，本文件不规定统一数值。

## 21. 最小可用实现

一个最小探针系统至少包含：

1. 数据源适配器；
2. 事件规范化器；
3. 标识关联器；
4. 状态和拓扑重建器；
5. 探针规则引擎；
6. 指标计算器；
7. 数据缺口管理器；
8. 报告生成器；
9. 可选反馈适配器；
10. 权限和脱敏层。

这些模块可以在一个进程中实现，也可以拆分部署。探针拓扑不应由微服务数量决定。

## 23. 评估用例

### 用例一：缺失分支

三个调查分支只完成两个，聚合器准备生成最终报告。

预期：拓扑探针发现分支回收率不足；任务探针阻止完成声明或要求明确缺失原因。

### 用例二：摘要遗漏例外

原文包含例外条款，摘要和报告均未保留。

预期：压缩探针发现关键差异；证据探针给出原文引用；评审探针重新打开相关问题。

### 用例三：非法跨步

备份节点未完成，导入节点已经启动。

预期：依赖探针报告跨步；动作探针要求暂停；治理入口决定是否阻断。

### 用例四：假设未转向

日志否定超时原因，但后续仍连续修改超时参数。

预期：假设探针标记否定证据未生效；循环探针识别低信息增益重试。

### 用例五：嵌套循环失控

外层三轮，内层五轮，总尝试数不断增长。

预期：循环探针按任务级预算计算真实剩余额度，并在达到硬上限时发出阻断请求。

### 用例六：审批失配

审批绑定配置第三版，执行使用第四版。

预期：治理探针发现版本不匹配，要求重新审批。

### 用例七：范围越界

批准一个部门，实际写入两个部门。

预期：治理探针列出越界对象；动作探针请求查询实际影响并准备补偿。

### 用例八：技术成功、业务失败

接口返回成功，但目标系统查询仍显示旧配置。

预期：动作探针报告业务核验失败；验收探针拒绝完成。

### 用例九：错误版本交接

接收者使用旧版工件继续核对。

预期：交接探针发现版本不一致并标记后续结论受影响。

### 用例十：无标准事件的旧系统

系统只提供文本日志。

预期：适配器生成临时标识，所有关联标注低或中置信；报告说明无法自动阻断的限制。

### 用例十一：数据不可获得

探针请求原文位置，但原始材料已删除。

预期：补全响应为“不可获得”，不生成虚假引用；相关结论保持未验证状态。

### 用例十二：评审层不值得保留

大量低风险任务增加评审后时延显著上升，但错误率没有改善。

预期：成本探针建议改为按风险启用、抽样评审或撤销该层。

## 24. 常见反模式

1. 只有组件日志，没有任务、运行和节点关联标识。
2. 只看模型和工具是否报错，不看业务结果是否达成。
3. 将缺失数据按零处理，混淆“未发生”和“未采集”。
4. 事件没有版本，无法判断评审、审批和动作针对哪一版工件。
5. 并行分支只统计数量，不检查是否全部回收和可比较。
6. 只统计重试次数，不检查每轮是否有新增信息。
7. 探针发现范围越界后直接修改业务状态，越过治理入口。
8. 为提高证据覆盖率而从摘要反向生成原文。
9. 保存完整提示词和隐性思维过程，造成不必要的隐私与安全风险。
10. 所有任务都启用全量高成本探针，没有风险分级。
11. 探针报告只有红黄绿颜色，没有事实、证据和建议处理点。
12. 将探针自己的重建状态当作业务权威状态。
13. 采样后仍把缺少事件解释为“没有发生”。
14. 阈值写死在代码中，无法按场景、风险和规模调整。
15. 只评价单个组件指标，不评价端到端成功、时延、费用和人工负担。

## 25. 完成定义

一次探针分析只有在以下条件满足时才可视为完成：

```text
数据来源和采样范围已说明
且事件已按任务、运行、节点和版本完成关联
且缺失数据被区分为未采集、不可获得或不适用
且启用的探针均产生明确结论或未知状态
且每个异常发现带有事实、依据、影响和置信等级
且需要补全的数据已请求或说明无法补全
且需要治理处理的发现已提交到正确责任方
且最终报告能够重建任务、状态、证据、权限、责任和结果关系
```

探针分析完成不代表业务任务完成。业务完成仍由执行流程的验收条件决定。
