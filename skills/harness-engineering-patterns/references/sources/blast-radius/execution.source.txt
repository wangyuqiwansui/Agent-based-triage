# 1. 文档定位

本文件把“爆炸半径控制”工程模式执行化，形成一套可独立运行、可复用、可扩展的高风险动作控制流程。

它解决的不是“动作是否获批”，而是动作获批后，实际执行最多能够触及哪些资源、产生多少外部效果、持续多长时间，以及错误如何停止、对账和收敛。

本执行流程可采用两种运行方式：

1. **独立运行**：执行流程自行完成边界解析、额度预留、许可签发、外部效果提交、状态记账、未知结果对账和运行关闭，不依赖工作流可观测性探针。
2. **交互运行**：执行流程持续输出标准事件，工作流可观测性探针旁路采集、校验并补全数据；探针可返回数据补丁、告警、停止建议和对账请求，但不能自行扩大执行边界。

# 2. 所属基座

## 2.1 认知基座

主认知为 `COG_GOVERNANCE`。模式直接约束 Agent 能够造成的实际后果。

辅助认知包括：

- `COG_ACTION`：每一个外部效果必须先取得许可。
- `COG_COLLABORATION`：多个 Agent、Worker 和恢复任务必须共同消费同一份根额度。
- `COG_REFLECTION`：运行结束后根据拒绝、未知、对账和事故数据调整自主边界。

## 2.2 拓扑基座

主拓扑为 `TOP_HIERARCHY`。根任务持有总信封，子任务只能从父信封中预留更小的份额。

辅助拓扑包括：

- `TOP_ORCHESTRATION`：统一入口、统一账本和统一效果网关协调执行。
- `TOP_PARALLEL`：多个 Worker 并发消费额度时必须原子检查与占用。
- `TOP_LOOP`：循环、重试和恢复必须累计消费同一份额度，不能因再次进入循环而刷新上限。
- `TOP_ROUTING`：不同业务分支可以使用不同子信封，但仍受同一根信封约束。
- `TOP_CHAIN`：审批、预留、许可、提交、回执、对账依次形成证据链。

## 2.3 工程模式分类

本模式属于：

- 外部效果治理模式
- 分层额度控制模式
- 统一账本模式
- 幂等与未知结果治理模式
- 渐进式执行模式
- 多 Agent 权力不复制模式

# 3. 适用工程节点

适用于任何能够改变外部世界、产生不可忽略业务后果的节点，包括但不限于：

| 场景 | 典型动作 | 主要受控维度 |
|---|---|---|
| 客服补偿 | 发券、退款、补偿积分 | 单用户金额、单工单次数、日累计金额、对象名单 |
| 营销运营 | 群发邮件、短信、推送 | 接收者集合、人数、速率、渠道、时间窗口 |
| 人力资源 | 修改员工记录 | 可改字段、员工集合、单次影响人数、敏感动作类别 |
| 数据处理 | 导出、删除、更新数据 | 租户、表、字段、行数、目的地、保留时间 |
| 软件发布 | 部署、切流、回滚 | 环境、区域、实例比例、流量比例、持续时间 |
| 云资源运维 | 扩容、缩容、重启 | 服务、区域、实例数、并发数、小时费用、回收时间 |
| 采购付款 | 发起付款、批量结算 | 供应商集合、单笔金额、累计金额、次数、币种 |
| 多 Agent 协作 | 派生 Worker、调用下游 | 子 Agent 数、递归深度、并发数、下游写入数、总预算 |

# 4. 解决的问题

本模式重点解决以下问题：

1. 审批正确，但执行器因程序错误、参数错误、循环失控、并发竞争或重试风暴产生超额效果。
2. 同一个合法工具在不同参数下具有完全不同的后果，仅按工具名称授权无法限制真实影响。
3. 多个小动作单次都合规，但累计结果超过根任务上限。
4. 父任务拆分为多个子任务时，额度被错误复制而不是被分配。
5. 外部调用结果不确定时，额度被过早释放，重试形成重复效果。
6. 不同入口、补偿任务、回调、人工补单绕过统一额度账本。
7. Agent 能够自行修改硬上限、关闭计量或取得直连外部系统的高权限凭证。
8. 运行可以停止，但已发出的请求、迟到回调和未知结果没有继续被追踪。

# 5. 模式目标与非目标

## 5.1 目标

- 把企业可承受的最坏结果写成机器可执行边界。
- 在每一个外部效果发生前完成范围检查、额度占用和许可签发。
- 保证父子信封守恒，任务拆分不复制权力。
- 保证并发、循环、重试、恢复和回调共同消费同一份额度。
- 对成功、失败、未知三类结果采用不同记账策略。
- 支持先小后大、分批推进和自动停止。
- 为审计、复盘、探针补全和后续自治调整保留完整证据。

## 5.2 非目标

- 不替代审批门。审批决定动作能否开始，本模式限制开始后的最大后果。
- 不替代业务正确性校验。信封能限制“最多支付多少”，不能判断“正确工资应是多少”。
- 不替代沙箱。沙箱限制技术环境，本模式还需要限制业务效果。
- 不保证程序无错误。它允许错误继续暴露，但阻止错误无限扩散。
- 不把提示词中的口头限制视为强制边界。

# 6. 核心概念

## 6.1 外部效果

外部效果是指会改变系统外部可观察状态的动作，例如付款、发送消息、修改记录、发布版本、扩容实例、写入第三方系统或派生具有行动能力的子 Agent。

## 6.2 信封

信封是一组不可由当前执行者自行扩张的资源与效果边界。信封不是单一数字，而是多个限制维度的组合。

常见维度包括：

- 资源：租户、账户、环境、区域、表、字段、对象集合。
- 数量：单次、单批、单运行、单身份、单租户累计数量。
- 速率：每秒、每分钟、每小时最大效果数。
- 成本：金额、令牌、算力、实例小时、外部调用费用。
- 时间：运行时长、许可有效期、执行窗口、自动回收时间。
- 并发：并发写入数、Worker 数、子 Agent 数、进程数。
- 传播：递归深度、下游系统数、写入目的地数、消息转发层级。
- 恢复：停止条件、未知结果占用规则、补偿和对账要求。

## 6.3 硬信封

硬信封保存绝对不可由当前 Agent 或当前任务修改的边界，例如：

- 租户隔离
- 禁止访问的数据类别
- 禁止工具和禁止环境
- 生产凭证边界
- 绝对金额上限
- 最大递归深度
- 不可关闭的停止开关

硬信封只能由独立管理面或更高等级人工流程修改。

## 6.4 自主信封

自主信封保存当前 Agent 在硬信封内可以自动处理的范围，例如：

- 当前批量
- 当前速率
- 当前对象名单
- 当前并发数
- 当前自动化档位
- 当前可用工具子集

自主信封可以依据运行证据收紧或放宽，但不能突破硬信封。

## 6.5 根信封与子信封

根信封持有一次运行的总边界。子信封从父信封中预留一部分额度和范围。子信封继续派生时，孙信封只能从子信封剩余范围中预留。

## 6.6 效果许可

效果许可是一次性、不可转让、绑定具体请求的执行凭证。每一个外部效果在提交前必须取得效果许可。

效果许可至少绑定：

- 信封编号
- 运行编号
- 动作类型
- 资源对象
- 数量或金额
- 幂等键
- 参数摘要
- 有效期
- 签发版本

## 6.7 未知结果

外部请求已经发出，但本地无法确认成功或失败时，结果必须标记为“未知”。未知期间对应额度继续占用，直到独立对账取得证据。

# 7. 不可破坏的执行不变量

以下规则必须由系统强制执行，而不是仅写入提示词：

1. **无许可，不产生外部效果。**
2. **有效范围只能取交集。**
3. **子信封不得大于父信封，所有子信封预留总和不得超过父信封。**
4. **检查额度与占用额度必须在同一原子事务中完成。**
5. **循环、重试、恢复、回调和人工补单不得获得新额度。**
6. **未知结果继续占用额度。**
7. **相同外部效果的重试必须复用同一个幂等键。**
8. **同一幂等键的参数摘要不得变化。**
9. **未使用额度只有在不存在运行中请求和未知结果时才能返还。**
10. **所有外部调用路径必须经过同一账本和同一效果网关。**
11. **执行 Agent 不得修改硬信封、账本规则和停止开关。**
12. **停止新提交不等于忽略已发请求；迟到结果仍需记账和对账。**
13. **对象集合使用交集，数值上限使用最小值，任意显式禁止均具有否决权。**
14. **审批票据、信封、许可和外部回执必须绑定同一版本化动作提案。**

# 8. 有效范围计算

有效范围按以下关系计算：

```text
有效范围 =
    硬信封
    ∩ 身份范围
    ∩ 任务范围
    ∩ 能力范围
    ∩ 当前上下文范围
    ∩ 证据支持范围
```

计算规则：

- 对金额、数量、速率、并发、时长等数值限制，取各层最小上限。
- 对租户、对象、字段、工具、环境等集合限制，取各层允许集合的交集。
- 任意一层显式禁止时，动作立即拒绝。
- 缺失的高风险字段不得自动推断为无限制。
- 来源冲突时，采用更窄边界并进入人工或策略复核。

# 9. 角色与职责分离

| 角色 | 主要职责 | 不得执行的动作 |
|---|---|---|
| 边界管理员 | 配置硬信封、全局限额和停止规则 | 不直接执行业务效果 |
| 审批签发者 | 批准版本化动作提案 | 不修改执行账本 |
| 工作流编排器 | 拆分任务、申请子信封、调度阶段 | 不自行扩大信封 |
| 执行 Worker | 在子信封内申请许可并执行动作 | 不直连高权限外部凭证 |
| 信封账本 | 原子预留、占用、提交、释放、冻结 | 不解释业务意图 |
| 效果网关 | 校验许可后提交外部请求 | 不接受无许可调用 |
| 对账执行者 | 读取独立回执，关闭未知结果 | 不凭主观判断释放额度 |
| 值班处置者 | 冻结信封、停止新提交、组织恢复 | 不改写历史记录 |
| 可观测性探针 | 采集、校验、补全、告警和建议 | 不自行扩大边界或伪造成功状态 |

# 10. 输入契约

执行流程至少接收以下输入：

| 输入 | 必需 | 说明 |
|---|---|---|
| 版本化动作提案 | 是 | 明确动作、对象、参数、预计效果和版本摘要 |
| 审批引用 | 高风险动作必需 | 绑定动作提案版本、审批者、有效期和批准范围 |
| 硬信封 | 是 | 独立管理面提供的绝对边界 |
| 身份范围 | 是 | 当前主体可使用的账户、租户、工具和凭证范围 |
| 任务范围 | 是 | 当前运行的对象、目标、预算和时间窗口 |
| 能力范围 | 是 | 允许调用的工具、动作类型和参数约束 |
| 当前上下文范围 | 是 | 当前环境、区域、租户、时间和风险条件 |
| 证据支持范围 | 可选 | 依据历史表现、验证结果和当前证据收紧范围 |
| 场景配置 | 是 | 维度定义、单位、阈值、阶段计划、对账方式 |
| 停止策略 | 是 | 触发条件、作用范围和处置责任人 |

# 13. 状态机

## 13.1 运行状态

```text
已创建
  → 边界已解析
  → 根信封已建立
  → 子信封已预留
  → 执行中
      → 暂停
      → 对账中
      → 安全失败
  → 关闭中
  → 已关闭
```

## 13.2 信封状态

```text
草稿 → 有效 → 部分占用 → 耗尽
              ↘ 冻结
              ↘ 关闭
```

## 13.3 效果许可状态

```text
已签发 → 执行中 → 已提交
                → 已释放
                → 未知 → 已提交
                       → 已释放
                       → 需人工处理
已签发 → 已过期
已签发 → 已取消
```

# 14. 标准执行流程

## 14.1 总流程

```text
接收已批准动作提案
  ↓
加载硬信封、身份范围、任务范围和场景配置
  ↓
计算有效范围
  ↓
建立根信封
  ↓
按阶段、分支或子任务预留子信封
  ↓
为单个外部效果申请许可
  ↓
原子检查并占用额度
  ↓
效果网关提交外部请求
  ↓
根据证据标记成功、失败或未知
  ↓
提交额度、释放额度或继续占用
  ↓
阶段校验、扩大、暂停或停止
  ↓
对账未知结果
  ↓
返还可返还额度并关闭运行
```

## 14.2 分步规范

| 步骤 | 执行动作 | 必须校验 | 主要输出 | 失败处理 |
|---|---|---|---|---|
| 1. 接收提案 | 读取版本化动作提案和审批引用 | 提案摘要、审批范围、有效期一致 | 提案快照 | 拒绝启动 |
| 2. 加载边界 | 读取硬信封、身份、任务、能力、上下文和证据范围 | 来源有效、版本可追溯 | 边界输入包 | 缺失高风险字段则安全失败 |
| 3. 计算交集 | 按集合交集、数值最小值和显式否决计算有效范围 | 不得扩大任何来源边界 | 有效范围快照 | 采用更窄值并告警 |
| 4. 建立根信封 | 将批准范围转为可核减额度 | 维度、单位、作用域、时间窗口完整 | 根信封 | 无法量化的关键维度则阻断 |
| 5. 制定阶段计划 | 确定先小后大、批次、检查点和停止条件 | 每阶段累计不超过根信封 | 阶段计划 | 降级为更小批次 |
| 6. 预留子信封 | 为部门、分支、Worker 或批次预留范围 | 子级不超父级，集合为父级子集 | 子信封和预留记录 | 原子拒绝并返回原因 |
| 7. 申请效果许可 | Worker 提交具体对象、参数和所需额度 | 对象、动作、信封、时间和幂等键有效 | 待签发请求 | 拒绝或转人工 |
| 8. 原子占用 | 在同一事务中检查并占用额度 | 金额、数量、速率、并发、传播等全部通过 | 已签发许可和账本事件 | 拒绝，不得触发外部调用 |
| 9. 提交外部效果 | 效果网关校验许可后提交 | 许可未过期、参数摘要一致、停止开关未生效 | 外部请求引用 | 不确定时进入未知 |
| 10. 处理回执 | 读取外部回执或状态查询结果 | 回执与幂等键、对象、金额一致 | 成功、失败或未知状态 | 冲突时冻结并对账 |
| 11. 核算额度 | 成功转为已提交，明确失败转为已释放 | 证据充分、事务一致 | 更新账本 | 结果未知继续占用 |
| 12. 阶段检查 | 检查健康、错误、投诉、对账、偏差和剩余额度 | 满足扩大条件且无阻断信号 | 扩大、保持、暂停或停止决策 | 收紧或停止 |
| 13. 对账未知 | 通过独立渠道确认结果 | 不能仅依赖执行 Agent 自述 | 对账证据和闭环状态 | 超时升级人工处置 |
| 14. 返还与关闭 | 确认无运行中请求、无未知、无迟到回调风险 | 账实一致、子信封全部关闭 | 关闭报告 | 保持冻结，不得强制清零 |

# 15. 额度核减规则

一次效果申请只有在所有维度均通过时才能签发许可。

```text
允许执行 =
    对象属于允许集合
    且动作类型被允许
    且请求金额不超过剩余额度
    且请求数量不超过剩余次数
    且当前速率不超过窗口上限
    且当前并发不超过并发上限
    且预计运行时间不超过剩余时长
    且传播范围不超过剩余传播额度
    且停止开关未生效
```

任一维度不通过，整个效果申请拒绝。不得以“其他维度仍有余额”为理由进行兑换。

# 16. 子任务与层级分配规则

1. 子任务必须通过预留获得子信封，不能复制父信封配置。
2. 预留发生时，父级可用额度同步减少。
3. 子信封允许范围必须是父信封允许范围的子集。
4. 同级子信封可以使用不同维度配置，但总预留不得超过父级。
5. 子任务继续派生时，孙信封只能从子信封剩余范围中预留。
6. 子信封关闭后，未使用额度可以返还父级。
7. 返还前必须确认：
   - 子任务已结束；
   - 没有执行中许可；
   - 没有未知结果；
   - 没有尚未处理的迟到回调；
   - 外部系统不存在已受理但未返回的请求。
8. 父任务关闭前必须确认所有后代信封均已关闭、冻结或完成对账。

# 17. 并发控制规则

并发执行时，信封账本必须支持以下原子操作：

```text
读取剩余额度
+ 校验对象与策略
+ 占用请求额度
+ 写入许可
+ 写入账本事件
```

以上操作必须形成一个不可分割的事务。禁止采用“先查余额，再异步扣减”的实现。

当两个 Worker 同时申请同一剩余额度时，只允许先完成事务的一方成功。另一方必须读取更新后的余额并被拒绝或获得较小额度。

# 18. 循环、重试与恢复规则

## 18.1 循环

- 循环次数、累计效果数、累计成本和总时长都受根信封约束。
- 每次循环不得自动创建新根信封。
- 循环终止条件失效时，额度上限仍能阻止无限外部效果。

## 18.2 重试

- 同一外部效果重试必须复用原幂等键和参数摘要。
- 已确认成功的请求不得再次申请新许可。
- 已确认失败且额度已释放后，可以依据策略重新申请许可，但必须生成新的效果意图编号，并保留与原请求的关联。
- 未知结果不得新建幂等键重试。

## 18.3 恢复

- 恢复任务不得绕过原信封。
- 恢复时先重建账本状态，再决定继续、对账或停止。
- 任何无法重建的额度差异都按已占用处理，直到证据确认。

# 19. 未知结果处理

当网络超时、回执丢失、回调冲突或外部系统状态不明确时：

1. 将效果许可标记为“未知”。
2. 对应额度继续计入占用。
3. 禁止以新幂等键重复提交同一效果。
4. 创建对账对象并设置下一次查询时间。
5. 通过外部系统状态查询、流水、回执或人工证明获取独立证据。
6. 证据确认成功时，将额度转为已提交。
7. 证据确认失败时，将额度转为已释放。
8. 长时间无法确认时，冻结相关信封并升级人工处置。

# 20. 停止与恢复机制

## 20.1 停止开关

停止开关至少支持以下作用域：

- 单个效果许可
- 单个子信封
- 单次运行
- 单个主体
- 单个租户
- 单个工具或外部系统
- 全局高风险动作

## 20.2 停止后的行为

- 阻止新许可签发。
- 阻止尚未提交的许可进入效果网关。
- 不删除已发请求。
- 继续接收并记录迟到回执。
- 保持未知额度占用。
- 启动对账、补偿或人工处置流程。

## 20.3 恢复条件

恢复前必须满足：

- 触发停止的原因已定位；
- 账本与外部状态已完成必要对账；
- 边界已重新确认或收紧；
- 恢复范围和批次已明确；
- 值班责任人或策略引擎完成放行；
- 恢复后仍沿用原根信封或经独立流程签发新根信封。

# 21. 渐进式扩大范围

对于可分阶段执行的动作，默认先采用窄半径：

| 动作 | 第一阶段 | 扩大条件 |
|---|---|---|
| 发布版本 | 一个实例、一个区域或少量流量 | 技术健康和业务指标均通过 |
| 批量消息 | 内部种子名单或小规模试验组 | 内容检查、退信率、投诉率正常 |
| 数据修改 | 试运行后先改少量记录 | 对账、抽样和差异检查通过 |
| 云资源扩容 | 少量实例并设置自动回收 | 负载和费用指标持续满足条件 |
| 付款结算 | 按部门、供应商或受控批次 | 每批回执完整、账实一致 |

阶段扩大不是重置额度，而是在同一根信封内释放下一阶段可用份额。

# 22. 拒绝原因规范

建议使用稳定原因码：

| 原因码 | 含义 |
|---|---|
| `proposal_version_mismatch` | 动作提案版本或摘要不一致 |
| `approval_scope_mismatch` | 请求超出审批范围 |
| `scope_out_of_bounds` | 资源、对象、字段或环境越界 |
| `reservation_over_parent` | 子信封预留超过父级剩余范围 |
| `reservation_out_of_scope` | 子信封对象不属于父级允许集合 |
| `amount_exceeded` | 金额额度不足 |
| `count_exceeded` | 次数或数量额度不足 |
| `rate_exceeded` | 时间窗口速率超限 |
| `concurrency_exceeded` | 并发上限已满 |
| `duration_exceeded` | 运行或许可时长超限 |
| `propagation_exceeded` | Worker、递归深度或下游写入超限 |
| `unknown_quota_occupied` | 未知结果占用了剩余额度 |
| `idempotency_conflict` | 同一幂等键参数不一致 |
| `permit_expired` | 效果许可已过期 |
| `stop_switch_active` | 停止开关已生效 |
| `direct_external_call_forbidden` | 检测到绕过效果网关的调用 |
| `evidence_insufficient` | 无足够证据释放或扩大范围 |

# 23. 六类拓扑适配

## 23.1 链式

- 每个节点接收上一步的信封快照、许可状态和证据引用。
- 后续节点不得覆盖前序账本事件。
- 链路中断后从已确认检查点恢复。

## 23.2 路由

- 路由器按场景选择子信封配置。
- 路由结果必须保留策略版本和选择依据。
- 路由改变不能扩大根信封。

## 23.3 并行

- 并行 Worker 共享同一账本。
- 子信封预留与许可占用必须原子化。
- 合并时按根信封核对所有分支累计效果。

## 23.4 编排

- 编排器只负责调度和申请，不直接更改账本。
- 所有外部效果通过统一效果网关。
- 停止、恢复和对账由独立控制面协调。

## 23.5 循环

- 循环次数、累计效果和总时长均计入同一运行。
- 重试不得刷新额度。
- 达到任一上限立即停止继续迭代。

## 23.6 层级

- 每一层只能保持或缩小父级范围。
- 权力随预留转移，不随任务复制。
- 父级关闭前必须汇总全部后代信封状态。

- 场景配置只能收紧通用硬信封，不能扩大它。
- 新场景先在较窄自主信封内验证。

# 25. 独立运行模式

执行流程在没有可观测性探针时，仍必须具备以下最低能力：

1. 保存完整信封和许可状态。
2. 原子记账。
3. 记录所有拒绝和原因。
4. 记录外部请求、回执和幂等键。
5. 维护未知结果队列。
6. 支持停止和冻结。
7. 生成运行关闭报告。
8. 保留足够事件供事后审计。

独立运行时，不得因为缺少探针而省略强制控制。

# 26. 与工作流可观测性探针的交互

## 26.1 共享标识

执行流程与探针使用以下稳定标识关联数据：

```text
trace_id
run_id
parent_run_id
task_id
step_id
agent_id
worker_id
tenant_id
envelope_id
parent_envelope_id
reservation_id
permit_id
effect_id
idempotency_key
```

## 26.2 执行流程输出事件

建议至少输出以下事件：

- 边界输入已加载
- 有效范围已计算
- 根信封已创建
- 子信封预留成功
- 子信封预留拒绝
- 效果许可申请
- 效果许可签发
- 效果许可拒绝
- 外部请求已提交
- 外部回执已接收
- 结果转为未知
- 额度已提交
- 额度已释放
- 信封已冻结
- 停止开关已触发
- 对账已开始
- 对账已完成
- 阶段已扩大
- 运行已关闭

## 26.3 探针返回对象

探针可以返回：

- 数据补丁
- 数据冲突报告
- 越界或守恒异常告警
- 未知结果超时告警
- 停止建议
- 对账请求
- 阶段扩大否决建议
- 运行关闭前缺口清单

执行流程必须记录对探针返回对象的接收、采纳、拒绝或延期状态。

## 26.4 权限边界

- 探针默认只读，不直接修改账本。
- 探针不能签发新额度、扩大信封或伪造回执。
- 只有预先配置的硬门禁规则可以让探针信号自动阻断下一步。
- 所有自动阻断规则必须在运行前注册并版本化。

# 27. 治理要求

1. 信封账本、效果网关和停止开关位于 Agent 之外。
2. 执行 Worker 只持有受限凭证，不能直连高权限外部接口。
3. 硬信封由独立管理面维护。
4. 账本事件追加写入，不允许原地覆盖历史。
5. 策略、信封、许可和回执均保留版本与摘要。
6. 重要操作采用双人复核或独立职责分离。
7. 外部系统不支持幂等时，效果网关必须实现等效去重和对账机制。
8. 多租户场景按租户分别记账，禁止共享未隔离的全局余额。
9. 敏感对象和凭证不得写入普通日志。
10. 运行关闭不等于删除数据，保留周期由治理策略决定。

# 28. 评估与验收

## 28.1 必测用例

| 用例 | 期望结果 |
|---|---|
| 单次请求超过金额上限 | 请求被拒绝，外部系统无调用 |
| 多次小请求累计超过上限 | 超出部分被拒绝 |
| 十个 Worker 并发消费同一余额 | 总提交不超过根上限 |
| 子信封总和超过父信封 | 预留阶段原子拒绝 |
| 子信封包含父范围外对象 | 返回范围越界 |
| 循环终止条件失效 | 达到数量、金额或时长上限后停止 |
| 同一请求重复提交 | 幂等机制返回首次结果或拒绝重复 |
| 同一幂等键参数变化 | 返回幂等冲突 |
| 外部请求超时 | 状态进入未知，额度继续占用 |
| 未知结果随后确认成功 | 占用转为已提交 |
| 未知结果随后确认失败 | 占用转为已释放 |
| 停止开关触发 | 新许可停止，迟到回执继续记录 |
| 关闭子信封时仍有未知结果 | 禁止返还额度 |
| 回调试图绕过网关 | 阻断并告警 |
| Agent 试图修改硬信封 | 拒绝并记录治理事件 |
| 阶段扩大前健康指标不通过 | 保持当前阶段或收紧 |

## 28.2 验收条件

- 任何已提交效果均可追溯到有效许可。
- 任何许可均可追溯到有效信封和批准提案。
- 任一时刻，父级已预留总和不超过父级可分配上限。
- 已提交、执行中、未知和可用额度之间守恒。
- 结果未知时不存在自动释放额度的路径。
- 并发测试中不存在超卖额度。
- 停止后不再产生新的许可签发。
- 运行关闭时不存在未解释的账本差异。

# 29. 失败模式与反模式

| 反模式 | 风险 | 修正方式 |
|---|---|---|
| 只在提示词写“最多执行若干次” | 模型或其他路径可绕过 | 在外部账本和网关强制执行 |
| 只限制单次调用 | 小动作累计越界 | 同时限制运行、身份、租户和根任务累计值 |
| 每个 Worker 获得完整父额度 | 任务拆分复制权力 | 使用父级预留和子信封 |
| 先查余额再异步扣减 | 并发超卖 | 原子检查与占用 |
| 超时立即当失败并释放 | 可能重复付款或重复写入 | 标记未知并对账 |
| 每次重试生成新幂等键 | 下游产生重复效果 | 同一效果复用稳定键 |
| 执行者可以修改配额 | 边界可被自行拆除 | 配额管理与执行职责分离 |
| 多个入口各自记账 | 总效果不可控 | 所有入口经过统一账本和网关 |
| 关闭运行时强制清零未知项 | 丢失真实责任 | 冻结并继续对账 |
| 把拒绝数等同于事故数 | 误判系统质量 | 区分被拦截请求、程序缺陷和真实外部损失 |
| 把所有影响折算成金额 | 忽略声誉、数据和传播后果 | 保留多维原始单位 |

# 30. 教学示例映射

某月结算包含 798 张工资单，总批准金额为 13,706,097 元。根信封限制：

- 总金额不超过 13,706,097 元；
- 总付款次数不超过 798 次；
- 员工对象必须属于已批准名单。

五个部门分别从根信封预留子信封。某部门 160 人的批次因程序错误额外重跑四遍，形成 640 次额外请求。

采用本执行流程后：

- 首次 160 笔正常消费该部门子信封；
- 后续 640 次请求在许可签发前被拒绝；

# 31. 注册与扩展建议

接入 Hanerss Skill Framework 时：

1. 将本模式注册到工程模式注册表。
2. 主坐标挂载到 `COG_GOVERNANCE__TOP_HIERARCHY`。
3. 将并行、循环和编排坐标作为辅助挂载。
4. 将场景配置、原因码和数据对象拆为可版本化注册项。
5. 将高频场景封装为独立 Skill，但共享同一信封账本和事件契约。
6. 后续扩展不得改变既有标识的语义，只能通过新版本增加维度或约束。
