# 1. 文档定位

本文件定义“爆炸半径控制”的工作流可观测性探针。探针负责采集、关联、校验、补全和解释执行流程中的边界、信封、许可、外部效果、未知结果、对账、停止与恢复数据。

探针不是执行器，也不是额度账本。它不能替代信封控制，更不能通过修改观测数据制造新的执行权限。

本探针支持两种运行方式：

1. **独立运行**：读取日志、事件、账本快照、回执和配置，重建运行轨迹，发现缺口并生成观测报告、数据补丁和风险清单。
2. **交互运行**：实时消费执行流程事件，返回数据补丁、告警、停止建议、对账请求和关闭前缺口；执行流程决定是否采纳，预先注册的硬门禁规则除外。

工作流可观测性探针用于补全执行流程的数据，但不得把无证据的推断写成事实。未知必须保持未知，冲突必须保留冲突。

# 2. 探针目标

- 还原一次高风险动作从审批后到外部效果完成的完整轨迹。
- 验证有效范围是否确实由多层边界交集得到。
- 验证父子信封是否守恒，任务拆分是否复制了额度。
- 验证每一个外部效果是否持有有效许可。
- 识别并发超卖、循环刷新额度、重试换键和旁路调用。
- 量化金额、数量、对象、速率、并发、时间和传播等多维半径。
- 追踪未知结果占用、对账时效和迟到回执。
- 为执行流程补全缺失关联、派生指标和证据引用。
- 为治理调整、事故复盘和自主边界收放提供数据。
- 观测探针自身的数据完整性、延迟、覆盖率和误报情况。

# 3. 探针职责边界

## 3.1 探针可以做什么

- 读取运行事件和账本快照。
- 关联跨进程、跨 Worker、跨系统的同一动作。
- 计算累计效果和剩余额度。
- 检查父子信封守恒关系。
- 检查许可、幂等键、参数摘要和外部回执的一致性。
- 将缺失字段补成带来源、计算方式、置信度和有效期的数据补丁。
- 生成告警、停止建议、对账请求和关闭前缺口。
- 对策略、执行、数据或探针自身的问题进行分类。

## 3.2 探针不能做什么

- 不能签发或扩大信封。
- 不能代替审批人批准动作。
- 不能代替效果网关提交外部请求。
- 不能把推断结果伪装成外部成功回执。
- 不能在没有证据时释放未知额度。
- 不能覆盖、删除或改写原始事件。
- 不能因为“指标看起来正常”就判定业务结果正确。
- 不能把所有业务后果强行折算为金额。

# 4. 所属基座

## 4.1 认知基座

- `COG_PERCEPTION`：采集运行、账本、网关、外部系统和管理面的事实。
- `COG_MEMORY`：保存版本化轨迹、证据、补丁和对账历史。
- `COG_REASONING`：计算有效范围、额度守恒、累计影响和异常关系。
- `COG_REFLECTION`：根据事故、拒绝、未知和误报调整探针规则。
- `COG_GOVERNANCE`：生成边界异常、停止建议和治理证据。

## 4.2 拓扑基座

- `TOP_CHAIN`：串联提案、审批、信封、许可、请求、回执和对账。
- `TOP_ROUTING`：按场景、风险和数据来源选择探针组合。
- `TOP_PARALLEL`：汇总多个 Worker 和分支的累计效果。
- `TOP_ORCHESTRATION`：协调采集、关联、计算、告警和补全节点。
- `TOP_LOOP`：持续扫描未知结果、重试、循环和迟到回执。
- `TOP_HIERARCHY`：校验根信封、子信封和孙信封之间的守恒关系。

# 5. 探针运行模式

## 5.1 离线审计模式

适合事后复盘、历史扫描和未实时接入的系统。

输入通常包括：

- 执行日志
- 信封账本导出
- 外部系统流水或回执
- 工作流状态快照
- 策略与配置版本

输出包括：

- 重建轨迹
- 缺失数据清单
- 守恒差异
- 无许可效果清单
- 未知结果老化清单
- 风险报告

## 5.2 实时旁路模式

探针实时消费事件，但不参与执行决策。

适合先接入观测、再逐步启用联动的场景。

## 5.3 联动增强模式

探针实时返回：

- 数据补丁
- 告警
- 停止建议
- 对账请求
- 阶段扩大否决建议
- 运行关闭前缺口

执行流程必须记录探针返回对象的处理结果。

## 5.4 硬门禁模式

只有预先注册、版本化且由独立管理面启用的规则，才能把探针信号转成自动阻断。

适合以下确定性异常：

- 检测到无许可外部调用
- 子信封预留总和超过父信封
- 同一幂等键参数摘要冲突
- 停止开关已生效仍签发新许可
- 运行关闭时存在未解释账本差异

探针本身不能在运行中临时扩大硬门禁权限。

# 6. 输入数据源

| 数据源 | 主要内容 | 可信用途 |
|---|---|---|
| 动作提案与审批记录 | 版本、摘要、批准对象和上限 | 确认动作基线 |
| 硬信封注册表 | 绝对边界、禁止项、策略版本 | 计算最高允许范围 |
| 身份与能力配置 | 主体、凭证、工具和租户范围 | 验证能力边界 |
| 工作流事件 | 节点、分支、循环、Worker、状态 | 重建执行拓扑 |
| 信封账本 | 预留、占用、提交、释放、冻结 | 校验额度守恒 |
| 效果网关日志 | 许可、参数摘要、外部请求引用 | 验证无许可调用和一致性 |
| 消息队列与调度记录 | 重试、延迟、并发和重复投递 | 识别重试风暴和迟到消息 |
| 外部系统回执 | 成功、失败、流水和状态查询 | 关闭未知结果 |
| 停止与恢复记录 | 停止作用域、时间、原因和恢复条件 | 计算停止有效性 |
| 人工处置记录 | 决策、证据和责任人 | 补全非自动化闭环 |
| 探针自身运行日志 | 采集延迟、规则版本、错误 | 观测探针健康 |

# 9. 数据质量状态

探针对每个字段和事实保留数据质量状态：

| 状态 | 含义 | 处理规则 |
|---|---|---|
| 原始 | 来自权威源的直接记录 | 保留原文和来源 |
| 派生 | 根据原始数据按确定公式计算 | 记录公式、输入和版本 |
| 推断 | 根据多个信号建立候选关系 | 标记置信度，不覆盖原始数据 |
| 冲突 | 两个可信来源给出不同结果 | 同时保留，升级核验 |
| 缺失 | 预期字段没有记录 | 生成补全请求 |
| 未知 | 业务结果暂时无法确认 | 保持占用并进入对账 |

## 9.1 补全原则

1. 原始事实优先于派生结果。
2. 派生结果优先于概率推断。
3. 推断只能作为补充，不能作为释放额度或确认成功的唯一依据。
4. 冲突不得自动选择对执行更有利的结果。
5. 未知不得被补成失败或成功。
6. 所有补丁必须带来源、生成规则、置信度和适用范围。
7. 补丁不得覆盖原始事件，只能追加观测视图。

# 10. 探针总体流程

```text
发现数据源
  ↓
采集并标准化事件
  ↓
校验事件完整性与时间顺序
  ↓
按稳定标识关联运行、信封、许可和效果
  ↓
重建层级、并行、循环和重试拓扑
  ↓
计算有效范围与信封守恒关系
  ↓
检查许可、幂等、网关和外部回执
  ↓
计算累计效果、占用、未知和剩余额度
  ↓
识别异常、缺失、冲突和旁路调用
  ↓
生成数据补丁、告警、停止建议或对账请求
  ↓
跟踪执行流程响应
  ↓
输出运行报告和探针健康报告
```

# 11. 分步探针流程

| 步骤 | 探针动作 | 输入 | 输出 |
|---|---|---|---|
| 1. 数据源登记 | 记录来源、负责人、延迟、保留期和可信级别 | 数据源配置 | 数据源注册表 |
| 2. 事件采集 | 拉取或订阅事件 | 日志、账本、回执 | 原始事件流 |
| 3. 标准化 | 映射为统一事件结构 | 原始事件 | 标准事件 |
| 4. 完整性检查 | 检查必需字段、版本和时间 | 标准事件 | 缺失字段清单 |
| 5. 关联 | 连接运行、信封、许可、效果和回执 | 稳定标识 | 关联图 |
| 6. 拓扑重建 | 识别父子、并行、循环、重试和恢复 | 关联图 | 工作流轨迹 |
| 7. 边界校验 | 重算有效范围并对比实际配置 | 边界源、信封 | 边界差异 |
| 8. 守恒校验 | 检查父子预留和额度状态总和 | 账本事件 | 守恒报告 |
| 9. 许可校验 | 检查每个效果是否有有效许可 | 网关、许可、效果 | 无许可或过期清单 |
| 10. 幂等校验 | 检查重复键、参数摘要和重试路径 | 请求与回执 | 重复和冲突清单 |
| 11. 未知追踪 | 计算未知占用和老化时间 | 许可、回执、对账 | 未知队列与升级建议 |
| 12. 停止校验 | 计算停止后是否仍有新许可或新效果 | 停止事件、许可、请求 | 停止失效告警 |
| 13. 数据补全 | 生成可追溯补丁 | 缺失、派生、推断结果 | 数据补丁包 |
| 14. 告警与建议 | 按风险等级输出动作建议 | 异常和阈值 | 告警、停止建议、对账请求 |
| 15. 闭环跟踪 | 记录执行侧采纳、拒绝和处理结果 | 响应事件 | 闭环状态 |
| 16. 报告 | 生成运行、趋势和探针健康报告 | 全部观测数据 | 可审计报告 |

# 12. 探针组件

## 12.1 数据源发现探针

**目的**：确认所有可能产生外部效果的入口是否被纳入观测。

检查内容：

- 正常执行入口
- 重试入口
- 回调入口
- 恢复任务
- 补偿任务
- 人工补单入口
- 定时任务
- 子 Agent 和 Worker
- 直接调用外部接口的旁路路径

输出：未登记入口清单、来源覆盖率、旁路风险。

## 12.2 边界输入完整性探针

**目的**：检查硬信封、身份范围、任务范围、能力范围、上下文范围和证据范围是否齐全。

重点异常：

- 高风险维度缺失后被默认为无限制
- 策略版本缺失
- 动作提案摘要不一致
- 审批范围与根信封不一致
- 过期配置仍在使用

## 12.3 有效范围一致性探针

**目的**：独立重算有效范围，并与执行流程实际使用的范围对比。

校验规则：

- 集合取交集
- 数值取最小上限
- 显式禁止具有否决权
- 冲突采用更窄范围

输出：扩大差异、收紧差异、无法重算字段和证据引用。

## 12.4 根信封建立探针

**目的**：确认批准范围已经被完整转为可执行信封。

检查内容：

- 是否遗漏关键维度
- 单位是否明确
- 金额是否使用最小货币单位或定点数
- 对象名单是否版本化
- 时间窗口是否存在
- 停止条件是否绑定

## 12.5 父子信封守恒探针

**目的**：确保子任务分走额度，而不是复制额度。

核心校验：

```text
任意父信封：
子信封有效预留总和
+ 父信封直接占用
+ 父信封已提交
+ 父信封未知占用
≤ 父信封上限
```

对于集合：

```text
任意子信封允许集合 ⊆ 父信封允许集合
```

重点异常：

- 子信封总和超过父级
- 子信封出现父级名单外对象
- 子信封返还后旧请求迟到
- 同一预留被多个子信封引用
- 关闭父信封时后代仍在运行

## 12.6 并发占用探针

**目的**：识别“先查余额、后异步扣减”造成的超卖。

观测信号：

- 多个许可在同一旧余额快照上同时通过
- 许可签发时间重叠但账本序号不连续
- 余额短暂出现负数
- 同一版本号被多次成功更新
- 失败重试未重新读取余额

输出：可能的非原子占用窗口和受影响许可。

## 12.7 效果许可生命周期探针

**目的**：确保每个外部效果都由有效许可覆盖。

检查内容：

- 请求提交前许可已签发
- 许可未过期、未取消、未被冻结
- 请求参数摘要与许可一致
- 请求额度与许可额度一致
- 一个许可没有被多个独立效果重复消费
- 许可状态变化完整

## 12.8 无许可外部效果探针

**目的**：发现绕过统一网关的调用。

关联方法：

- 外部请求引用反查许可
- 回执反查外部请求和许可
- 网络出口、凭证使用和外部系统流水交叉核对
- 人工补单与正常工作流对比

确定存在无许可效果时，应生成最高等级告警。

## 12.9 幂等一致性探针

**目的**：识别重复提交和换键重试。

检查内容：

- 同一效果意图是否复用稳定幂等键
- 同一幂等键的参数摘要是否一致
- 同一对象、金额、时间窗口出现多个不同键
- 外部系统是否返回首次结果
- 执行流程是否因超时立即创建新请求

## 12.10 循环与重试累计探针

**目的**：确认循环和重试仍消费同一根额度。

重点异常：

- 每次循环创建新根信封
- 重试次数不计入累计数量
- 恢复运行重置已提交金额
- Worker 重启后丢失原许可和幂等键
- 循环终止条件失效但没有额度停止

## 12.11 未知结果占用探针

**目的**：监控未知结果的额度占用、老化和对账进度。

检查内容：

- 超时请求是否进入未知
- 未知期间额度是否继续占用
- 是否存在未知结果被自动释放
- 对账任务是否按时运行
- 对账证据是否来自独立来源
- 长时间未知是否触发冻结和升级

## 12.12 速率与时间窗口探针

**目的**：校验每秒、每分钟、每小时和业务窗口的累计效果。

重点处理：

- 跨 Worker 聚合
- 跨进程时钟偏差
- 重放事件去重
- 滑动窗口与固定窗口差异
- 夏令时或时区变化
- 窗口边界突发

## 12.13 并发与传播探针

**目的**：观测子 Agent、Worker、下游写入和递归派生的扩大速度。

指标包括：

- 当前并发数
- 峰值并发数
- Worker 派生数
- 最大层级深度
- 每个上游动作触发的下游效果数
- 每个子 Agent 获得的信封份额

## 12.14 阶段推进探针

**目的**：确认“先小后大”的阶段扩大符合条件。

检查内容：

- 第一阶段实际范围
- 阶段健康指标
- 业务验收结果
- 未知结果是否清零或受控
- 扩大后累计范围是否仍在根信封内
- 阶段扩大是否经过版本化决策

## 12.15 停止开关有效性探针

**目的**：验证停止是否真正切断后续新效果。

检查内容：

- 停止触发时间
- 停止作用域
- 停止后新许可数
- 停止后新外部请求数
- 已发请求的迟到回执
- 停止到最后一个新效果之间的延迟
- 恢复前是否完成必要对账

## 12.16 返还与关闭探针

**目的**：防止仍有在途或未知效果时返还额度。

检查内容：

- 子信封是否仍有执行中许可
- 是否存在未知结果
- 是否存在未处理迟到回调
- 外部系统是否仍有受理中请求
- 返还金额与账本守恒
- 运行关闭后是否继续出现外部效果

## 12.17 数据补全探针

**目的**：为执行流程补充可证实的缺失信息。

可补全内容：

- 父子运行关系
- 事件时间差
- 累计效果量
- 信封占用状态
- 许可与请求关联
- 重试链
- 未知老化时间
- 停止生效延迟
- 场景维度标签

不可补全为事实的内容：

- 外部请求是否真实成功
- 业务金额是否正确
- 审批人本应作出的判断
- 没有证据的对象归属

## 12.18 探针自观测组件

**目的**：防止探针静默失效。

观测内容：

- 事件采集延迟
- 丢失事件数
- 重复事件数
- 无法解析事件数
- 关联失败率
- 规则执行失败率
- 告警发送失败率
- 数据源最后更新时间
- 探针版本覆盖率
- 补丁采纳率和误报率

# 13. 指标目录

## 13.1 边界与信封指标

### 13.1.1 根信封利用率

```text
根信封利用率 = 已提交额度 ÷ 根信封上限
```

金额、数量、时间、并发和传播维度分别计算，不合并为单一值。

### 13.1.2 根信封占用率

```text
根信封占用率 =
（已提交 + 执行中占用 + 未知占用）÷ 根信封上限
```

### 13.1.3 子信封预留率

```text
子信封预留率 = 子信封有效预留总和 ÷ 父信封可分配上限
```

### 13.1.4 子信封超配率

```text
子信封超配率 =
最大值（0，子信封有效预留总和 - 父信封可分配上限）
÷ 父信封可分配上限
```

期望值为 0。

### 13.1.5 范围扩大差异数

探针独立重算范围比执行范围更窄时，按资源、对象、字段、工具和环境分别计数。

### 13.1.6 边界版本漂移率

```text
边界版本漂移率 =
使用过期或不一致策略版本的运行数 ÷ 总运行数
```

## 13.2 效果与许可指标

### 13.2.1 许可覆盖率

```text
许可覆盖率 = 有有效许可的外部效果数 ÷ 外部效果总数
```

期望值为 100%。

### 13.2.2 无许可外部效果率

```text
无许可外部效果率 = 无有效许可的外部效果数 ÷ 外部效果总数
```

期望值为 0。

### 13.2.3 许可拒绝率

```text
许可拒绝率 = 被拒绝许可申请数 ÷ 许可申请总数
```

需按拒绝原因拆分，不能简单把高拒绝率视为坏事。

### 13.2.4 被拦截效果量

对每个维度累计被拒绝请求的原始效果量，例如：

- 被拦截金额
- 被拦截接收者数
- 被拦截数据行数
- 被拦截实例数
- 被拦截下游写入数

只有确认请求若无控制便会进入外部系统时，才标记为“潜在损失已拦截”；否则只标记为“请求被拒绝”。

### 13.2.5 许可过期率

```text
许可过期率 = 未使用即过期的许可数 ÷ 已签发许可总数
```

## 13.3 幂等与重复指标

### 13.3.1 重复请求识别数

同一效果意图在窗口内出现多次提交的数量。

### 13.3.2 重复抑制率

```text
重复抑制率 = 被成功抑制的重复请求数 ÷ 已识别重复请求数
```

### 13.3.3 幂等参数冲突率

```text
幂等参数冲突率 =
同一幂等键参数摘要不一致的请求数 ÷ 使用幂等键的请求数
```

### 13.3.4 换键重试率

```text
换键重试率 =
同一效果意图使用多个幂等键的重试链数 ÷ 重试链总数
```

## 13.4 未知与对账指标

### 13.4.1 未知额度占比

```text
未知额度占比 = 未知状态占用额度 ÷ 根信封上限
```

### 13.4.2 未知结果数量

按场景、外部系统、租户、Agent 和年龄区间统计。

### 13.4.3 未知结果老化时间

```text
未知结果老化时间 = 当前时间 - 进入未知状态时间
```

建议统计中位数、较高分位数和最大值。

### 13.4.4 对账闭环率

```text
对账闭环率 = 已确认成功或失败的未知结果数 ÷ 应对账未知结果总数
```

### 13.4.5 未知误释放数

结果仍未确认但额度已经释放的许可数量。期望值为 0。

### 13.4.6 迟到回执率

```text
迟到回执率 =
运行关闭、信封返还或停止后到达的回执数 ÷ 外部回执总数
```

## 13.5 并发、循环与传播指标

### 13.5.1 峰值并发数

按运行、租户、工具和外部系统分别统计。

### 13.5.2 并发超卖尝试数

多个请求基于同一旧余额尝试成功占用的次数。

### 13.5.3 Worker 派生数

一次运行创建的 Worker 总数及峰值并发 Worker 数。

### 13.5.4 层级深度

从根任务到最深子任务的层级数。

### 13.5.5 权力复制系数

```text
权力复制系数 = 同级子信封上限总和 ÷ 父信封上限
```

在同一维度上应不大于 1。

### 13.5.6 效果传播系数

```text
效果传播系数 = 下游外部效果数 ÷ 上游获批准动作数
```

该指标需结合场景基线解释。

### 13.5.7 循环累计消耗率

```text
循环累计消耗率 = 循环中已提交效果量 ÷ 根信封上限
```

## 13.6 停止与恢复指标

### 13.6.1 停止生效延迟

```text
停止生效延迟 = 最后一个新许可签发时间 - 停止触发时间
```

理想情况下不应为正值；若系统存在传播延迟，应有明确上限。

### 13.6.2 停止后新效果数

停止触发后新增的外部效果数量，需区分：

- 停止前已发、停止后回执
- 停止后新提交

只有后者表示停止失效。

### 13.6.3 恢复前对账完成率

```text
恢复前对账完成率 =
恢复前已闭环的受影响未知结果数 ÷ 恢复前应闭环未知结果数
```

### 13.6.4 恢复后复发率

同类异常在恢复后的指定窗口内再次出现的比例。

## 13.7 数据质量与探针健康指标

### 13.7.1 事件完整率

```text
事件完整率 = 满足必需字段的事件数 ÷ 事件总数
```

### 13.7.2 轨迹关联率

```text
轨迹关联率 = 成功关联到运行和信封的事件数 ÷ 需要关联的事件总数
```

### 13.7.3 外部效果可追溯率

```text
外部效果可追溯率 =
可追溯至许可、信封和提案的外部效果数 ÷ 外部效果总数
```

### 13.7.4 数据新鲜度

```text
数据新鲜度 = 探针采集时间 - 来源记录时间
```

### 13.7.5 补丁采纳率

```text
补丁采纳率 = 被执行流程采纳的补丁数 ÷ 已发送补丁数
```

### 13.7.6 告警闭环率

```text
告警闭环率 = 已确认处理结果的告警数 ÷ 应处理告警总数
```

### 13.7.7 探针静默时间

关键数据源自最后一条成功事件起未更新的时长。

# 14. 多维指标约束

爆炸半径不是一个总分。探针必须保留原始维度并分别展示：

```text
金额
数量
对象集合
速率
并发
运行时间
Worker 数
层级深度
下游写入数
流量比例
数据行数
接收者数
实例小时
```

可以生成风险摘要，但不得用一个综合分数替代原始限额和守恒校验。

# 15. 告警等级

| 等级 | 条件示例 | 默认动作 |
|---|---|---|
| 提示 | 字段缺失但可从权威源补全、许可即将过期 | 生成补丁或提醒 |
| 警告 | 拒绝率突增、未知结果老化、阶段健康变差 | 通知责任人并限制扩大 |
| 高危 | 子信封接近超配、停止后仍出现新许可、换键重试 | 建议暂停相关信封 |
| 严重 | 无许可外部效果、父子额度已超配、硬边界被突破、账本出现负数 | 自动硬门禁或立即停止，视预注册规则而定 |

# 16. 告警规则示例

## 16.1 父子信封超配

```yaml
rule_id: rule_parent_child_overallocation
condition: 子信封有效预留总和 > 父信封可分配上限
severity: 严重
action:
  - 阻断新的子信封预留
  - 冻结受影响父信封
  - 生成守恒差异报告
```

## 16.2 无许可外部调用

```yaml
rule_id: rule_effect_without_permit
condition: 外部请求存在且无法关联有效许可
severity: 严重
action:
  - 触发停止建议或硬门禁
  - 冻结相关凭证
  - 启动外部流水核查
```

## 16.3 未知结果超时

```yaml
rule_id: rule_unknown_aging
condition: 未知结果老化时间 > 场景阈值
severity: 高危
action:
  - 升级对账频率
  - 阻止相关信封返还
  - 通知人工处置
```

## 16.4 幂等参数冲突

```yaml
rule_id: rule_idempotency_parameter_conflict
condition: 同一幂等键对应多个参数摘要
severity: 严重
action:
  - 拒绝后续请求
  - 冻结相关许可
  - 保存冲突参数证据
```

# 17. 数据补丁协议

## 17.1 补丁对象

```yaml
patch_id: patch_唯一编号
trace_id: 全链路编号
run_id: 运行编号
target_type: 运行或信封或许可或效果或回执
target_id: 目标编号
field_path: 待补字段路径
proposed_value: 建议值
value_type: 原始或派生或推断
source_refs: []
evidence_refs: []
derivation_rule: 计算或关联规则
rule_version: 规则版本
confidence: 置信度
valid_from: 生效时间
valid_until: 失效时间或空
conflict_policy: 保留冲突或更窄优先或人工核验
created_at: 时间
status: 已生成或已发送或已采纳或已拒绝或已过期
```

## 17.2 补丁限制

- 不修改原始事件。
- 不补写审批决定。
- 不补写外部成功状态。
- 不释放未知额度。
- 不扩大任何范围。
- 当补丁会影响控制决策时，必须要求执行流程显式确认或命中预注册规则。

## 17.3 常见补丁

| 缺失项 | 可用来源 | 补全方式 |
|---|---|---|
| parent_run_id | 调度记录、创建事件 | 确定关联或推断关联 |
| parent_envelope_id | 预留记录 | 确定关联 |
| 累计已提交量 | 账本事件 | 确定公式派生 |
| 未知老化时间 | 未知开始时间、当前时间 | 确定公式派生 |
| 重试链 | 幂等键、对象、参数摘要、时间 | 确定或推断关联 |
| 停止生效延迟 | 停止事件、许可事件 | 确定公式派生 |
| 场景标签 | 工具、资源、业务节点 | 推断并标记置信度 |

# 19. 与执行流程的交互协议

## 19.1 交互闭环

```text
执行流程产生标准事件
  ↓
探针采集、关联、校验和计算
  ↓
探针输出补丁、告警、停止建议或对账请求
  ↓
执行流程记录接收状态
  ↓
执行流程采纳、拒绝、延期或触发硬门禁
  ↓
处理结果重新作为事件返回探针
```

## 19.2 响应对象

执行流程对每个探针输出返回：

```yaml
response_id: response_唯一编号
probe_object_id: 探针对象编号
run_id: 运行编号
decision: 已采纳或已拒绝或已延期或已自动阻断
reason: 处理原因
actor_id: 决策主体
resulting_action_refs: []
responded_at: 时间
```

## 19.3 交互约束

- 探针补丁不能静默改写执行状态。
- 执行流程拒绝高风险告警时必须记录理由和责任主体。
- 探针不得因执行流程拒绝建议而伪造更高风险等级。
- 自动阻断仅依据运行前注册的确定性规则。
- 两者通过稳定标识交互，不共享可被任意修改的内存状态。

# 20. 独立运行流程

当没有标准事件总线或执行流程未接入时，探针按以下步骤独立运行：

1. 登记可获取的数据源和时间范围。
2. 读取账本、日志、外部回执和配置快照。
3. 生成本地标准事件，不修改来源。
4. 使用稳定标识和证据建立关联图。
5. 重建根任务、子任务、循环、重试和恢复关系。
6. 重算信封守恒和累计效果。
7. 标记无法确认的关联和结果。
8. 输出缺失数据、风险和对账建议。
9. 保存报告版本，供后续增量分析。

独立运行时，探针可以发现异常，但不能保证实时阻止外部效果。

# 21. 六类拓扑的观测适配

## 21.1 链式

观测重点：

- 节点顺序
- 输入输出版本
- 许可是否早于外部请求
- 回执是否正确连接到请求
- 中断后从哪个检查点恢复

## 21.2 路由

观测重点：

- 路由依据
- 场景配置版本
- 分支是否获得正确子信封
- 路由切换是否扩大范围

## 21.3 并行

观测重点：

- 并行 Worker 数
- 原子占用
- 同一旧余额快照
- 分支累计效果
- 汇合时的根信封守恒

## 21.4 编排

观测重点：

- 编排器、账本和效果网关职责分离
- 跨系统标识传递
- 停止信号传播

# 23. 阈值配置原则

1. 阈值必须按场景和维度配置，禁止全局使用一个通用百分比。
2. 硬不变量不使用宽松阈值，例如无许可外部效果必须为 0。
3. 趋势型指标可以使用基线和变化率，例如拒绝率突然上升。
4. 未知结果阈值应考虑外部系统正常回执时间。
5. 低频高损失场景应优先使用绝对值和对象集合校验。
6. 高频低单价场景应重点监控累计量、速率和传播。
7. 阈值版本必须与运行事件绑定。
8. 阈值调整不能追溯性改变历史结论，历史报告使用当时版本。

# 24. 运行关闭判定

探针在以下条件全部满足时，才建议运行关闭：

- 所有根信封和子信封状态可解释。
- 所有效果都能追溯到许可。
- 所有许可都能追溯到信封和动作提案。
- 未知结果已经闭环，或进入明确人工冻结状态。
- 账本守恒成立。
- 不存在停止后新提交的外部效果。
- 迟到回执窗口已结束或有持续处理责任人。
- 数据补丁冲突已经处理。
- 探针自身关键数据源未静默失效。

# 25. 评估与验收用例

| 用例 | 探针应发现或证明的结果 |
|---|---|
| 子信封总和超过父级 | 识别超配并生成严重告警 |
| 子信封包含父级外对象 | 识别范围越界 |
| 两个 Worker 基于同一余额同时通过 | 标记可能非原子占用 |
| 外部请求没有 permit_id | 关联失败并触发无许可告警 |
| 许可已过期但请求仍提交 | 标记许可生命周期违规 |
| 同一幂等键参数不同 | 触发幂等冲突 |
| 同一效果换新键重试 | 识别换键重试链 |
| 超时后额度立即释放 | 识别未知误释放 |
| 未知结果长期无对账 | 计算老化并升级 |
| 停止后仍签发新许可 | 识别停止失效 |
| 停止前请求在停止后回执 | 不误判为停止后新提交 |
| 循环每轮建立新根信封 | 识别额度刷新 |
| 运行关闭后出现新效果 | 触发迟到或旁路告警 |
| 缺少 parent_run_id | 从调度证据生成带置信度补丁 |
| 两个权威源结果冲突 | 保留冲突，不自动选边 |
| 探针数据源停止更新 | 触发探针静默告警 |

# 26. 探针自身验收条件

- 关键外部效果来源覆盖率达到场景要求。
- 无许可效果检测能够覆盖正常、回调、恢复和人工补单入口。
- 父子信封关系可重建。
- 原始、派生、推断、冲突、缺失和未知状态可区分。
- 所有补丁均可追溯到来源和规则版本。
- 探针不会覆盖原始事实。
- 探针不能自行释放额度或扩大范围。
- 告警具备去重、合并、升级和闭环状态。
- 探针失效本身能够被发现。

# 27. 失败模式与反模式

| 反模式 | 风险 | 修正方式 |
|---|---|---|
| 只看单个工具调用 | 看不到跨 Worker 累计效果 | 按运行、身份、租户和根信封聚合 |
| 只统计成功请求 | 未知和在途额度被忽略 | 同时统计执行中、未知和已提交 |
| 把超时直接记为失败 | 可能掩盖重复效果 | 保持未知并对账 |
| 用日志文本猜测成功 | 证据不可靠 | 使用外部回执或独立查询 |
| 用一个总分表示爆炸半径 | 丢失多维风险 | 保留各维度原始指标 |
| 补丁覆盖原始事件 | 破坏审计链 | 追加观测视图 |
| 探针直接修改额度 | 观测者越权 | 只输出建议或命中预注册门禁 |
| 只监控主执行入口 | 回调、恢复和人工补单绕过 | 建立入口清单和来源覆盖率 |
| 只看平均值 | 峰值并发和单次严重越界被掩盖 | 同时观察最大值和高分位数 |
| 高拒绝率一律判坏 | 可能误伤有效控制 | 按原因区分被拦截风险与配置过窄 |
| 关闭后停止采集 | 迟到回执和旁路效果丢失 | 保留关闭后观察窗口 |
| 探针无自观测 | 静默失效 | 监控采集延迟、覆盖率和最后更新时间 |

# 28. 教学示例观测结果

某月工资结算：

- 批准工资单数：798
- 批准总金额：13,706,097 元
- 实际已提交金额：13,706,097 元
- 某 160 人批次额外重跑四遍
- 被拒绝额外请求：640 次
- 被拦截请求金额：10,995,840 元
- 未知结果：0

探针应生成的关键观测：

```yaml
root_envelope:
  approved_payment_count: 798
  approved_amount: 13706097
  committed_payment_count: 798
  committed_amount: 13706097
  unknown_payment_count: 0
  unknown_amount: 0

refusals:
  total: 640
  primary_reason: amount_exceeded
  requested_amount_blocked: 10995840

invariants:
  permit_coverage_rate: 1.0
  child_overallocation_rate: 0
  unknown_misrelease_count: 0
  amount_conservation: 通过
```

探针还应区分：

- “被拒绝请求金额”是程序试图产生的额外效果量；
- “真实外部损失”仍为 0；
- 640 次拒绝说明控制有效，同时也表明执行器存在重试缺陷，需要修复。

# 29. 注册与扩展建议

接入 Hanerss Skill Framework 时：

1. 将探针作为爆炸半径控制模式的执行化 Skill 注册。
2. 与执行流程共享稳定标识和事件契约。
3. 探针规则、指标、阈值和场景配置分别版本化。
4. 观测结果作为派生视图，不替代注册表和原始账本。
5. 新增场景时优先增加配置和探针组合，不修改已有指标语义。
6. 探针可以独立升级，但必须声明兼容的事件契约版本。
7. 所有自动硬门禁规则单独注册、评审和审计。
