# Hanerss 工作流可观测性探针

## 1. 文档定位

本文件定义一套可独立运行、也可与《Hanerss 通用执行流程》交互运行的工作流可观测性探针体系。

探针的核心任务不是替代执行器，也不是再调用一个模型对结果发表评论，而是把执行流程中分散、缺失或不可直接比较的数据连接起来，使系统能够回答：

- 智能体说自己做了什么；
- 执行轨迹显示它实际经过了什么；
- 外部环境最终发生了什么；
- 关键结论是否真正得到证据支持；
- 证据是否有效、完整、可追溯；
- 发现偏差后是否发生了越权改变；
- 循环是否取得进展；
- 自动修复失败后是否真的恢复基线；
- 某条经验或某个技能在真实复用中是否带来收益；
- 用来判断对错的检查器本身是否仍然可信。

探针体系同时承担“运行数据补全”职责。当执行流程缺少环境终态、外部回执、证据版本、验证器元数据、交接状态或恢复证明时，探针可以在授权范围内发出证据请求、读取允许的数据源，并生成独立的补全记录。

探针不得伪造缺失数据，不得原地覆盖原始事件，也不得绕过策略闸直接修改业务机械态。

---

## 2. 目标与非目标

### 2.1 目标

1. 建立统一的运行关联键，使任务、节点、动作、工件、证据、回执、检查点和反思能够被串联；
2. 同时观察最终输出、完整轨迹和环境终态；
3. 将叙事态与机械态的分歧转化为可计算信号；
4. 检查关键结论是否接入数据库、测试、规则、回执或人工审核等结果信号；
5. 发现执行数据缺口并生成可追溯的补全记录；
6. 为七类认知能力和六类拓扑提供通用探针；
7. 为不同风险与场景提供不同探针集合；
8. 支持实时观察、离线回放、旁路审计和交互式策略闸；
9. 观测反思闭环是否真正获得新证据、受权改变、独立复验并能够停止；
10. 观测探针与验证器自身的健康状态。

### 2.2 非目标

本文件不负责：

- 直接执行工作流节点；
- 直接调用高风险业务写接口；
- 直接替代策略闸做最终放行；
- 把模型自评当作业务终态；
- 自动把一次成功升级为正式技能；
- 自动把一次失败解释为已确认根因；
- 规定所有业务共享同一数值阈值；
- 将可观测性探针提升为 Hanerss 的第四个一级基座。

## 3. 与 Hanerss 基座的关系

### 3.1 探针是运行时挂载资产

Hanerss v0.1 仍然保持三大一级基座：

```text
认知基座
拓扑基座
工程模式基座
```

探针属于运行时挂载资产，可以引用并服务于：

```text
认知项
拓扑项
矩阵坐标
工程模式
业务节点
技能
评估用例
治理规则
工作流定义
工作流运行
```

### 3.2 注册表是探针定义的源头

推荐关系：

```text
认知注册表 + 拓扑注册表 + 工程模式注册表
                 ↓
          探针挂载声明
                 ↓
            探针注册表
                 ↓
       场景探针集与运行实例
                 ↓
  观察、补全、指标、告警、回放与建议
```

探针定义与探针运行实例分离。探针定义可版本化，运行实例必须锁定具体版本。

### 3.3 探针不改变原始框架语义

例如：

- `COG_REFLECTION__TOP_LOOP` 仍然是认知与拓扑的矩阵坐标；
- 反思循环探针只是挂载到该坐标，用于检查新结果信号、进展、停止与恢复；
- 探针不会把“反思”重新定义为一个指标，也不会把“循环”重新定义为监控工具。

## 4. 核心原则

### 4.1 测量先于评价

如果探针拿不到真实业务状态，只能评价文本是否自洽，那么它最多说明“叙述内部一致”，不能说明“结果真实正确”。

### 4.2 新信号优先于重复思考

第二次检查是否更可靠，取决于第二次多看到了什么。

以下变化可以提高可靠性：

- 新数据库快照；
- 新测试结果；
- 新外部回执；
- 新规则版本；
- 新人工审核；
- 受控回放；
- 针对性干预后结果翻转。

仅更换语气、降低评分或让同一模型“再仔细想想”，不能填补事实盲区。

### 4.3 读取、判断、建议与控制分离

探针读取数据并产生观察。

指标计算器把观察转为信号。

诊断器把信号转为发现与风险说明。

策略闸把发现映射为继续、阻断、回滚或转人工。

执行器才负责改变机械态。

### 4.4 原始事件不可覆盖

探针发现原始事件缺字段或值错误时，应生成：

- 补全记录；
- 更正建议；
- 冲突记录；
- 证据请求；
- 新版本观察。

不得原地修改原始事件。

### 4.5 未知必须显式存在

以下情况不能记为零：

- 没有读到环境终态；
- 证据过期；
- 事件缺失；
- 关联键断裂；
- 验收器版本未知；
- 探针失效；
- 采样范围不足。

统一使用：

```text
已观测
未观测
未知
冲突
失效
不适用
```

### 4.6 偏差识别与根因归因分离

探针可以确认“报告与账本不一致”，但不能在没有回放、调查或干预证据时自动确认根因。

探针输出应区分：

```text
偏差事实
归因假设
归因证据
归因置信状态
```

### 4.7 阈值由风险和场景决定

同一指标在不同场景中的意义不同。

- 文案生成的错误放行；
- 代码发布的错误放行；
- 支付任务的错误放行；

三者不能共用同一条健康线。

### 4.8 探针本身也必须可观测

需要监控：

- 探针是否启动；
- 是否收到必需事件；
- 数据是否延迟；
- 规则版本是否有效；
- 指标是否成功计算；
- 补全请求是否闭环；
- 告警是否重复或丢失；
- 探针结论是否被策略闸消费。

### 4.9 可重放优先

任何重要发现都应能够从以下材料重新计算：

- 定义版本锁；
- 原始事件；
- 机械态快照；
- 证据引用；
- 探针版本；
- 指标定义版本；
- 策略版本。

### 4.10 低侵入、默认只读

探针默认以旁路读取方式运行。需要主动获取数据时，只能调用被授权的只读接口或快照接口。

高风险环境中，探针不得因自身故障改变业务执行语义；是否阻断由预先固定的探针失效策略决定。

### 4.11 可比性先于改善率

改变前后只有在目标、样本、窗口、风险分层和验收口径可比时，才能计算改善率。若验证器、分母、数据范围或任务分布发生变化，探针必须保留两个口径并标记“不可直接比较”，不能通过换尺子制造提升。

探针还应分别观察：

- **结果是否改善：**目标相关终态、质量、风险、成本或时延是否变好；
- **改善是否无回归：**原有通过项和硬约束是否仍成立；
- **改善是否可归因：**实际改变与结果之间是否存在足够的对照、回放或干预证据。

三者不得合并成一个模糊的“反思有效分”。

## 6. 探针运行模式

### 6.1 离线独立模式

探针读取已经归档的：

- 事件日志；
- 工件清单；
- 证据引用；
- 环境快照；
- 验收结果；
- 最终运行摘要。

它不依赖执行器在线，也不影响原运行结果。

适用：

- 历史审计；
- 事故复盘；
- 指标重算；
- 探针规则升级后的回归；
- 技能与经验真实收益分析；
- 验证器校准。

### 6.2 实时旁路模式

探针订阅执行事件并实时计算信号，但只发出观察、补全记录和告警，不参与控制。

适用：

- 低风险任务；
- 新探针试运行；
- 监控覆盖度验证；
- 不希望改变既有执行语义的迁移阶段。

### 6.3 交互建议模式

探针可以：

- 发出证据请求；
- 请求机械态快照；
- 请求补充回执；
- 生成放行建议；
- 指出应重验的对象。

策略闸可以参考建议，但最终控制仍由执行系统决定。

### 6.4 交互策略闸模式

在高风险工作流中，策略预先声明某些探针信号为必需输入。

例如：

```text
没有真实终态对账 → 不允许放行
基线恢复未证明 → 不允许结束自愈循环
验证器已过期 → 转人工
关键证据冲突 → 阻断写入
```

探针仍不直接执行控制，只是其结果成为策略闸的强制条件。

### 6.5 取证回放模式

探针定位长轨迹中的可疑步骤，通过受控回放或针对性干预观察结果是否翻转。

该模式用于提高错误归因证据质量。它必须在隔离环境或明确授权范围内运行，不能为了验证假设随意修改生产状态。

## 7. 可观测数据面

### 7.1 叙事数据

包括：

- 原始用户目标；
- 计划摘要；
- 模型解释；
- 进度说明；
- 最终回复；
- 交接摘要；
- 反思文本。

主要用途：检查目标漂移、完成声明、假设表达与交接信息。

主要限制：不能单独证明环境事实。

### 7.2 机械数据

包括：

- 数据库状态；
- 文件与代码指纹；
- 工具参数；
- 外部系统对象；
- 事务状态；
- 权限记录；
- 回执；
- 测试结果；
- 回滚状态。

主要用途：确认真实终态、参数绑定、副作用与恢复结果。

### 7.3 轨迹数据

包括：

- 节点开始与结束；
- 路由选择；
- 并行扇出与汇合；
- 工具请求与结果；
- 重试与重排；
- 反思轮次；
- 策略闸；
- 人工批准；
- 交接。

主要用途：检查过程合规、依赖、错误传播、无进展与权限使用。

### 7.4 工件数据

包括：

- 中间文档；
- 最终文档；
- 代码补丁；
- 数据表；
- 报告；
- 计划；
- 摘要；
- 经验条目；
- 候选技能。

主要用途：检查版本、来源、段间契约和修订是否重新受审。

### 7.5 证据数据

包括：

- 数据库快照；
- 规则版本；
- 测试；
- 指标；
- 人工意见；
- 外部回执；
- 搜索结果；
- 文件内容；
- 受控回放与干预结果。

主要用途：判断结论是否真正接入结果信号。

### 7.6 控制与治理数据

包括：

- 风险等级；
- 权限范围；
- 策略版本；
- 验收器版本；
- 人工责任人；
- 停止条件；
- 恢复策略；
- 探针失效策略；
- 数据保留与脱敏规则。

### 7.7 资源数据

包括：

- 时延；
- 模型与工具调用次数；
- 费用；
- 并发；
- 重试；
- 上下文大小；
- 压缩前后大小；
- 存储与网络错误。

资源数据不能替代正确性数据，但可用于发现循环失控、瓶颈和不合理成本。

## 8. 证据可信状态

外部信号不等于绝对正确。探针应保存证据类型与已知盲区，而不是只保存一个分数。

建议使用以下证据状态：

| 状态 | 含义 |
|---|---|
| 权威机械事实 | 来自业务系统、数据库或正式外部回执，且版本与时间有效 |
| 确定性检查结果 | 来自测试、结构校验、参数校验或业务不变量 |
| 版本化规则 | 来自明确版本的政策、字段结构或业务规则 |
| 人工专业判断 | 来自有责任主体的人工审核，可能存在分歧 |
| 模型评分结果 | 适合语义质量与开放内容，存在非确定性与偏好 |
| 叙事声明 | 智能体或用户的自然语言陈述，尚未与机械事实对账 |
| 未知 | 无法取得、无法验证或引用断裂 |
| 冲突 | 多份有效证据相互不一致 |
| 失效 | 超过有效期、版本被撤销或校准失败 |

探针不能简单以“外部来源”作为通过条件，还要检查：

- 谁维护；
- 使用哪个版本；
- 何时获取；
- 是否过期；
- 覆盖什么；
- 不覆盖什么；
- 是否需要人工抽检。

## 9. 探针生命周期

### 9.1 绑定

1. 接收 `RUN_CREATED`；
2. 读取工作流、节点、契约与风险版本；
3. 加载对应探针集；
4. 固定探针与指标版本；
5. 确定必需事件、可选事件和补全权限。

### 9.2 发现

1. 获取事件结构版本；
2. 获取可用机械态接口；
3. 获取证据目录；
4. 获取验收器治理信息；
5. 检查当前环境是否满足探针输入要求。

### 9.3 收集

收集原始事件、工件引用、证据引用、外部回执、快照与人工决策。

收集阶段不做结论覆盖，只产生观察对象。

### 9.4 归一

将不同工具和系统的数据归一为统一对象：

```text
谁
在何时
对哪个对象
使用什么版本与参数
执行了什么动作
得到什么回执
环境终态是什么
证据是什么
```

### 9.5 数据质量检查

检查：

- 必需事件是否缺失；
- 事件是否重复；
- 因果引用是否断裂；
- 时间是否乱序；
- 版本是否缺失；
- 指纹是否一致；
- 证据是否过期；
- 是否存在孤立工件或孤立回执。

### 9.6 关联

将以下对象建立图关系：

```text
目标
→ 节点
→ 决策
→ 动作
→ 回执
→ 工件
→ 证据
→ 验收
→ 环境终态
→ 反思
→ 变更
→ 复验
→ 恢复或交接
```

### 9.7 计算

根据指标定义计算样本。每个样本必须保存：

- 指标版本；
- 分子与分母；
- 适用范围；
- 时间窗口；
- 数据完整状态；
- 维度；
- 原始观察引用；
- 是否可与基线比较。

### 9.8 诊断

将指标与契约、风险和基线结合，产生：

- 数据缺口；
- 契约违反；
- 叙事与终态分歧；
- 越权改变；
- 循环无进展；
- 验收器失效；
- 需要人工判断的冲突。

### 9.9 补全

发现可补全缺口时：

1. 生成证据请求；
2. 检查读取权限；
3. 调用允许的只读接口；
4. 验证来源与版本；
5. 生成独立补全记录；
6. 重新计算受影响指标；
7. 保留补全前后状态。

### 9.10 输出

探针输出不只有指标，还包括：

- 观察；
- 补全记录；
- 发现；
- 告警；
- 放行建议；
- 回放清单；
- 探针自身健康状态。

### 9.11 归档与回放

运行结束后固定：

- 探针版本；
- 指标定义；
- 原始观察；
- 补全记录；
- 发现与建议；
- 被策略闸消费的结果；
- 回放输入；
- 数据缺口与未知。

## 11. 按认知基座划分的探针

### 11.1 感知探针

感知探针关注“智能体看到了什么、没有看到什么、看到的是否仍然有效”。

#### 11.1.1 来源覆盖探针

**探针 ID：** `PROBE_COG_PERCEPTION_SOURCE_COVERAGE`

检查：

- 任务要求的来源是否全部访问；
- 关键结论是否只有单一来源；
- 权威机械源是否缺失；
- 只读到了摘要还是读到了完整对象；
- 多模态对象是否真正解析，而不是只记录文件名。

输出：来源覆盖率、关键来源缺口、未读取对象清单。

#### 11.1.2 时效与版本探针

**探针 ID：** `PROBE_COG_PERCEPTION_FRESHNESS`

检查：

- 证据获取时间；
- 业务有效时间；
- 规则版本；
- 快照版本；
- 引用是否指向当前对象；
- 长程任务中证据是否已经过期。

输出：有效、临近失效、失效、未知。

#### 11.1.3 渐进获取探针

**探针 ID：** `PROBE_COG_PERCEPTION_PROGRESSIVE_DISCOVERY`

用于需要逐层发现的场景，观察：

```text
初始索引
→ 候选对象
→ 深入读取
→ 关键字段
→ 权威终态
```

识别只停在浅层摘要、没有进入关键事实源的情况。

#### 11.1.4 多模态完整性探针

**探针 ID：** `PROBE_COG_PERCEPTION_MULTIMODAL_COMPLETENESS`

检查文本、表格、图片、音频、视频、日志、代码和结构化数据是否被分别处理，并保存解析方式与失败状态。

#### 11.1.5 证据冲突探针

**探针 ID：** `PROBE_COG_PERCEPTION_EVIDENCE_CONFLICT`

当数据库、文件、规则、人工意见或模型提取互相不一致时，不做静默合并，而是形成冲突组与待裁决对象。

---

### 11.2 记忆探针

记忆探针关注“过去是否被正确写入、召回、实际使用，并在结果上产生作用”。

#### 11.2.1 记忆轨迹探针

**探针 ID：** `PROBE_COG_MEMORY_TRACE`

记录完整链路：

```text
应否写入
→ 实际写入
→ 后续召回
→ 是否进入上下文
→ 是否被决策或动作实际使用
→ 任务结果
→ 是否避免重复失败
```

建议事件字段：

```yaml
memory_candidate_id: 候选记忆
should_write: true|false|unknown
write_decision_reason: 原因
memory_record_id: 实际记录或空
retrieved_in_run_ids: []
used_by_decision_ids: []
used_by_action_ids: []
outcome_refs: []
avoided_repeat_failure: true|false|unknown
```

#### 11.2.2 无来源记忆探针

检查记忆条目是否缺少原始轨迹、证据、时间、版本与适用范围。

#### 11.2.3 过期记忆使用探针

检查旧政策、旧工具、旧环境和已废弃技能留下的经验是否仍被召回并实际使用。

#### 11.2.4 记忆信用分配探针

一次任务召回多条经验时，分别记录每条经验是否进入决策或动作，避免把整体成功归功于全部被召回内容。

#### 11.2.5 重复失败探针

观察某类失败是否在已有记忆可用的情况下再次发生，并区分：

- 没有写入；
- 没有召回；
- 召回但未使用；
- 使用但无效；
- 使用后仍因其他原因失败。

---

### 11.3 推理探针

推理探针不要求暴露私密推理过程，而是观察可审计的决策输入、候选、证据、未知和选择结果。

#### 11.3.1 结论—证据连接探针

**探针 ID：** `PROBE_COG_REASONING_CLAIM_EVIDENCE`

检查关键结论是否引用：

- 证据对象；
- 证据版本；
- 证据适用范围；
- 支持或反驳关系。

#### 11.3.2 事实—假设分离探针

**探针 ID：** `PROBE_COG_REASONING_FACT_HYPOTHESIS_SEPARATION`

识别：

- 已确认事实；
- 推断；
- 根因假设；
- 未知；
- 待验证条件。

尤其防止将“发现偏差”升级为“已确认根因”。

#### 11.3.3 目标漂移探针

**探针 ID：** `PROBE_COG_REASONING_GOAL_DRIFT`

比较每次重规划、修订和循环所优化的局部目标，与原始目标契约是否仍一致。

#### 11.3.4 决策可复核探针

检查路由、放行、拒绝、回滚等决策是否保存：

- 候选项；
- 选择结果；
- 使用证据；
- 适用规则；
- 未知与例外。

#### 11.3.5 证据边界探针

识别结论超出证据覆盖范围的情况，例如样本级证据被扩张为全局结论。

---

### 11.4 行动探针

行动探针关注“工具是否经过授权、参数是否正确绑定、外部状态是否真的改变”。

#### 11.4.1 工具准入探针

**探针 ID：** `PROBE_COG_ACTION_TOOL_ADMISSION`

检查：

- 工具是否在允许清单；
- 工具版本是否锁定；
- 权限是否覆盖当前动作；
- 高风险工具是否取得批准；
- 未注册工具是否被临时调用。

#### 11.4.2 参数绑定探针

**探针 ID：** `PROBE_COG_ACTION_PARAMETER_BINDING`

对比：

- 计划参数；
- 实际调用参数；
- 参数指纹；
- 业务对象 ID；
- 时间、金额、收件人、环境等高风险字段。

#### 11.4.3 前置与后置条件探针

**探针 ID：** `PROBE_COG_ACTION_PRE_POST_CONDITION`

检查动作前是否满足准入条件，动作后是否真正达到预期机械状态。

#### 11.4.4 回执完整性探针

**探针 ID：** `PROBE_COG_ACTION_RECEIPT_COMPLETENESS`

识别工具返回“已提交”但没有正式对象 ID、事务 ID、状态或外部回执的情况。

#### 11.4.5 幂等与重复副作用探针

**探针 ID：** `PROBE_COG_ACTION_IDEMPOTENCY`

检查重试是否重复发送通知、重复创建记录、重复扣款或重复发布。

#### 11.4.6 补偿闭环探针

**探针 ID：** `PROBE_COG_ACTION_COMPENSATION`

检查补偿动作是否执行、是否获得回执、是否仍有残余影响。

---

### 11.5 反思探针

反思探针关注“结果是否进入反馈回路、改变是否受权、复验是否独立、循环是否能够停止”。

进入反思后，探针至少应能够关联以下条件必需事件：

```text
REFLECTION_STARTED
REFLECTION_ELIGIBILITY_EVALUATED
REFLECTION_ROUTED
REFLECTION_BASELINE_FROZEN
REFLECTION_ROUND_STARTED
DEVIATION_DETECTED
CHANGE_PROPOSED
CHANGE_AUTHORIZED | CHANGE_REJECTED
CHANGE_APPLIED（仅在授权后）
REVALIDATION_STARTED
REVALIDATION_FINISHED
REFLECTION_ROUND_FINISHED
REFLECTION_STOPPED
```

归因调查发生时，再要求 `ATTRIBUTION_HYPOTHESIS_RECORDED` 与 `ATTRIBUTION_CHECK_FINISHED`。未应用改变的轮次不要求伪造 `CHANGE_APPLIED` 或复验事件，但必须以拒绝、补证据、转人工或不适用等终态闭合。

#### 11.5.1 结果信号覆盖探针

**探针 ID：** `PROBE_COG_REFLECTION_RESULT_SIGNAL_COVERAGE`

检查关键结论中，有多少真正经过：

- 数据库；
- 测试；
- 业务规则；
- 外部回执；
- 人工审核；
- 受控回放或干预。

模型自评不能自动计为外部结果信号。

#### 11.5.2 轨迹与终态分歧探针

**探针 ID：** `PROBE_COG_REFLECTION_TRACE_OUTCOME_DIVERGENCE`

寻找：

- 对话声称完成，环境没有成功记录；
- 轨迹显示跳过审批，最终输出仍称合规；
- 工具返回成功，但数据库状态未改变；
- 报告数字与账本不一致。

#### 11.5.3 汇总掩盖探针

**探针 ID：** `PROBE_COG_REFLECTION_AGGREGATE_MASKING`

检查汇总结果通过时，是否仍存在逐对象、逐记录或逐字段偏差。重点识别：

- 一条多计与一条少计相互抵消；
- 总金额正确但对象归属错误；
- 总数量正确但状态分布错误；
- 汇总规则遗漏冲正、撤销、失败或异常状态；
- 只检查总数，没有保存异常对象清单。

探针输出应区分“汇总级通过”和“明细级通过”，不能用前者替代后者。

#### 11.5.4 错误放行探针

**探针 ID：** `PROBE_COG_REFLECTION_FALSE_APPROVAL`

检查严重问题已被发现后，错误版本是否仍然被批准、发布或交付。

#### 11.5.5 越权改变探针

**探针 ID：** `PROBE_COG_REFLECTION_UNAUTHORIZED_CHANGE`

比较反思契约中的 `allowed_changes` 与实际改变对象。

例如，只允许修改报告文本，却修改了工资账本；只允许生成补丁，却直接发布生产。

#### 11.5.6 无进展循环探针

**探针 ID：** `PROBE_COG_REFLECTION_NO_PROGRESS_LOOP`

比较连续轮次的：

- 失败签名；
- 补丁指纹；
- 未通过验收项；
- 环境终态；
- 新证据；
- 原始目标距离。

同一错误与同一补丁重复出现时，触发停止建议。

#### 11.5.7 基线恢复探针

**探针 ID：** `PROBE_COG_REFLECTION_BASELINE_RECOVERY`

检查自动修复失败后是否完整恢复：

- 文件与代码指纹；
- 配置；
- 数据库；
- 临时资源；
- 外部副作用；
- 回滚后的测试。

#### 11.5.8 经验与技能复用收益探针

**探针 ID：** `PROBE_COG_REFLECTION_REUSE_BENEFIT`

对比引入经验或技能前后的真实任务结果，观察是否提高成功率、降低错误、降低成本或缩短时延。

不得用“曾经成功一次”替代持续复用结果。

#### 11.5.9 新信息增量探针

**探针 ID：** `PROBE_COG_REFLECTION_NEW_SIGNAL_DELTA`

每次反思轮次记录新增：

- 证据；
- 环境状态；
- 测试结果；
- 人工意见；
- 干预结果。

若没有新信息，仅发生文本重写，则标记为低价值重复。

#### 11.5.10 归因证据探针

**探针 ID：** `PROBE_COG_REFLECTION_ATTRIBUTION_EVIDENCE`

将归因状态分为：

```text
未归因
仅有假设
有相关性证据
有受控回放证据
有干预后结果翻转证据
```

探针不替业务定义统一因果标准，只负责防止假设被误写成已证实根因。

#### 11.5.11 反思准入与路由一致性探针

**探针 ID：** `PROBE_COG_REFLECTION_ADMISSION_ROUTING`

检查：

- 触发信号是否绑定具体被审版本；
- 新结果信号或获权取证计划是否真实存在；
- 原始目标、基线、允许改变与复验方式是否完整；
- 缺陷类别是否按版本化路由规则进入生成评审、自愈、补证据、经验回放、技能生命周期或人工分诊；
- 未分类裁定是否被错误地猜测路由。

已通过全部必要验收却仍被强制反思，或没有新信号仍启动新轮次，均产生低价值循环发现。

#### 11.5.12 基线与可比性探针

**探针 ID：** `PROBE_COG_REFLECTION_BASELINE_COMPARABILITY`

比较改变前后的目标版本、对象指纹、样本、时间窗口、风险分层、环境快照与验收口径。任何关键口径变化都必须进入 `non_comparable_reasons`；不可比样本不得计算改善率。

#### 11.5.13 独立复验探针

**探针 ID：** `PROBE_COG_REFLECTION_INDEPENDENT_REVALIDATION`

检查复验是否：

- 绑定改变后的确切对象版本；
- 使用契约要求的工具、模型或人工独立性等级；
- 重新执行全部必要验收，而不是继承旧版本通过状态；
- 将生成用上下文与验收用证据的重叠显式披露；
- 在高风险场景中使用至少一个不受修订器控制的结果信号。

#### 11.5.14 验证器投机探针

**探针 ID：** `PROBE_COG_REFLECTION_VALIDATOR_GAMING`

识别通过以下方式制造“改善”的行为：

- 删除或跳过失败用例；
- 放宽 Schema、规则、阈值或评分提示；
- 缩小分母、排除困难样本或改变采样窗口；
- 只运行最后一个失败检查而跳过完整回归；
- 在反思循环内部未经审批修改验证器；
- 把验证器错误、超时或未运行写成通过。

验证器合法变更必须形成独立提案、版本与审批，并使前后结果标记为不可直接比较。

#### 11.5.15 回归保护探针

**探针 ID：** `PROBE_COG_REFLECTION_REGRESSION_GUARD`

检查改变后原有通过项、硬约束、权限边界、性能下限和高风险业务不变量是否仍成立。局部目标变好但出现阻断级回归时，不得计为有效改善。

#### 11.5.16 反思闭环完整性探针

**探针 ID：** `PROBE_COG_REFLECTION_CLOSURE`

要求每轮可连接：

```text
触发
→ 准入
→ 路由
→ 基线
→ 新结果信号
→ 偏差
→ 变更提案与授权
→ 实际改变
→ 独立复验与回归
→ 终态与停止原因
```

缺少任何必需环节时输出闭环缺口；运行结束后仍处于 `continue`、`change_applied` 或无停止原因的轮次，标记为悬空反思。

#### 11.5.17 混杂因素与改善归因探针

**探针 ID：** `PROBE_COG_REFLECTION_CONFOUNDER_ATTRIBUTION`

记录同一窗口内的其他代码、配置、数据、模型、规则、流量或环境变化。存在多项并发改变、任务分布漂移或样本替换时，允许报告“观察到改善”，但将具体改变的收益归因降级为未知或假设。

最终归因状态必须从轮次观察包顶层 `attribution` 读取，并同时采集 `state`、`hypothesis`、`falsifier`、`confounders`、`evidence_kind` 与累计证据绑定。每次 `attribution_evidence_recorded` 只能晋升一级，新增证据不得与历史归因证据重合。

同时校验 `evidence_authority_ref` 是否属于契约为该等级预先批准的权威集合。受控回放或干预验证若未关联“复验通过、必选通过、回归通过且比较可比”的同轮事件，应降级并阻断强归因声明。

#### 11.5.18 学习晋升证据探针

**探针 ID：** `PROBE_COG_REFLECTION_LEARNING_PROMOTION`

检查经验、规则或技能从候选进入影子运行、有限流量和正式路由时，是否具备：

- 可比任务分层与足够样本；
- 对照或历史基线；
- 成功、回归、风险、人工介入、成本与时延结果；
- 适用范围、有效期、负责人和撤销条件；
- 新版本重新验证记录。

一次成功、结构完整或主观好评，均不足以支持正式晋升。

探针由 `learning_promotion_evaluated` 事件和观察包顶层 `learning_candidate` 共同触发；必须采集候选目标与版本、决定、晋升证据、精确授权器及责任人。运行时无法产出这些字段时，应把探针标记为不可观测并阻断晋升，不得以轮次成功替代学习治理证据。

学习候选还必须绑定来源轮次、来源对象版本和本轮真实证据集合；这些绑定必须能在同轮信号、偏差或复验事件中找到。仅提供若干任意绑定以满足数量要求，不得通过晋升探针。

---

### 11.6 协作探针

#### 11.6.1 交接完整性探针

**探针 ID：** `PROBE_COG_COLLABORATION_HANDOFF_COMPLETENESS`

检查交接是否包含：

- 原始目标；
- 已完成事项；
- 待办事项；
- 工件版本；
- 证据；
- 机械状态；
- 已做决策；
- 风险；
- 权限；
- 接收确认。

#### 11.6.2 责任归属探针

识别一个节点同时有多个“最终责任人”或无人负责的情况。

#### 11.6.3 权限传递探针

检查父层向子层委派时，权限是否隐式扩大。

#### 11.6.4 摘要失真探针

比较交接摘要与原始工件、证据和机械状态，识别摘要遗漏异议、失败或未知。

#### 11.6.5 汇总一致性探针

多分支或多智能体结果汇总时，检查冲突是否被显式处理，而不是被主智能体静默消解。

### 11.7 治理探针

#### 11.7.1 权限范围探针

**探针 ID：** `PROBE_COG_GOVERNANCE_PERMISSION_SCOPE`

检查实际读取、写入、发布和批准是否在既定权限范围内。

#### 11.7.2 策略版本探针

检查运行时使用的策略版本、有效期与适用风险等级。

#### 11.7.3 验收器健康探针

**探针 ID：** `PROBE_COG_GOVERNANCE_VALIDATOR_HEALTH`

检查：

- 负责人；
- 校准记录；
- 回归测试；
- 有效期；
- 已知盲区；
- 业务规则变化后的更新；
- 人工抽检。

#### 11.7.4 审批链完整性探针

检查高风险动作是否经过规定审批，审批对象与实际动作参数是否一致。

#### 11.7.5 数据治理探针

检查敏感字段是否按规则脱敏、保留与访问，同时保证运行关联键未被破坏。

#### 11.7.6 探针失效策略探针

检查探针故障时，工作流是否按照风险策略继续、降级、阻断或转人工，而不是静默忽略。

## 12. 按拓扑基座划分的探针

### 12.1 链式探针

#### 关注对象

- 段间输入输出契约；
- 中间工件；
- 首个失败节点；
- 错误传播范围；
- 下游是否消费未验收工件。

#### 关键探针

| 探针 ID | 作用 |
|---|---|
| `PROBE_TOP_CHAIN_CONTRACT_PASS` | 检查每个段间契约是否签收 |
| `PROBE_TOP_CHAIN_FIRST_FAILURE` | 定位首个真实失败，而非最后一个报错 |
| `PROBE_TOP_CHAIN_ERROR_PROPAGATION` | 计算错误被多少下游节点继续消费 |
| `PROBE_TOP_CHAIN_ARTIFACT_VERSION` | 检查下游消费的工件版本是否正确 |
| `PROBE_TOP_CHAIN_REWORK_SCOPE` | 检查是否只重做受影响子链 |

#### 关键指标

- 段间契约通过率；
- 未验收工件消费率；
- 错误传播距离；
- 首个失败定位成功率；
- 不必要重做率。

---

### 12.2 路由探针

#### 关注对象

- 候选路径；
- 首选路径；
- 选路依据；
- 回退路径；
- 重路由；
- 路由后的真实结果。

#### 关键探针

| 探针 ID | 作用 |
|---|---|
| `PROBE_TOP_ROUTING_FIRST_HIT` | 首次选择是否命中适合的能力或路径 |
| `PROBE_TOP_ROUTING_FALLBACK` | 回退是否按声明路径发生 |
| `PROBE_TOP_ROUTING_CHURN` | 是否在多个路径间反复切换 |
| `PROBE_TOP_ROUTING_UNREGISTERED_TARGET` | 是否路由到未注册能力 |
| `PROBE_TOP_ROUTING_OUTCOME_QUALITY` | 路由选择与真实任务结果的关系 |

#### “首次路由命中率”的准确含义

首次路由命中率指：第一次路由选择是否选中了满足任务、风险、能力和结果要求的正确路径。

它不是模型提示缓存、响应缓存或键值缓存的命中率。

建议公式：

```text
首次路由命中率
= 首次选择无需重路由且最终通过验收的任务数
÷ 发生路由决策的任务数
```

需要同时观察结果质量，不能只因为没有重路由就判定命中。

### 12.3 并行探针

#### 关注对象

- 计划扇出与实际扇出；
- 分支隔离；
- 并发限制；
- 重复副作用；
- 汇合完整性；
- 冲突结果。

#### 关键探针

| 探针 ID | 作用 |
|---|---|
| `PROBE_TOP_PARALLEL_FANOUT_COMPLETENESS` | 计划分支是否全部启动 |
| `PROBE_TOP_PARALLEL_ISOLATION` | 分支是否错误共享可变状态 |
| `PROBE_TOP_PARALLEL_DUPLICATE_SIDE_EFFECT` | 是否发生重复外部动作 |
| `PROBE_TOP_PARALLEL_JOIN_CONSISTENCY` | 汇合是否处理缺失与冲突 |
| `PROBE_TOP_PARALLEL_STRAGGLER` | 慢分支是否拖累关键路径 |

#### 关键指标

- 扇出完成率；
- 分支失败率；
- 重复副作用率；
- 汇合冲突率；
- 慢分支占比；
- 被取消分支残余副作用率。

### 12.4 编排探针

#### 关注对象

- 节点图；
- 依赖；
- 关键路径；
- 计划版本；
- 局部重排；
- 检查点；
- 阻塞节点。

#### 关键探针

| 探针 ID | 作用 |
|---|---|
| `PROBE_TOP_ORCHESTRATION_DEPENDENCY` | 节点启动前依赖是否满足 |
| `PROBE_TOP_ORCHESTRATION_PLAN_DRIFT` | 实际路径与计划版本的差异 |
| `PROBE_TOP_ORCHESTRATION_CRITICAL_PATH` | 关键路径时延与失败 |
| `PROBE_TOP_ORCHESTRATION_BLOCKED_NODE` | 阻塞原因与持续时间 |
| `PROBE_TOP_ORCHESTRATION_CHECKPOINT` | 检查点是否可恢复 |
| `PROBE_TOP_ORCHESTRATION_REPLAN_SCOPE` | 重排是否超出失败子图 |

#### 关键指标

- 依赖违反率；
- 计划漂移率；
- 非必要全局重排率；
- 检查点有效率；
- 阻塞节点平均持续时间；
- 关键路径失败率。

### 12.5 循环探针

#### 关注对象

- 原始目标；
- 每轮输入与证据；
- 失败签名；
- 变更指纹；
- 进展量；
- 预算；
- 停止；
- 恢复。

#### 关键探针

| 探针 ID | 作用 |
|---|---|
| `PROBE_TOP_LOOP_PROGRESS` | 每轮是否减少目标差距 |
| `PROBE_TOP_LOOP_REPEAT_FINGERPRINT` | 是否重复同一错误与变更 |
| `PROBE_TOP_LOOP_BUDGET` | 是否接近或超过轮次、时长、费用预算 |
| `PROBE_TOP_LOOP_STOP_CONDITION` | 停止条件是否生效 |
| `PROBE_TOP_LOOP_GOAL_ANCHOR` | 是否只围绕最后一个报错而忘记原始目标 |
| `PROBE_TOP_LOOP_RECOVERY` | 失败后是否恢复基线 |
| `PROBE_COG_REFLECTION_REGRESSION_GUARD` | 局部改善是否破坏原有通过项或硬约束 |
| `PROBE_COG_REFLECTION_VALIDATOR_GAMING` | 是否通过换尺子、跳检查或缩分母制造通过 |

#### 进展判定

每轮分别记录结果进展与信息进展。

结果进展至少一项发生真实改善：

- 外部红灯减少；
- 通过验收项增加；
- 未解决偏差减少；
- 环境终态更接近目标；
- 修复指纹发生有效变化。

信息进展要求新证据真实排除假设、缩小未知或改变下一步路由；证据数量增加但没有改变可行动知识，不算信息进展。

只有结果进展或受预算约束的信息进展存在，且没有阻断级回归时，循环才可继续。解释更长、不可比口径下分数变化或模型语气更谨慎，不自动算作进展。

#### 关注对象

- 委派目标；
- 权限；
- 子任务工件；
- 交接；
- 汇总；
- 责任边界。

#### 关键探针

| 探针 ID | 作用 |
|---|---|
| `PROBE_TOP_HIERARCHY_DELEGATION_CONTRACT` | 子任务是否有明确契约 |
| `PROBE_TOP_HIERARCHY_PERMISSION_INHERITANCE` | 子层权限是否异常扩大 |
| `PROBE_TOP_HIERARCHY_HANDOFF_LOSS` | 交接中是否丢失目标、证据或风险 |
| `PROBE_TOP_HIERARCHY_AGGREGATION` | 汇总是否忠实反映子任务结果 |
| `PROBE_TOP_HIERARCHY_DEPTH` | 委派层级是否过深并造成不可追踪 |

#### 关键指标

- 委派契约完整率；
- 子层越权率；
- 交接信息损失率；
- 汇总失真率；
- 未确认子任务被写成已完成的比例。

## 13. 核心指标定义

每个指标必须同时定义：

```text
指标要回答的问题
统计对象
分子
分母
时间窗口
维度
数据来源
未知处理
适用场景
不适用场景
风险阈值
已知盲区
```

### 13.1 事件完整率

**指标 ID：** `METRIC_EVENT_COMPLETENESS`

```text
事件完整率
= 实际收到的必需事件类型与实例数
÷ 按工作流和节点状态应产生的必需事件类型与实例数
```

注意：工作流未经过某节点时，不应把该节点事件计入分母。

### 13.2 关联完整率

**指标 ID：** `METRIC_CORRELATION_COMPLETENESS`

```text
关联完整率
= 能通过共同引用键连接到目标、节点、动作、工件或终态的对象数
÷ 应被关联的对象数
```

孤立回执、孤立工件和孤立告警会降低该指标。

### 13.3 结果信号覆盖率

**指标 ID：** `METRIC_RESULT_SIGNAL_COVERAGE`

```text
结果信号覆盖率
= 至少连接一种有效外部结果信号的关键结论数
÷ 需要验证的关键结论总数
```

关键结论必须由目标契约、风险策略或业务模式预先定义，不能在运行结束后只挑容易验证的结论。

### 13.4 叙事—机械分歧率

**指标 ID：** `METRIC_NARRATIVE_MECHANICAL_DIVERGENCE`

```text
叙事—机械分歧率
= 与机械事实不一致的可核验叙事声明数
÷ 已进行机械对账的叙事声明数
```

未对账声明应归入未知，不应计为一致。

### 13.5 轨迹—终态分歧率

**指标 ID：** `METRIC_TRACE_OUTCOME_DIVERGENCE`

```text
轨迹—终态分歧率
= 轨迹声称成功或完成，但环境终态未达到目标的任务数
÷ 已完成终态对账的任务数
```

### 13.6 结论—证据覆盖率

**指标 ID：** `METRIC_CLAIM_EVIDENCE_COVERAGE`

```text
结论—证据覆盖率
= 具有有效证据引用的关键结论数
÷ 关键结论总数
```

该指标只说明“有证据连接”，不自动说明证据足够、正确或无冲突。

### 13.7 错误放行率

**指标 ID：** `METRIC_FALSE_APPROVAL_RATE`

```text
错误放行率
= 已出现阻断级问题但仍被批准或发布的对象数
÷ 已出现阻断级问题的对象总数
```

高风险场景中，分母很小也必须逐例审计，不能只看平均值。

### 13.8 越权改变率

**指标 ID：** `METRIC_UNAUTHORIZED_CHANGE_RATE`

```text
越权改变率
= 超出契约允许改变范围的实际变更数
÷ 实际变更总数
```

没有变更权限记录的动作应标记未知或违规，不能默认授权。

### 13.9 无进展循环率

**指标 ID：** `METRIC_NO_PROGRESS_LOOP_RATE`

```text
无进展循环率
= 命中无进展判定的循环实例数
÷ 已进入两轮及以上的循环实例数
```

建议同时记录无进展轮数、重复失败指纹与重复变更指纹。

### 13.10 基线恢复率

**指标 ID：** `METRIC_BASELINE_RECOVERY_RATE`

```text
基线恢复率
= 自动修复失败后通过独立验证恢复到目标基线的实例数
÷ 触发基线恢复的实例数
```

只执行回滚命令但未验证终态，不计为成功恢复。

### 13.11 技能复用收益

**指标 ID：** `METRIC_SKILL_REUSE_BENEFIT`

建议同时观察：

```text
成功率变化
错误率变化
人工介入变化
费用变化
时延变化
回滚变化
风险事件变化
```

比较对象应尽量保持任务类型、风险和输入难度可比。数据不足时标记“暂不可归因”。

### 13.12 经验复用收益

**指标 ID：** `METRIC_MEMORY_REUSE_BENEFIT`

只有在经验被实际使用并能连接后续结果时，才进入收益统计。

召回但未使用的经验不能算有效，也不能算无效。

### 13.13 段间契约通过率

**指标 ID：** `METRIC_CHAIN_CONTRACT_PASS_RATE`

```text
段间契约通过率
= 通过验收的段间交接次数
÷ 发生段间交接的总次数
```

### 13.14 未验收工件消费率

**指标 ID：** `METRIC_UNVALIDATED_ARTIFACT_CONSUMPTION_RATE`

```text
未验收工件消费率
= 下游实际消费未通过验收工件的次数
÷ 下游工件消费总次数
```

### 13.15 首次路由命中率

**指标 ID：** `METRIC_ROUTING_FIRST_HIT_RATE`

```text
首次路由命中率
= 首次选路无需重路由且最终通过结果验收的任务数
÷ 发生路由的任务数
```

该指标不是模型缓存命中率。

### 13.16 路由抖动率

**指标 ID：** `METRIC_ROUTING_CHURN_RATE`

```text
路由抖动率
= 超过场景允许重路由次数的任务数
÷ 发生路由的任务数
```

### 13.17 并行汇合冲突率

**指标 ID：** `METRIC_PARALLEL_JOIN_CONFLICT_RATE`

```text
并行汇合冲突率
= 汇合时出现无法自动解决冲突的实例数
÷ 发生并行汇合的实例数
```

### 13.18 依赖违反率

**指标 ID：** `METRIC_DEPENDENCY_VIOLATION_RATE`

```text
依赖违反率
= 前置依赖未满足却启动的节点数
÷ 启动节点总数
```

### 13.19 交接完整率

**指标 ID：** `METRIC_HANDOFF_COMPLETENESS`

根据交接契约必需字段计算，不宜只检查是否存在一段摘要文本。

```text
交接完整率
= 已提供且通过验证的必需交接项数
÷ 应提供的必需交接项数
```

### 13.20 验收器有效覆盖率

**指标 ID：** `METRIC_VALIDATOR_VALID_COVERAGE`

```text
验收器有效覆盖率
= 使用未过期、已校准且适用当前风险的验收器所覆盖对象数
÷ 需要验收的对象总数
```

### 13.21 未知终态率

**指标 ID：** `METRIC_UNKNOWN_OUTCOME_RATE`

```text
未知终态率
= 无法确认环境真实终态的任务数
÷ 需要环境终态确认的任务数
```

该指标用于防止“没有数据”被隐藏在成功率中。

### 13.22 补全闭环率

**指标 ID：** `METRIC_ENRICHMENT_CLOSURE_RATE`

```text
补全闭环率
= 已获得有效数据并重新计算相关指标的证据请求数
÷ 已发出的可补全证据请求数
```

### 13.23 探针数据延迟

**指标 ID：** `METRIC_PROBE_DATA_LAG`

记录源事件时间、接收时间、计算时间与告警时间，分别观察延迟。

### 13.24 探针自身错误率

**指标 ID：** `METRIC_PROBE_ERROR_RATE`

```text
探针自身错误率
= 采集、归一、关联或计算失败次数
÷ 探针处理总次数
```

### 13.25 明细对账覆盖率

**指标 ID：** `METRIC_ITEM_LEVEL_RECONCILIATION_COVERAGE`

```text
明细对账覆盖率
= 已完成逐对象、逐记录或逐字段对账的高风险结果对象数
÷ 按场景要求需要明细对账的结果对象数
```

汇总对账完成但明细对账未执行时，不计入分子。该指标用于发现补偿性错误被汇总数字掩盖的风险。

### 13.26 反思准入合规率

**指标 ID：** `METRIC_REFLECTION_ADMISSION_COMPLIANCE`

```text
反思准入合规率
= 触发、被审版本、基线、新信号或取证计划、改变边界、复验与停止条件均完整的已准入反思数
÷ 已进入自动反思的实例数
```

未进入反思且被正确标记为不适用的任务不进入分母。

### 13.27 反思闭环率

**指标 ID：** `METRIC_REFLECTION_CLOSURE_RATE`

```text
反思闭环率
= 具备完整事件链、明确终态和停止原因的反思轮数
÷ 已开始的反思轮数
```

运行结束时仍停留在应用改变、等待复验或无停止原因的轮次不计入分子。

### 13.28 独立复验覆盖率

**指标 ID：** `METRIC_INDEPENDENT_REVALIDATION_COVERAGE`

```text
独立复验覆盖率
= 满足反思契约独立性要求且绑定确切新版本的复验轮数
÷ 已实际应用改变并要求复验的轮数
```

同一执行者自报“已修复”、继承旧版本验证结果或只重读输出，不计入分子。

### 13.29 改善可比覆盖率

**指标 ID：** `METRIC_IMPROVEMENT_COMPARABILITY_COVERAGE`

```text
改善可比覆盖率
= 改变前后目标、样本、窗口、风险分层与验收口径可比的改善评估轮数
÷ 尝试报告改善的轮数
```

口径变化但已明确标记不可比的样本保留为诊断数据，不进入改善率计算。

### 13.30 无回归验证改善率

**指标 ID：** `METRIC_REGRESSION_FREE_VERIFIED_IMPROVEMENT_RATE`

```text
无回归验证改善率
= 达到预设结果改善阈值、独立复验通过、回归护栏通过且未发现验证器投机的轮数
÷ 已完成可比复验的改变轮数
```

该指标说明观察到受验证的改善；若混杂因素未排除，不自动说明改善由某个改变导致。

### 13.31 验证器投机率

**指标 ID：** `METRIC_VALIDATOR_GAMING_RATE`

```text
验证器投机率
= 发现未经授权换尺子、跳检查、缩分母或把错误写成通过的轮数
÷ 已完成验证器完整性检查的改变轮数
```

未检查的轮次标记未知，不得并入“未投机”。高风险场景中任一已确认实例均可直接触发阻断建议。

### 13.32 有效新信号率

**指标 ID：** `METRIC_QUALIFIED_NEW_SIGNAL_RATE`

```text
有效新信号率
= 新信号未被前轮消费且能确认偏差、排除假设、缩小未知或改变路由的反思轮数
÷ 已准入的反思轮数
```

相同证据重复引用、同源文本重写或不可比较的评分波动不计入分子。

### 13.33 归因越级率

**指标 ID：** `METRIC_ATTRIBUTION_OVERCLAIM_RATE`

```text
归因越级率
= 将未归因、假设或仅相关性证据表述为已确认根因的结论数
÷ 包含具体根因声明的结论总数
```

分母为零时标记不适用，不返回零风险结论。

### 13.34 学习晋升证据完整率

**指标 ID：** `METRIC_LEARNING_PROMOTION_EVIDENCE_COMPLETENESS`

```text
学习晋升证据完整率
= 具备任务分层、样本、基线、收益、风险、回归、责任人与撤销条件的经验或技能晋升数
÷ 经验、规则或技能晋升尝试总数
```

一次成功或结构完整但缺少真实复用结果的候选，不计入分子。

## 14. 上下文分诊与压缩扩展指标

以下指标适用于实现了分级上下文获取或语义压缩的工作流，不是所有场景的强制指标。使用前必须在场景定义中说明各级含义和压缩边界。

### 14.1 深层获取触发率

**指标 ID：** `METRIC_LEVEL_3_TRIGGER_RATE`

```text
深层获取触发率
= 触发场景定义的第三级深度读取、校验或高成本获取的任务数
÷ 进入分诊流程的任务数
```

该指标用于观察分诊策略是否过于保守或过于激进，不能脱离成功率和证据覆盖率单独优化。

### 14.2 平均压缩比

**指标 ID：** `METRIC_AVG_COMPRESSION_RATIO`

```text
单次压缩比
= 压缩后有效上下文大小
÷ 压缩前候选上下文大小
```

平均值必须同时配合：

- 关键事实保留率；
- 错误轨迹保留率；
- 证据引用保留率；
- 压缩后任务结果。

压缩越高不代表越好。

### 14.3 每事件错误轨迹保留量

**指标 ID：** `METRIC_ERROR_TRACES_PRESERVED_PER_EVENT`

观察压缩或摘要后，原始失败签名、错误堆栈、拒绝原因、异议和恢复记录是否仍能被引用。

建议同时记录：

```text
原始错误轨迹数
压缩后可追溯错误轨迹数
被完全丢失的关键错误轨迹数
```

### 14.4 交接摘要忠实度

**指标 ID：** `METRIC_HANDOFF_SUMMARY_FIDELITY`

对比交接摘要与原始目标、工件、证据、机械状态、异议和风险，检查摘要是否遗漏关键事实。

## 15. 数据质量探针

可观测性结论只有在输入数据可信时才有意义。

### 15.1 缺失探针

检查按工作流状态应出现但未出现的事件、工件、回执、证据和终态。

### 15.2 重复探针

检查重复事件、重复动作、重复回执、重复补全和重复告警。

### 15.3 乱序探针

区分事件接收顺序与业务发生顺序，识别时钟偏差和延迟到达。

### 15.4 引用完整性探针

检查：

- 工件引用是否存在；
- 证据引用是否存在；
- 验收结果是否指向具体版本；
- 回滚是否指向基线；
- 反思是否指向被审对象。

### 15.5 版本完整性探针

没有定义版本、规则版本、验收器版本或证据版本的数据，不得参与高风险确定性放行。

### 15.6 指纹一致性探针

检查事件声称的文件、参数、补丁或对象版本与实际指纹是否一致。

### 15.7 采样偏差探针

当指标只来自抽样运行时，记录抽样范围、排除规则和缺失群体，避免把局部样本当作全量健康。

### 15.8 数据冲突探针

同一对象出现多个有效但不一致的状态时，保留冲突，不采用“最后写入即真相”的简化规则。

---

## 16. 验收器治理探针

反思依赖外部检查，但检查器本身也可能过期、偏置或覆盖不足。

### 16.1 必需元数据

每个验收器至少应提供：

```yaml
validator_ref: VALIDATOR_XXXX@版本
owner: 负责人
validator_type: 代码与环境检查|模型评分|人工审核|组合
calibration: 校准记录
regression_suite_ref: 回归用例
valid_from: 时间
expires_at: 时间或空
applicable_scope: 适用对象
known_blind_spots: 已知盲区
manual_sampling_policy: 人工抽检
```

### 16.2 治理检查

探针检查：

- 是否有明确维护者；
- 是否超过有效期；
- 业务规则变化后是否更新；
- 回归测试是否通过；
- 模型评分器是否经过校准；
- 人工审核是否存在分歧记录；
- 确定性检查是否只覆盖正常路径；
- 验收器是否被被审对象控制。

### 16.3 三类检查方式的组合

| 检查方式 | 适合对象 | 主要盲区 |
|---|---|---|
| 代码与环境检查 | 字段、状态、测试、参数、业务不变量 | 可能过于僵硬，难处理合法变化 |
| 模型评分 | 语义质量、完整性、开放内容 | 非确定性、自我偏好、需要校准 |
| 人工审核 | 专业责任、模糊边界、高风险决定 | 成本、速度、疲劳和意见分歧 |

探针应记录每个关键结论由哪类检查覆盖，而不是把多个检查器合并成一个不可解释总分。

---

## 17. 数据补全协议

工作流可观测性探针用于补全执行流程数据，但补全必须是可追溯、旁路、可撤销解释的。

### 17.1 可补全的数据

- 缺失的环境终态；
- 外部业务对象状态；
- 动作回执；
- 数据库快照；
- 证据版本与时效；
- 验收器治理元数据；
- 交接接收状态；
- 检查点有效性；
- 回滚后的基线状态；
- 经验是否被实际使用；
- 技能路由后的真实结果；
- 事件之间缺失的关联关系。

### 17.2 不可补全的数据

探针不得凭推断补写：

- 未发生的工具调用；
- 不存在的外部回执；
- 无法访问的数据库结果；
- 未记录的人工批准；
- 未经证据支持的根因；
- 未经验证的成功状态；
- 被删除且无法恢复的原始轨迹。

这些对象必须标记未知、缺失或无法恢复。

### 17.3 补全状态机

```text
identified
→ requested
→ authorized
→ collected
→ verified
→ linked
→ recomputed
→ closed
```

失败分支：

```text
unavailable
conflicted
expired
permission_denied
source_error
not_recoverable
```

### 17.4 补全请求结构

```yaml
evidence_request_id: EVIDENCE_REQUEST_...
run_id: RUN_...
requesting_probe_ref: PROBE_XXXX@版本
subject_ref: 需要补全的对象
missing_fields: []
allowed_sources: []
read_scope: 只读权限范围
reason: 缺口对哪些指标或策略有影响
required_by_gate: true|false
expires_at: 时间或空
```

### 17.5 补全合并规则

执行端或查询端可以在读取时把补全记录与原始事件组合展示，但必须保留：

```text
原始值
补充值
来源
版本
冲突
验证状态
补全时间
```

不得把补充值伪装成原始事件在当时已经存在的字段。

### 17.6 补全示例

原始事件只记录：

```yaml
event_type: TOOL_RESULT
status: success
```

探针发现缺少外部对象 ID 和数据库终态，发出证据请求。读取授权接口后生成：

```yaml
enrichment_id: ENRICHMENT_...
enriches_event_id: EVENT_...
fields_added:
  external_object_id: PAYROLL_BATCH_202606
  database_status: PARTIALLY_REVERSED
  paid_count: 798
  reversed_count: 2
status: 已验证
```

原始 `status: success` 不被删除。探针随后产生“工具成功声明与业务终态分歧”的发现，并建议重新对账。

## 18. 告警与策略闸语义

### 18.1 严重度

| 严重度 | 含义 | 默认动作建议 |
|---|---|---|
| 信息 | 记录趋势或非风险事实 | 继续 |
| 注意 | 存在缺口或轻度偏差 | 补证据或复核 |
| 高风险 | 可能导致错误结果或越权 | 暂停相关节点 |
| 阻断建议 | 已确认严重契约违反或终态分歧 | 阻断、回滚或转人工 |
| 人工必需 | 证据冲突、责任判断或不可逆风险 | 人工接管 |

### 18.2 告警指纹

告警指纹至少包含：

```text
探针 ID
被观测对象
失败签名
规则版本
关键维度
```

用于去重、识别重复循环和统计同类问题。

### 18.3 告警不能等同控制

```text
探针发现
→ 告警或建议
→ 策略闸结合风险与契约
→ 控制决策
→ 执行器执行
```

任何探针不得通过“阻断建议”直接写数据库、发布代码或撤销业务对象。

### 18.4 未知状态的控制建议

| 风险等级 | 关键终态未知时的默认建议 |
|---|---|
| R0 | 允许交付并注明未验证部分 |
| R1 | 补证据，必要时降级结论 |
| R2 | 暂停提交或保留本地状态 |
| R3 | 阻断正式写入或转人工 |
| R4 | 强制阻断 |

### 18.5 反思硬告警

以下情况无需等待统计基线，直接产生阻断建议或人工必需告警：

- 未通过反思准入、未冻结基线或没有改变权限却已经应用改变；
- 新版本未完成必需独立复验却进入接受、发布或正式路由；
- 反思循环内部未经独立审批修改验证器、删除失败用例、跳过必需检查或缩小分母；
- 局部指标改善但硬约束、高风险不变量或原有通过项发生阻断级回归；
- 达到预算、无进展、重复指纹或人工接管条件后仍继续自动循环；
- 在不可比样本上发布确定性改善率，或把相关性、假设写成已确认根因；
- 经验或技能缺少跨运行效果与撤销条件却被提升为正式规则或正式路由；
- 反思运行结束时没有闭合终态与停止原因。

## 19. 与执行流程的交互协议

### 19.1 启动握手

执行器发送：

```text
运行 ID
工作流版本
目标契约
风险等级
节点图
必需验证器
反思准入与路由规则版本
反思基线、可比性与验证器变更策略
探针策略
可读取数据源
探针失效策略
```

探针返回：

```text
已加载探针集
探针与指标版本
缺失输入
预计可覆盖对象
无法观测对象
反思闭环与验证器完整性覆盖范围
需要的只读权限
当前健康状态
```

### 19.2 运行中交互

```text
执行器发出事件
→ 探针确认接收与关联
→ 探针计算初步信号
→ 发现缺口则请求证据
→ 执行器按权限返回数据或拒绝
→ 探针生成补全记录
→ 受影响指标重新计算
→ 探针发出发现与建议
→ 策略闸决定控制动作
```

### 19.3 关键策略闸挂载点

- 任务风险确定后；
- 高风险工具调用前；
- 段间工件签收前；
- 并行结果汇合前；
- 循环进入下一轮前；
- 反思准入与路由决定后；
- 反思变更应用前；
- 反思复验结束、准备接受改善前；
- 自动修复结束前；
- 最终交付或正式发布前；
- 回滚完成后；
- 候选技能进入正式路由前。

### 19.4 探针失效处理

执行器不能临时决定忽略探针。探针失效策略必须在工作流开始前固定：

```yaml
probe_failure_policy:
  R0: continue_with_notice
  R1: continue_with_unknowns
  R2: local_validation_only
  R3: block_or_handoff
  R4: block
```

### 19.5 运行结束交互

执行器提交候选运行摘要后，探针进行最终检查：

- 事件是否完整；
- 关键对象是否关联；
- 终态是否已确认；
- 未知是否显式记录；
- 反思是否闭环；
- 反思改善是否可比、独立复验且无阻断级回归；
- 是否存在验证器投机或归因越级；
- 回滚是否验证；
- 交接是否被接收；
- 验收器是否有效。

探针返回最终观测包，策略闸再决定运行终态。

## 23. 场景探针集

### 23.1 内容生成探针集

#### 必需探针

- 工件版本探针；
- 目标覆盖探针；
- 来源引用探针；
- 生成评审探针；
- 错误放行探针；
- 修订稿重新审查探针。

#### 可选探针

- 多视角并行评审；
- 模型评分器校准；
- 交接摘要忠实度；
- 压缩后关键事实保留。

#### 主要终态

最终工件已冻结、通过适用验收，并明确未验证事实。

---

### 23.2 检索与研究探针集

#### 必需探针

- 来源覆盖；
- 时效与版本；
- 证据冲突；
- 结论—证据连接；
- 事实—假设分离；
- 关键结论结果信号覆盖；
- 未知与证据缺口。

#### 主要风险

只读取摘要、来源过期、单一来源、推断写成事实、引用不能支持结论。

---

### 23.3 代码与持续集成探针集

#### 必需探针

- 基线指纹；
- 补丁指纹；
- 测试版本；
- 计划漂移；
- 循环进展；
- 重复失败与重复补丁；
- 变更范围；
- 基线恢复；
- 验收器健康。

#### 强制策略

自动修复结束前，必须重新运行原始目标相关验收，而不是只运行最后一个失败测试。

---

### 23.4 企业业务写入探针集

#### 必需探针

- 工具准入；
- 参数绑定；
- 权限；
- 审批链；
- 幂等；
- 外部回执；
- 数据库终态；
- 汇总掩盖与明细对账；
- 叙事—机械分歧；
- 越权改变；
- 补偿闭环；
- 未知终态。

#### 强制策略

关键机械终态未知时，不允许仅凭智能体完成声明放行。

---

### 23.5 多智能体探针集

#### 必需探针

- 委派契约；
- 权限传递；
- 子任务工件与证据；
- 交接完整性；
- 摘要失真；
- 汇总冲突；
- 责任归属；
- 层级深度。

#### 主要风险

子任务失败被主智能体摘要掩盖、权限隐式扩大、不同分支冲突被静默合并。

---

### 23.6 反思与自愈探针集

#### 必需探针

- 反思准入与路由一致性；
- 新结果信号增量；
- 结果信号覆盖；
- 基线与可比性；
- 偏差与归因分离；
- 允许改变范围；
- 独立复验；
- 验证器投机；
- 回归保护；
- 反思闭环完整性；
- 混杂因素与改善归因；
- 无进展循环；
- 预算；
- 原始目标锚点；
- 基线恢复；
- 人工交接；
- 学习晋升证据。

#### 强制策略

没有新结果信号、没有停止线或没有恢复基线的循环，不得进入高风险自动执行。验证器在循环内未经独立审批被修改、必要复验未运行、或局部改善伴随阻断级回归时，强制给出阻断或回滚建议。

## 25. 探针自身健康指标

| 指标 | 含义 |
|---|---|
| 探针启动成功率 | 应挂载探针是否成功启动 |
| 必需事件接收率 | 探针是否收到所需事件 |
| 数据延迟 | 从源事件到观察、指标和告警的时间 |
| 关联失败率 | 对象因缺失关联键无法进入计算的比例 |
| 计算失败率 | 指标计算或规则执行失败比例 |
| 补全请求失败率 | 证据请求因权限、来源或结构失败的比例 |
| 告警重复率 | 相同指纹告警未正确去重的比例 |
| 建议消费率 | 放行建议是否被策略闸读取并记录结果 |
| 回放一致率 | 同版本输入下重算结果是否一致 |
| 探针版本过期率 | 运行中使用失效探针的比例 |

探针自身失效必须进入运行摘要，不能因为监控组件出错而继续显示“全部健康”。

## 26. 部署方式

### 26.1 内嵌采集器

执行器内部写出标准事件，适合保证事件完整性。

风险：执行器与探针耦合，探针故障可能影响主流程。

### 26.2 旁路进程

探针作为独立进程订阅事件与只读状态。

优点：隔离、可独立升级、适合实时观察。

### 26.3 集中式观测服务

多个工作流把事件发送到统一服务，适合跨运行、跨技能和跨业务比较。

要求：严格租户、权限、脱敏、版本与保留策略。

### 26.4 离线回放任务

从归档读取运行包，适合事故复盘、规则回归、验证器校准与历史指标重算。

### 26.5 混合方式

推荐组合：

```text
执行器内嵌最小事件采集
+ 旁路实时探针
+ 集中式指标与生命周期分析
+ 离线取证回放
```

不同方式共享同一事件、对象与指标版本语义。

## 27. 数据保留与治理

### 27.1 保留层级

根据风险与用途分别保留：

- 原始事件；
- 机械快照；
- 大对象引用；
- 工件；
- 证据；
- 指标样本；
- 告警；
- 回放材料；
- 审批与人工意见。

### 27.2 敏感数据

探针应尽量使用：

- 对象引用；
- 指纹；
- 脱敏字段；
- 最小必要快照；
- 分级访问。

但不能因为脱敏破坏动作、回执与终态的关联。

### 27.3 删除与更正

删除策略必须区分：

- 原始业务数据；
- 运行事件；
- 补全记录；
- 指标派生数据；
- 审计记录。

更正通过新版本或撤销标记完成，不得静默改写历史结论。

## 28. 探针验收清单

### 28.1 框架一致性

- [ ] 探针是运行时挂载资产，不是第四一级基座；
- [ ] 探针能引用认知、拓扑、矩阵、模式、业务节点和技能；
- [ ] 探针定义与运行实例分离；
- [ ] 所有探针与指标均有稳定 ID 和版本。

### 28.2 独立运行

- [ ] 可读取归档运行包并独立计算；
- [ ] 不依赖执行器在线；
- [ ] 能输出数据缺口、未知和冲突；
- [ ] 能重放同版本指标；
- [ ] 不修改历史原始事件。

### 28.3 交互运行

- [ ] 与执行器共享运行、节点、动作、工件、证据关联键；
- [ ] 能发出证据请求；
- [ ] 补全记录与原始事件分离；
- [ ] 建议经过策略闸才成为控制动作；
- [ ] 探针失效策略在运行前固定；
- [ ] 高风险终态未知时不会静默放行。

### 28.4 数据质量

- [ ] 缺失、重复、乱序、引用断裂、版本缺失均可检测；
- [ ] 未观测与零值分离；
- [ ] 冲突证据被保留；
- [ ] 指标样本保存分子、分母和数据完整状态；
- [ ] 大对象引用可追溯；
- [ ] 事件和补全均有来源与时间。

### 28.5 反思观测

- [ ] 反思触发、被审版本、准入理由与路由规则可追溯；
- [ ] 第二次检查获得的新信息可识别；
- [ ] 改变前基线、验收口径与已通过项已冻结；
- [ ] 偏差与根因归因分离；
- [ ] 允许改变与实际改变可比较；
- [ ] 改变前后可比性与混杂因素被记录；
- [ ] 新版本由满足契约独立性要求的信号重新受审；
- [ ] 验证器变更、跳检、缩分母与规则放宽可检测；
- [ ] 原有通过项和高风险不变量的回归结果可见；
- [ ] 每轮从触发到终态形成完整事件链；
- [ ] 无进展循环可检测；
- [ ] 基线恢复有机械证明；
- [ ] “观察到改善”与“已确认归因”分别表达；
- [ ] 技能与经验晋升连接跨运行真实结果与撤销条件。

### 28.6 验收器治理

- [ ] 验收器有负责人、版本、校准和回归；
- [ ] 验收器有效期可检测；
- [ ] 已知盲区被记录；
- [ ] 代码检查、模型评分和人工审核可分别观察；
- [ ] 被审对象不能控制最终放行检查器。

### 28.7 探针自身健康

- [ ] 探针启动、收集、关联、计算和告警均有健康状态；
- [ ] 探针错误不会被显示为业务成功；
- [ ] 告警可去重；
- [ ] 建议是否被策略闸消费可追踪；
- [ ] 探针版本升级后可离线回归。

## 30. 总结

Hanerss 工作流可观测性探针不是“再加一个批评模型”，而是一套连接运行事实的旁路工程机制。

其标准闭环为：

```text
绑定运行与定义版本
→ 收集事件、工件、证据与机械状态
→ 检查数据质量
→ 关联目标、轨迹与终态
→ 计算指标
→ 识别偏差、缺口与风险
→ 发出证据请求
→ 生成旁路补全记录
→ 重新计算
→ 输出发现、告警与放行建议
→ 由策略闸决定继续、阻断、回滚或转人工
→ 归档并支持回放
```

探针体系最重要的不是指标数量，而是以下能力：

- 能否拿到真实结果信号；
- 能否判断一次反思是否具备准入资格并走到正确处理路径；
- 能否把单轮的触发、基线、改变、复验与终态连接起来；
- 能否区分叙事、自洽与真实终态；
- 能否识别执行流程缺少的数据；
- 能否在不覆盖原始记录的前提下补全数据；
- 能否区分偏差事实与根因假设；
- 能否识别换验证器、跳过回归、缩小分母等“换尺子式改善”；
- 能否区分可比改善、无回归改善与可归因改善；
- 能否识别越权改变和错误放行；
- 能否证明循环取得进展或应当停止；
- 能否证明失败后已经恢复基线；
- 能否验证经验和技能在真实复用中带来收益；
- 能否持续检查验证器与探针自身是否仍然可信。

当执行流程独立运行时，它负责产生稳定、可重放的事实记录；当探针独立运行时，它可以对归档数据进行审计和重算；当两者交互运行时，探针通过证据请求和补全记录完善执行数据，再由策略闸将观测结果转化为受治理的控制决定。
