# 渐进承诺工作流可观测性探针

## 1. 文档定位

本文把“渐进承诺”的可观测指标整理为一套可独立运行、也可与执行流程交互运行的工作流可观测性探针。

探针不只是展示图表。它需要回答下面这些可审计问题：

- 当前 Agent 对哪项能力处于什么等级？
- 当前等级绑定的是哪个 Agent、模型、策略和工具版本？
- 一次任务是否按低风险到高风险的顺序推进？
- 每次真实外部效果是否检查了具体能力凭证？
- 晋级使用了哪一批证据？证据是否唯一、有效、多样且可核验？
- 审批人批准的证据批次和最终签发凭证是否一致？
- 事故发生后，旧凭证何时失效，执行点何时开始拒绝？
- 权限扩大以后，人工纠正、回滚和事故是否增加？
- 哪些必要数据没有被执行流程记录，能否从权威来源补全？

本探针负责：

1. 采集渐进承诺执行流程的事件、工件、回执和状态快照。
2. 重建单次任务钟表和跨任务权限钟表。
3. 检查凭证、范围、证据、晋级、降级和人工责任边界。
4. 计算可解释、可复算的指标。
5. 发现数据缺口、版本错配、证据污染和执行点边界泄漏。
6. 从权威来源补全观测数据。
7. 输出发现、告警、时间线、数据缺口单、证据补全包和治理建议。

本探针不负责：

- 直接执行付款、发信、写库或部署。
- 直接签发、扩大或吊销权限凭证。
- 用推断结果覆盖权威业务事实。
- 删除失败记录或修改历史证据。
- 代替审批者承担晋级或重大例外责任。

## 2. Hanerss 框架映射

### 2.1 基座映射

| 基座 | 本探针中的含义 |
|---|---|
| 认知基座 | 以治理为主，观测权限、证据、审批、事故和责任边界 |
| 拓扑基座 | 以链式为主，重建从请求到凭证变化的前后关系 |
| 工程模式基座 | 将渐进承诺的观测、核验和补全能力封装为可复用探针 |

### 2.2 主坐标

```text
COG_GOVERNANCE__TOP_CHAIN
```

探针必须重建下面的治理链：

```text
任务请求
→ 能力识别
→ 凭证校验
→ 单次任务阶梯
→ 真实外部效果
→ 业务验收
→ 运行结果
→ 证据窗口
→ 晋级或降级决定
→ 凭证签发或吊销
```

### 2.3 扩展坐标

```text
COG_GOVERNANCE__TOP_LOOP
```

探针还需要跨多次运行计算趋势，观察权限扩大后的真实表现，并判断事故后是否建立了新的证据基线。

### 2.4 源数据与视图

按照“注册表是源数据、矩阵和报表是视图”的原则：

- 能力注册表、权限策略、凭证状态、业务终态和原始事件是源数据。
- 权限地图、晋级漏斗、证据矩阵、趋势图和事故时间线是派生视图。
- 探针发现和指标不得反向覆盖源数据。
- 补全数据必须保留来源、验证状态、摘要和补全者。

## 3. 探针与执行流程的职责分离

| 对象 | 执行流程 | 工作流可观测性探针 |
|---|---|---|
| 业务动作 | 负责执行或阻断 | 只观测，不执行 |
| 权限判断 | 负责正式判断 | 检查判断是否存在、是否一致 |
| 凭证签发 | 负责签发和吊销 | 检查签发依据和传播结果 |
| 运行结果 | 负责生成和入账 | 检查唯一性、完整性和可核验性 |
| 证据窗口 | 负责正式维护 | 重建、核对并发现污染或缺口 |
| 晋级审批 | 负责提交和决策 | 检查审批权、证据批次和目标范围 |
| 事故降级 | 负责冻结、吊销和恢复 | 检查时延、覆盖面和旧凭证拒绝情况 |
| 数据补全 | 接纳已核验补全 | 发现缺口并从权威来源形成补全包 |
| 治理建议 | 决定是否采纳并执行 | 提出建议，不直接改权限 |

### 3.1 不可跨越的边界

探针输出的任何指标、评分、风险等级或建议，都不能直接成为外部动作授权。

正式权限变化必须经过：

```text
探针发现或建议
→ 执行流程验证
→ 正式治理动作
→ 有权审批或事故控制
→ 凭证签发或吊销
→ 执行点生效
```

---

## 4. 两种运行方式

## 4.1 独立运行

探针可以不接入实时执行流程，直接读取：

- 历史日志。
- 事件流归档。
- 权限凭证快照。
- 审批记录。
- 业务回执。
- 证据窗口导出。
- 事故记录。
- 工具调用和执行适配器日志。

独立运行适合：

- 上线前审计。
- 历史事故还原。
- 现有系统治理体检。
- 从日志判断是否真正执行了渐进承诺。
- 为尚未接入探针的流程生成基线报告。

独立运行时，探针只输出报告、发现和补全包，不影响在线权限。

## 4.2 交互运行

探针可以订阅执行流程事件，在运行中持续检查：

- 关键事件是否缺失。
- 凭证是否有效。
- 阶梯是否被跳过。
- 请求是否超过受限范围。
- 晋级证据是否发生变化。
- 严重事故后旧凭证是否仍被使用。

交互运行时，探针可以近实时返回：

- 数据缺口单。
- 高优先级发现。
- 已核验证据补全包。
- 建议暂停晋级、缩小范围、触发人工复核或启动事故流程。

探针仍然不能直接执行治理动作。

## 5. 探针架构

```text
数据源适配层
  ↓
事件标准化层
  ↓
身份与关联层
  ↓
运行史重建层
  ↓
规则探针层
  ↓
指标计算层
  ↓
数据质量与缺口层
  ↓
补全与核验层
  ↓
报告、告警与治理建议层
```

### 5.1 数据源适配层

负责接入执行流程、权限服务、审批服务、业务系统、证据账本和事故系统。

### 5.2 事件标准化层

把不同来源的时间、状态、对象和字段转换为统一事件契约，同时保留原始引用。

### 5.3 身份与关联层

使用 `trace_id`、`run_id`、`task_id`、`credential_id`、`capability_id`、`evidence_ref` 和摘要建立关系。

### 5.4 运行史重建层

分别重建：

- 单次任务钟表。
- 跨任务权限钟表。
- 晋级申请时间线。
- 凭证生命周期。
- 事故和恢复时间线。

### 5.5 规则探针层

执行不变量检查、权限检查、证据检查、顺序检查和责任边界检查。

### 5.6 指标计算层

生成可复算指标，并保留分子、分母、过滤条件、时间窗口和维度。

### 5.7 数据质量与缺口层

判断哪些结论可信、哪些需要补全、哪些只能标记为推断。

### 5.8 补全与核验层

从权威来源取回缺失事实，形成带来源、摘要和验证状态的补全包。

### 5.9 输出层

输出：

- 运行重建报告。
- 指标快照。
- 探针发现。
- 数据缺口单。
- 证据补全包。
- 告警。
- 治理建议。

## 6. 数据来源与可信优先级

### 6.1 建议数据源

| 数据源 | 主要内容 |
|---|---|
| 能力注册表 | 能力定义、版本、允许动作和永久人工确认规则 |
| 权限策略库 | 等级规则、证据要求、限额和事故策略 |
| 权限凭证存储 | 当前凭证、历史凭证、签发和吊销状态 |
| 执行拦截点日志 | 每次真实外部效果前的凭证和组合闸检查 |
| 审批系统 | 晋级审批、动作审批、审批者权限和决定理由 |
| 证据账本 | 运行结果、证据窗口、去重和验证结果 |
| 业务事实源 | 付款、发信、写库、部署等真实终态 |
| 工具调用日志 | 调用开始、结束、参数摘要、幂等键和错误 |
| 事故系统 | 事故等级、冻结、吊销、恢复和影响范围 |
| 人工复核系统 | 改判、纠正、回滚和例外处理 |

### 6.2 事实可信优先级

对“业务是否成功”的判断建议采用：

```text
权威业务终态
> 独立对账或回执
> 受信验证器
> 人工复核结果
> 受信监控和测试
> 执行器自报
> 推断
```

对“权限是否有效”的判断建议采用：

```text
凭证签发和吊销源
> 执行拦截点实际校验结果
> 权限缓存快照
> 执行器自报等级
```

### 6.3 冲突处理

当多个来源冲突时：

1. 不覆盖原始记录。
2. 记录冲突双方和时间。
3. 使用可信优先级选择临时主结论。
4. 标记为“冲突待核验”。
5. 生成数据缺口单或人工复核任务。
6. 在冲突关闭前，不把该记录计为晋级成功证据。

## 7. 共享事件契约

探针优先消费执行流程的统一事件信封：

```yaml
event_id: EVT_唯一标识
trace_id: TRACE_链路标识
run_id: RUN_运行标识
task_id: TASK_业务任务标识
parent_event_id: 上游事件标识
pattern_id: PATTERN_GOVERNANCE_0003
skill_id: 执行技能标识
agent_id: Agent 标识
agent_version: Agent 版本
model_version: 模型版本
policy_version: 策略版本
credential_id: 权限凭证标识
capability_id: 能力标识
environment: 运行环境
tenant_id: 租户或业务域
step_id: 执行节点
occurred_at: 业务发生时间
recorded_at: 记录时间
event_type: 事件类型
status: 状态
source_system: 来源系统
source_refs: []
evidence_refs: []
payload_digest: 内容摘要
data_quality:
  completeness: 完整度
  confidence: 置信等级
  verification: 核验状态
```

### 7.1 探针附加字段

探针不得改写原事件，只能创建派生记录：

```yaml
probe_record_id: 探针记录标识
source_event_ids: []
reconstruction_status: 原始或重建或推断
join_method: 关联方法
rule_ids: []
metric_ids: []
finding_ids: []
confidence: 高或中或低
verified_by: 核验者
created_at: 创建时间
```

### 7.2 最小关联键

| 关联对象 | 首选键 | 备用键 |
|---|---|---|
| 单次运行 | run_id | task_id + 主体 + 时间窗口 |
| 完整链路 | trace_id | 业务对象 + 请求摘要 + 时间窗口 |
| 凭证 | credential_id | 主体 + 能力 + 签发时间 + 摘要 |
| 能力 | capability_id | 工具动作 + 业务动作映射 |
| 证据 | evidence_ref | 内容摘要 + 来源 + 发生时间 |
| 晋级申请 | promotion_request_id | 主体 + 能力 + 目标等级 + 证据摘要 |
| 事故 | incident_id | 运行 + 能力 + 事故时间 |

使用备用键时必须标记为“重建”，不能伪装成原始确定关系。

## 8. 探针运行流程

本探针定义十三个逻辑节点。

```text
P01 加载注册表、策略与版本
  ↓
P02 接收事件、快照和工件
  ↓
P03 标准化与保留原始引用
  ↓
P04 身份解析、去重与链路关联
  ↓
P05 数据完整性和可信度检查
  ↓
P06 重建单次任务钟表
  ↓
P07 重建跨任务权限钟表
  ↓
P08 检查凭证与执行点边界
  ↓
P09 检查证据窗口与晋级批次
  ↓
P10 检查事故、降级与恢复
  ↓
P11 计算指标和趋势
  ↓
P12 生成缺口、补全包、发现和建议
  ↓
P13 输出报告、告警和交互回执
```

## 9. 十三个探针节点

### P01 加载注册表、策略与版本

**目标**：锁定本次探针运行的解释基线。

**加载内容**：

- 能力注册表。
- 权限等级定义。
- 证据要求。
- 事故规则。
- 永久人工确认清单。
- 指标口径版本。
- 数据源可信优先级。

**输出**：探针策略快照。

**失败处理**：策略缺失时只做数据盘点，不下治理结论。

---

### P02 接收事件、快照和工件

**目标**：采集所有可能还原运行史的数据。

**要求**：

- 保留来源系统。
- 保留原始时间和记录时间。
- 保留原始内容摘要。
- 不因字段缺失丢弃整条记录。
- 对重复到达的数据执行幂等接收。

---

### P03 标准化与保留原始引用

**目标**：统一状态、时间、标识和对象描述。

**动作**：

1. 映射事件类型。
2. 统一时间格式。
3. 统一权限等级和凭证状态。
4. 映射能力和工具动作。
5. 保存标准化前后的双向引用。

探针不得为了方便统计而删除无法映射的原始值。

---

### P04 身份解析、去重与链路关联

**目标**：识别同一运行、同一凭证、同一证据和同一晋级申请。

**检查**：

- `event_id` 是否重复。
- `run_id` 是否被复用。
- 相同 `evidence_ref` 是否出现在多个成功条目中。
- 内容摘要相同但标识不同的疑似重复。
- 关联键缺失导致的孤立事件。

**输出**：关联图和重复候选集。

---

### P05 数据完整性和可信度检查

**目标**：先判断“能否相信数据”，再计算治理结论。

**检查**：

- 必需事件是否存在。
- 必需字段是否存在。
- 来源是否权威。
- 事件顺序是否合理。
- 时间是否严重漂移。
- 摘要是否一致。
- 业务终态是否可解析。
- 核验者是否受信。

**输出**：数据质量评分、缺口和可信等级。

---

### P06 重建单次任务钟表

**目标**：还原一次任务是否从低风险动作逐步走向真实外部效果。

**重建内容**：

```text
只读确认
→ 提案或草稿
→ 规则检查
→ 演练
→ 影子
→ 受限真实执行
→ 当前权限内扩大
```

**发现示例**：

- 未经过演练直接写生产。
- 影子级出现生产写入。
- 受限级超过对象数或金额上限。
- 真实执行前没有组合闸回执。
- 外部效果先发生，凭证校验后补记。

---

### P07 重建跨任务权限钟表

**目标**：还原主体在具体能力上的等级变化。

**重建内容**：

```text
观察级
→ 建议级
→ 影子级
→ 受限级
→ 自主级
```

同时重建：

- 每一级开始时间。
- 支持该等级的证据批次。
- 审批者。
- 凭证版本。
- 范围变化。
- 降级、冻结和恢复。

---

### P08 检查凭证与执行点边界

**目标**：确认真实外部效果受到具体能力凭证约束。

**检查项**：

- 每次真实执行是否有凭证。
- 凭证是否在动作发生前校验。
- 主体、版本、能力、环境和租户是否匹配。
- 凭证是否过期、吊销或被替代。
- 请求是否超限。
- 是否命中永久人工确认清单。
- 审批、预算、爆炸半径和幂等回执是否齐全。

**最高优先级发现**：未授权外部效果已经发生。

---

### P09 检查证据窗口与晋级批次

**目标**：确认晋级确实由合格证据支持。

**检查项**：

- 运行编号和证据引用唯一。
- 证据发生在当前版本和策略下。
- 证据仍在有效期内。
- 任务切片和风险覆盖达到要求。
- 业务结果经过独立核验。
- 没有未关闭阻断性失败。
- 证据批次在审批前后摘要一致。
- 晋级目标与最终凭证范围一致。

---

### P10 检查事故、降级与恢复

**目标**：判断“出事先收权”是否真正发生。

**检查项**：

- 事故发现到冻结的时延。
- 冻结到凭证吊销的时延。
- 吊销通知到执行点生效的时延。
- 在途动作停止、回滚或补偿情况。
- 旧凭证是否仍被成功使用。
- 事故前证据是否被违规复用。
- 恢复是否从新基线重新积累证据。
- 是否逐级恢复，而非直接回到原最高等级。

### P11 计算指标和趋势

**目标**：生成可解释、可复算的指标。

每个指标必须保留：

```text
指标标识
指标名称
口径版本
时间窗口
维度
分子
分母
过滤条件
数据源
数据质量
计算时间
```

没有分母或数据质量不足时，不得展示为精确百分比。

### P12 生成缺口、补全包、发现和建议

**输出类型**：

- 数据缺口单。
- 证据补全包。
- 探针发现。
- 指标异常。
- 治理建议。
- 待人工核验清单。

**独立模式输出**：完整报告和离线补全包。

**交互模式输出**：

- 高优先级告警。
- 缺口请求。
- 补全包。
- 建议动作。
- 探针运行回执。

报告必须支持从结论下钻到原始事件和权威来源。

## 10. 探针深度等级

### 10.1 一级：存在性探针

回答：该记录是否存在？

例如：

- 是否有凭证校验事件。
- 是否有业务验收回执。
- 是否有晋级审批记录。
- 是否有凭证吊销通知。

### 10.2 二级：一致性探针

回答：记录之间是否一致？

例如：

- 执行时能力是否与凭证能力一致。
- 审批目标范围是否与签发范围一致。
- 业务终态是否与执行器自报一致。
- 证据批次摘要是否变化。

### 10.3 三级：治理重建探针

回答：能否完整还原一次权限判断和权限变化？

例如：

- 为什么这次允许执行？
- 为什么这次晋级？
- 为什么事故后降级？
- 哪一版凭证在何时失效？

### 10.4 四级：趋势与风险探针

回答：权限变化是否带来新的风险？

例如：

- 晋级后人工纠正率是否上升。
- 受限范围扩大后事故率是否增加。
- 某类任务切片长期缺少证据。
- 探针补全数据是否成为常态，说明执行流程记录能力不足。

四个等级可以分阶段建设，但未达到三级时，不应声称系统具备完整治理可审计性。

## 12. 指标口径总则

### 12.1 指标不是授权依据

指标用于观测、评估和触发治理流程，不能单独授权外部动作。

### 12.2 指标必须可复算

每个百分比必须保存分子和分母；每个时延必须保存起止事件；每个计数必须可下钻到原始记录。

### 12.3 指标按能力和版本分维度

至少支持按下列维度切分：

- Agent。
- Agent 版本。
- 模型版本。
- 策略版本。
- 能力。
- 权限等级。
- 环境。
- 租户或部门。
- 工具。
- 任务切片。
- 风险等级。
- 时间窗口。

禁止把不同能力、版本和环境混成一个总成功率后用于晋级判断。

### 12.4 阈值分三类

| 类型 | 说明 | 示例 |
|---|---|---|
| 不变量阈值 | 必须为零或百分之百 | 未授权外部效果必须为零，真实执行凭证检查覆盖率必须为百分之百 |
| 策略阈值 | 由能力、等级和业务风险配置 | 最少证据数、覆盖切片数、最长证据年龄 |
| 趋势阈值 | 根据历史基线和变化幅度判断 | 晋级后人工纠正率明显上升 |

通用探针不把某个业务的金额、人数或成功次数写死在代码中。

## 22. 零容忍不变量

下列指标出现非零值时，应至少产生最高或高优先级发现：

```text
无凭证外部效果次数
未授权外部效果次数
吊销后旧凭证成功执行数
永久人工确认绕过成功数
跨租户越权次数
影子级真实写入次数
证据批次变化后继续签发次数
审批者无权却成功批准次数
探针直接修改权限次数
推断事实用于正式授权次数
父子委派越界次数
```

下列覆盖率原则上应为百分之百：

```text
真实执行凭证检查覆盖率
需审批动作的审批回执完整率
需限额动作的爆炸半径回执完整率
用于晋级证据的可解析率
批准后证据摘要一致率
新凭证与批准范围一致率
吊销凭证拒绝率
```

如业务无法达到，应明确记录例外、责任人、补偿控制和截止日期，而不是静默降低指标口径。

## 23. 数据缺口与补全规则

### 23.1 数据状态

探针为每个关键事实标记一种状态：

| 状态 | 含义 | 可否用于正式晋级 |
|---|---|---|
| 原始已核验 | 执行流程或权威系统直接提供，且已验证 | 可以 |
| 补全已核验 | 探针从权威来源取得并通过验证 | 可以 |
| 重建关系 | 通过稳定键重建事件关系，事实本身未改变 | 视具体字段决定 |
| 待核验 | 来源存在但尚未完成独立验证 | 不可以 |
| 推断 | 根据时间、内容或统计关系推断 | 不可以 |
| 冲突 | 多来源不一致 | 不可以 |
| 缺失 | 未找到可用数据 | 不可以 |

### 23.2 可以补全的内容

- 缺失的权威业务终态。
- 缺失的审批记录引用。
- 缺失的凭证签发或吊销记录引用。
- 缺失的证据核验状态。
- 缺失的事件关联关系。
- 缺失的来源、摘要和记录时间。
- 缺失的执行点校验回执。

### 23.3 不能仅靠推断补全的内容

- 正式权限等级。
- 凭证是否有效。
- 业务是否真正成功。
- 审批者是否已经同意。
- 事故是否已经关闭。
- 永久人工确认是否完成。
- 某条证据是否可用于晋级。

这些内容必须回到权威来源或正式治理记录。

### 23.4 补全优先级

```text
影响未授权外部效果判断的缺口
> 影响事故收权判断的缺口
> 影响晋级合法性判断的缺口
> 影响业务成功判断的缺口
> 影响趋势和效率分析的缺口
```

- 通过正式人工核查得出结论。
- 策略确认该字段在此场景不适用。

“超过时间没有处理”不能自动视为关闭。

```yaml
urgency: 立即或高或常规
status: 待处理或已转治理或已拒绝或已完成
governance_action_ref: 正式治理动作引用
```

探针建议只有转化为正式治理动作后，才可以影响权限状态。

## 28. 独立运行输出

独立运行至少输出以下内容：

1. 数据源清单和采集范围。
2. 数据质量报告。
3. 主体—能力—权限等级地图。
4. 单次任务钟表重建结果。
5. 跨任务权限钟表重建结果。
6. 凭证生命周期和执行点检查情况。
7. 证据窗口质量和覆盖矩阵。
8. 晋级申请与审批一致性。
9. 事故、降级和恢复时间线。
10. 指标快照和趋势。
11. 零容忍不变量检查结果。
12. 数据缺口单。
13. 可验证的证据补全包。
14. 探针发现和治理建议。

独立运行报告必须说明：

- 时间范围。
- 数据源范围。
- 未接入系统。
- 不能验证的结论。
- 推断比例。
- 指标口径版本。

## 29. 与执行流程交互闭环

### 29.1 标准闭环

```text
执行流程产生原始事件
  ↓
探针接收并标准化
  ↓
探针重建运行史
  ↓
发现缺口或不一致
  ↓
探针查询权威来源
  ↓
生成补全包、发现和建议
  ↓
执行流程验证并接纳已核验补全
  ↓
正式治理流程处理建议
  ↓
执行流程产生新的权限或事故事件
  ↓
探针继续验证是否真正生效
```

### 29.2 执行流程应提供的接口

- 事件订阅或事件导出。
- 能力注册表读取。
- 策略版本读取。
- 凭证状态读取。
- 运行结果和证据窗口读取。
- 晋级申请和审批读取。
- 事故状态读取。
- 补全包接纳回执。
- 治理建议处理状态。

### 29.3 探针应提供的接口

- 数据缺口单输出。
- 证据补全包输出。
- 探针发现输出。
- 指标查询。
- 运行史重建查询。
- 治理建议输出。
- 告警确认和关闭回执。

### 29.4 交互失败时的降级方式

探针不可用时：

- 执行流程继续依靠自身正式控制运行。
- 不得因缺少探针而跳过凭证、审批或限额。
- 暂停依赖探针补全才能成立的晋级申请。
- 保留本地事件，待探针恢复后补采。

执行流程不可用时：

- 探针继续保存已接收数据。
- 标记链路中断。
- 不推断业务成功或权限变化。
- 恢复后执行补采和对账。

## 30. 场景化探针配置

### 30.1 付款与结算

重点探针：

- 人数和金额上限。
- 单笔与批次限额。
- 收款账户变更。
- 重复付款和幂等。
- 银行回执与内部调用结果差异。
- 冲正和补偿。
- 部门、租户和预算信封。

重点指标：

```text
未授权付款次数
重复付款次数
收款账户变更人工确认覆盖率
权威银行回执覆盖率
金额超限拦截率
事故后旧付款凭证拒绝率
```

### 30.2 发信与消息触达

重点探针：

- 收件人范围。
- 模板版本。
- 敏感信息。
- 发送额度。
- 退订和发送时段。
- 影子运行是否真的没有发送。

重点指标：

```text
错误收件人率
重复发送次数
敏感信息泄露次数
批量发送限额拦截率
影子级真实发送次数
全员公告人工确认覆盖率
```

### 30.3 数据库写入

重点探针：

- 表、字段、租户和行数。
- 事务和回滚点。
- 删除与更新区别。
- 批次拆分。
- 跨租户扫描和写入。

重点指标：

```text
超行数写入次数
跨租户写入次数
无事务写入次数
回滚成功率
不可恢复删除人工确认覆盖率
旧凭证写入拒绝率
```

### 30.4 代码与发布

重点探针：

- 仓库、分支、服务、环境和区域。
- 测试、预生产和金丝雀步骤。
- 流量比例和扩大条件。
- 错误率、延迟和回滚。

重点指标：

```text
跳过测试发布次数
跳过小流量直接全量次数
流量超限次数
异常后自动回滚率
发布凭证检查覆盖率
晋级后生产事故率变化
```

### 30.5 客服与退款

重点探针：

- 单笔金额和日累计。
- 客户等级和退款原因。
- 重复申请。
- 欺诈或争议转人工。
- 账户关闭等永久人工确认动作。

重点指标：

```text
重复退款次数
错误账户退款次数
超额退款拦截率
争议转人工准确率
账户关闭自动执行次数
受限级扩大后的人工纠正率变化
```

### 30.6 多 Agent 层级委派

重点探针：

- 父凭证和子凭证关系。
- 子任务范围。
- 子 Agent 版本。
- 委派时间和有效期。
- 结果回收和责任归属。

重点指标：

```text
子权限超父权限次数
委派凭证过期后执行次数
子任务超范围次数
子结果未回收率
父级责任链缺失率
```

## 31. 建议视图

### 31.1 当前权限地图

按主体、能力、环境和租户展示：

- 当前等级。

- 生效和过期时间。
- 人数、金额、对象数和工具上限。


### 31.3 证据覆盖矩阵

- 证据数量。
- 成功与失败。
- 来源。
- 验证者。
- 新鲜度。
- 环境和版本。

### 31.4 单次任务阶梯视图

按时间展示：

- 只读。
- 提案。
- 演练。
- 影子。
- 受限真实执行。
- 扩大范围。
- 每一道闸和回执。

### 31.5 事故与收权时间线

- 例外转人工准确率。
- 处理时长。

## 32. 告警策略

### 32.1 立即告警

- 未授权外部效果。
- 吊销凭证继续成功。
- 跨租户写入。
- 永久人工确认动作被自动完成。
- 影子级真实写入。
- 探针直接改写权限。
- 晋级凭证超出批准范围。

### 32.2 高优先级告警

- 真实执行缺少凭证检查事件。
- 证据批次审批前后不一致。
- 无权审批者批准。
- 事故后未及时冻结或吊销。
- 用事故前证据申请恢复。
- 晋级后事故或人工纠正显著上升。

### 32.3 常规告警

- 数据缺口长期未关闭。
- 任务切片覆盖不足。
- 证据即将过期。
- 探针补全依赖率持续偏高。
- 例外队列积压。

### 32.4 告警抑制与合并

同一根因产生大量重复事件时，应按：

```text
主体 + 能力 + 凭证 + 根因 + 时间窗口
```

合并告警，但不能隐藏受影响对象数和影响范围。

---

## 33. 数据保留与隐私

### 33.1 最小化采集

探针优先采集：

- 标识。
- 摘要。
- 状态。
- 范围。
- 回执引用。
- 时间。

只有在核验必需时才读取完整业务内容。

### 33.2 敏感数据处理

- 对身份、账户、工资、客户信息等敏感内容使用脱敏或引用。
- 探针输出报告默认不复制完整敏感载荷。
- 补全包应只包含完成核验所需的最小字段。
- 探针访问权不得大于其观测职责所需范围。

### 33.3 保留周期

保留周期应按以下对象分别配置：

- 原始事件。
- 派生事件。
- 指标明细。
- 聚合指标。
- 证据补全包。
- 事故记录。
- 凭证和审批历史。

与权限晋级、事故和法律责任相关的记录，不应因普通日志轮转提前丢失。

---

## 34. 探针自身治理

探针也必须被治理。

### 34.1 探针版本

每次输出必须记录：

- 探针版本。
- 规则版本。
- 指标口径版本。
- 数据源版本。
- 运行时间。

### 34.2 规则变更

规则变更后：

- 新旧报告不得无说明直接比较。
- 必要时重算历史窗口。
- 重大规则变化应经过评审。
- 零容忍不变量不得被普通配置静默关闭。

### 34.3 探针权限

探针默认只读。需要写入缺口单、补全包或发现时，应写入独立观测数据面。

任何探针身份直接修改：

- 权限等级。
- 凭证状态。
- 业务终态。
- 审批结果。

都应触发“探针越权”发现。

### 34.4 探针失效

探针不可用时，执行流程的正式控制仍须工作。探针不是授权链上的单点依赖。

---

## 35. 探针失败与降级

| 失败类型 | 处理方式 |
|---|---|
| 数据源不可用 | 标记来源缺失，保留重试队列，不推断正式事实 |
| 事件格式无法解析 | 保存原始记录，生成格式缺口 |
| 关联键缺失 | 尝试重建并标记低置信；无法确定时保持孤立 |
| 时间严重漂移 | 降低顺序和时延指标可信度，生成时钟告警 |
| 来源冲突 | 保留冲突，不计入正式晋级证据 |
| 指标分母未知 | 输出数量和缺口，不展示精确比例 |
| 补全包被拒绝 | 保留拒绝理由，修正后重新提交，不覆盖原事实 |
| 规则执行失败 | 标记该探针未运行，不把“无发现”当作“无问题” |
| 探针积压 | 优先处理未授权外部效果、事故收权和晋级合法性相关事件 |

---

## 36. 验收测试

### 36.1 数据质量测试

1. 缺少 `run_id` 的事件应被保留并生成缺口，而不是丢弃。
2. 相同 `event_id` 重复到达不得重复计数。
3. 相同证据摘要使用不同标识时，应进入疑似重复集合。
4. 多来源时间冲突时，应保留原始时间并标记时钟问题。
5. 分母未知时，不得输出伪精确百分比。

### 36.2 单次任务钟表测试

1. 真实执行先于凭证校验时，必须产生严重发现。
2. 影子级出现生产写入时，必须产生严重发现。
3. 跳过要求的演练或小范围步骤时，必须记录跳步。
4. 超限请求被正确阻断时，应计入超限拦截率。
5. 工具成功但业务失败时，应计入机械成功误判率。

### 36.3 证据窗口测试

1. 相同 `run_id` 不得重复计入。
2. 相同 `evidence_ref` 不得重复计入。
3. 旧版本证据进入新版本窗口时，应标记版本失配。
4. 单一简单切片占比过高时，应生成覆盖不足发现。
5. 未经受信验证的证据不得被标记为合格晋级证据。
6. 评审期间新增失败时，探针应判断旧申请失效。

### 36.4 晋级与凭证测试

1. 审批者权限不足时，应产生审批权不匹配发现。
2. 新凭证范围超过批准范围时，应产生超签发发现。
3. 批准后证据摘要变化时，应产生批次不一致发现。
4. 新凭证生效后旧凭证仍有效时，应产生双凭证窗口发现。
5. 跨级晋升没有策略依据时，应产生晋级路径违规发现。

### 36.5 事故与收权测试

1. 严重事故后没有冻结事件，应产生高优先级发现。
2. 吊销后旧凭证成功执行，应产生严重发现。
3. 事故前证据被用于恢复晋级，应产生恢复证据污染发现。
4. 直接从观察级恢复到自主级，应产生恢复路径违规发现。
5. 事故只影响单一能力却无理由全局停机，应标记为可能过度收权，供治理评估。

### 36.6 探针边界测试

1. 探针写入权限状态应被检测并阻断。
2. 推断事实进入正式晋级证据应被检测。
3. 补全包来源摘要不一致时，执行流程应拒绝，探针记录拒绝原因。
4. 探针不可用时，执行流程仍能执行正式权限控制。
5. 执行流程恢复后，探针可以补采并重建中断时间线。

## 39. 示例：一条完整观测链

```text
任务请求进入
→ 识别为“小额退款”能力
→ 读取受限级凭证
→ 检查客户、金额、日累计和工具范围
→ 检查动作审批与额度回执
→ 使用幂等键提交退款
→ 工具返回成功
→ 支付系统返回已退款终态
→ 独立对账确认金额和账户
→ 生成运行结果
→ 进入证据窗口
→ 达到晋级申请条件
→ 锁定证据批次
→ 审批者批准目标范围
→ 再次核对证据摘要
→ 签发新凭证并替代旧凭证
```

探针应能够回答：

- 每一步是否存在。
- 顺序是否正确。
- 使用了哪一版凭证。
- 真实业务是否成功。
- 证据是否唯一和已核验。
- 审批范围是否与新凭证一致。
- 旧凭证是否已经失效。

若其中任何关键记录缺失，探针应生成数据缺口单，而不是假装链路完整。

## 40. 实施结论

渐进承诺的可观测性不是“看成功率”，而是还原一条可以追责和复核的运行史：

```text
谁
在什么版本和策略下
使用哪项具体能力
持有什么范围的凭证
经过了哪些单次任务步骤
产生了什么真实外部效果
业务结果是否被独立核验
哪些结果进入了证据窗口
谁批准了哪一批证据
最终签发了什么凭证
事故后何时冻结、吊销并建立新基线
```

本探针可以独立读取历史数据完成审计，也可以与执行流程交互运行，持续补全事件、业务终态和证据关系。

两套系统联动时应保持稳定分工：

```text
执行流程负责事实动作、权限判断和状态变化
探针负责观测、核验、重建、补全和建议
```

探针补全的是执行流程的数据，不是执行流程的责任；探针发现的是边界问题，不是自动获得修改边界的权力。
