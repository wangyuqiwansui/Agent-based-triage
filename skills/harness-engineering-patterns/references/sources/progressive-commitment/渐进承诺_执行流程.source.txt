# 渐进承诺执行流程

## 1. 文档定位

本文把“渐进承诺”整理为一套可直接实现、可独立运行、可与工作流可观测性探针联动的通用执行流程。

渐进承诺解决的不是“是否相信整个 Agent”，而是下面这个更具体的问题：

> 某个版本的 Agent，在某项能力、某个环境、某个业务范围和某组限制下，已经积累了哪些可核验证据，因此当前允许它独立做到哪一步？

本流程负责：

1. 识别当前任务需要使用的具体能力。
2. 读取并校验当前能力凭证。
3. 在一次任务内按“低成本、可撤销、窄范围”逐步推进。
4. 在多次任务之间积累经过核验的运行证据。
5. 根据证据申请逐级晋权。
6. 在严重事故、证据失效或版本变化后立即收权。
7. 在真正产生外部效果之前强制执行权限检查。
8. 输出完整事件、工件、回执和状态变化，供审计或探针使用。

本流程不负责替代审批门、预算限制或爆炸半径控制。三者的分工如下：

| 控制 | 核心问题 |
|---|---|
| 审批门 | 眼前这一项动作是否已经由有权人员批准 |
| 爆炸半径控制 | 即使动作出错，最多影响多少对象、资源、金额和时间 |
| 渐进承诺 | 当前这个 Agent 是否有资格承担这种能力和范围的任务 |

三种控制应当在执行点叠加，而不是互相替代。

## 2. Hanerss 框架映射

### 2.1 三大基座映射

| 基座 | 本模式中的含义 |
|---|---|
| 认知基座 | 以治理为主，处理权限、证据、审批、降级和责任边界 |
| 拓扑基座 | 以链式为主，前一步检查通过后才允许进入下一步 |
| 工程模式基座 | 将渐进放权、证据晋级、事故收权封装为可复用工程模式 |

### 2.2 主坐标与扩展坐标

主坐标：

```text
COG_GOVERNANCE__TOP_CHAIN
```

原因：一次任务中的动作阶梯、跨任务的权限阶梯、晋级审核与凭证签发都具有明确的前后依赖。

扩展坐标：

```text
COG_GOVERNANCE__TOP_LOOP
```

原因：多次运行结果会反复进入证据窗口，影响下一轮权限，形成“运行—核验—记账—评估—放权或收权”的闭环。

### 2.3 在框架中的资产关系

```text
认知注册表 + 拓扑注册表
        ↓
治理 × 链式坐标
        ↓
渐进承诺工程模式
        ↓
执行流程技能化
        ↓
具体业务场景实例
```

工程模式注册表是模式元数据的源头；矩阵是模式归属的视图；本文是工程模式的执行化产物。

## 3. 适用场景

本模式适用于会改变外部世界、且权限应随证据逐步扩大的能力，例如：

- 付款、退款、报销和资金调拨。
- 发信、批量通知、营销触达和客户回复。
- 写数据库、修改配置、删除资源和变更账户。
- 生成补丁、合并代码、部署测试环境和生产发布。
- 创建订单、修改订单、取消订单和自动采购。
- 工单处理、客户补偿、账户限制和风控处置。
- 调用高成本工具、使用敏感数据或访问生产系统。
- 多 Agent 系统中对子 Agent 的分层委派。

不适合直接使用本模式替代人工责任的场景：

- 法律、纪律、人事处分等必须由责任人作出的决定。
- 不可恢复删除且无法建立可靠补偿路径的动作。
- 重要收款账户、身份、证件或受益人变更。
- 企业明确规定必须由人确认的重大例外。
- 无法获取真实业务结果、无法独立核验成功与否的任务。

这些场景仍可使用渐进承诺准备材料、做影子运行或有限预处理，但最终动作必须保留人工确认。

## 4. 核心原则

### 4.1 信任绑定具体能力

权限不得笼统发给“整个 Agent”，必须至少绑定：

```text
Agent 身份
Agent 版本
模型版本
策略版本
能力标识
环境
租户或业务域
可用工具
数据范围
金额、人数、对象数或流量上限
有效时间
例外规则
```

查询订单的成功记录，不能自动证明关闭账户的能力；测试环境的成功记录，不能直接证明生产环境能力；旧模型的成绩，不能自动继承给新模型。

### 4.2 两只钟表分开运行

第一只钟表发生在一次任务内：

```text
读取 → 分析 → 提案 → 演练 → 影子 → 小范围真实执行 → 扩大范围
```

第二只钟表发生在多次任务之间：

```text
观察级 → 建议级 → 影子级 → 受限级 → 自主级
```

单次演练通过，只允许当前任务继续推进；不会自动带来长期晋级。

长期达到自主级，也不代表高风险任务可以跳过单次任务中的校验、审批和限额。

### 4.3 晋权慢，收权快

晋级必须经过：

```text
证据积累 → 证据核验 → 覆盖检查 → 观察期 → 晋级审批 → 新凭证签发
```

严重事故发生时应优先止损：

```text
冻结相关能力 → 吊销凭证 → 阻断新动作 → 隔离影响 → 再做调查
```

### 4.4 权限在执行点生效

权限判断必须出现在真正执行付款、发信、写库、部署等动作的执行点。

不能只在规划阶段检查，也不能只依赖提示词、Agent 自报等级或一个“已可信”布尔值。

### 4.5 证据必须来自外部可核验结果

可晋级证据应尽量来自：

- 测试结果。
- 银行回执。
- 工单终态。
- 人工改判记录。
- 回滚结果。
- 生产监控结果。
- 独立评测器输出。
- 真实业务对账结果。

工具返回“调用成功”不等于业务成功，Agent 自己给出的评分不能单独作为晋级依据。

### 4.6 自主不等于无边界

自主级只表示：在已经批准的常规范围内，不必每一步都等待人工点击。

绝对限额、租户隔离、敏感动作、重大例外、不可逆动作和永久人工确认清单仍然有效。

## 5. 权责边界

### 5.1 角色划分

| 角色 | 主要职责 | 禁止事项 |
|---|---|---|
| 任务执行器 | 读取任务、生成计划、调用工具、提交结果 | 不得自行签发或扩大权限 |
| 权限控制器 | 解析当前等级、范围和凭证，决定请求是否可进入执行 | 不得伪造业务结果 |
| 执行拦截点 | 在产生外部效果前校验能力凭证和组合闸 | 不得绕过拒绝结果 |
| 证据记录器 | 把核验后的运行结果写入证据窗口 | 不得重复记账或覆盖原记录 |
| 独立验证器 | 验证证据引用、业务终态和记录来源 | 不得由被评估 Agent 自己替代 |
| 晋级审批者 | 判断是否接受某一批锁定证据和目标权限 | 不得批准超出自身授权范围的晋级 |
| 凭证签发者 | 根据已批准的晋级决定签发新凭证并吊销旧凭证 | 不得绕过审批或签发未批准范围 |
| 事故控制器 | 发现严重事故后冻结、降级、吊销和隔离 | 不得由普通调用者随意触发全局降级 |
| 业务事实源 | 提供真实业务终态、回执和对账结果 | 不得被探针推断覆盖 |
| 工作流可观测性探针 | 采集、重建、核验、补全观测数据并提出建议 | 不得直接修改权限或业务事实 |

### 5.2 四个数据平面

| 数据平面 | 内容 | 写入权 |
|---|---|---|
| 业务事实面 | 付款、发信、写库、部署等真实业务结果 | 业务系统及受信适配器 |
| 权限状态面 | 当前等级、能力范围、凭证状态、晋级和降级记录 | 权限控制器、签发者、事故控制器 |
| 观测数据面 | 事件、指标、链路、缺口、重建结果和质量标记 | 执行流程、探针 |
| 治理决策面 | 审批、拒绝、例外、晋级、降级和责任签名 | 有权人员或受信治理服务 |

探针可以补全观测数据面，但不能通过“推断”修改业务事实面或权限状态面。

## 7. 五级权限阶梯

| 等级 | 可执行内容 | 必须保留的限制 | 典型证据 |
|---|---|---|---|
| 观察级 | 读取允许的数据、识别对象、核对版本、发现信息不足并停止 | 默认只读；不能生成外部效果 | 数据定位正确率、版本识别、缺失信息阻断能力 |
| 建议级 | 生成提案、草稿、差异、风险说明和建议动作 | 人工采用后才可执行；不得直接写生产 | 提案完整性、金额和对象准确率、异常识别率 |
| 影子级 | 在真实任务旁并行运行，与人工或权威结果对照 | 输出隔离；只读凭证；不得触发真实写入 | 与真实结果差异、误报漏报、异常处理一致性 |
| 受限级 | 在明确部门、租户、对象数、金额、工具和时间范围内产生真实效果 | 组合闸、限额、幂等、回滚和例外转人工 | 小范围真实执行成功、重复请求控制、超时和并发稳定性 |
| 自主级 | 在批准的日常范围内独立完成常规任务 | 绝对上限、重大例外、永久人工确认清单仍然有效 | 长期稳定结果、事故率、人工纠正率、回滚率和扩大权限后的表现 |

### 7.1 等级不是单一数字

同一个 Agent 可以同时拥有：

```text
订单查询：自主级
退款提案：影子级
小额退款：受限级
关闭账户：无权限
修改收款账户：永久人工确认
```

因此，权限存储必须以“主体 × 版本 × 能力 × 环境 × 范围”为基本键，而不是只保存一个总等级。

### 7.2 冻结状态

“冻结”不是第六级，而是一个高优先级控制状态。

处于冻结状态时：

- 不得发起新的真实执行。
- 当前未完成动作应按策略取消、回滚或转人工。
- 旧凭证立即失效。
- 只允许事故调查、只读核查和恢复验证所需动作。

## 8. 两只钟表

### 8.1 单次任务钟表

单次任务从低成本、可撤销动作走向高成本、难撤销动作：

```text
只读确认
  ↓
生成草稿
  ↓
规则检查
  ↓
演练或预演
  ↓
影子运行
  ↓
小批次真实执行
  ↓
扩大到当前凭证允许的范围
```

每一步必须定义：

- 进入条件。
- 输入版本。
- 输出工件。
- 验收条件。
- 风险上限。
- 失败后的停止点。
- 回滚或补偿方式。

### 8.2 跨任务钟表

跨任务钟表使用证据窗口推动权限变化：

```text
观察级
  ↓ 经过核验的数据定位和阻断证据
建议级
  ↓ 经过核验的提案和异常识别证据
影子级
  ↓ 与真实结果对照并覆盖目标风险
受限级
  ↓ 小范围真实执行且外部效果稳定
自主级
```

晋级通常只能相邻进行。跨级晋升必须被策略明确允许，并要求更高强度的评测、审批和观测。

### 8.3 两只钟表不能互相冒充

禁止下列推理：

- “这次演练成功，所以长期权限自动晋级。”
- “已经是自主级，所以这次可以跳过演练、审批或限额。”
- “在一百笔小额任务中成功，所以具备大额整批能力。”
- “查询能力稳定，所以写入能力也可信。”

## 9. 运行时状态机

### 9.1 模式资产状态

遵循框架通用状态：

```text
草稿 → 待评审 → 已启用 → 已废弃 → 已归档
```

### 9.2 权限凭证状态

```text
草稿 → 有效 → 过期
          ├→ 吊销
          └→ 被替代
```

### 9.3 晋级申请状态

```text
证据收集中
  ↓
达到申请条件
  ↓
证据批次锁定
  ↓
待评审
  ├→ 批准 → 待签发 → 已签发
  ├→ 拒绝
  └→ 失效
```

等待评审期间出现新失败、证据变化、策略变更、版本变更或事故时，申请必须转为“失效”，不得继续沿用旧批准。

### 9.4 单次运行状态

```text
已接收
  ↓
已建模
  ↓
已校验
  ↓
已过闸
  ↓
执行中
  ├→ 已完成
  ├→ 已阻断
  ├→ 已失败 → 已补偿
  └→ 已冻结
```

机械成功和业务成功必须分开记录。工具返回成功，只能说明调用完成，不能替代业务结果核验。

## 10. 执行流程总览

本流程定义十五个逻辑节点。节点可以落在同一服务中，也可以分布在权限服务、业务服务、审批服务和审计服务中。

```text
F01 初始化与版本锁定
  ↓
F02 请求建模
  ↓
F03 能力与范围识别
  ↓
F04 风险与不可逆性分类
  ↓
F05 当前权限凭证解析
  ↓
F06 永久人工确认规则检查
  ↓
F07 单次任务阶梯编排
  ↓
F08 执行前组合闸
  ↓
F09 低风险与可撤销动作执行
  ↓
F10 影子、演练或受限真实执行
  ↓
F11 业务结果核验
  ↓
F12 运行结果记账
  ↓
F13 证据窗口评估
  ↓
F14 晋级、降级或冻结决策
  ↓
F15 凭证签发、吊销与闭环
```

---

## 11. 十五个执行节点

### F01 初始化与版本锁定

**目标**：为本次运行锁定不可模糊的身份、版本和策略基线。

**输入**：

- 任务请求。
- Agent 身份与版本。
- 模型版本。
- 策略版本。
- 能力注册表。
- 当前时间与环境。

**动作**：

1. 生成 `trace_id`、`run_id` 和 `task_id`。
2. 锁定本次运行使用的 Agent、模型、策略和能力定义版本。
3. 读取业务环境、租户和数据域。
4. 记录初始化事件。

**输出**：运行上下文快照。

**阻断条件**：

- 版本不可解析。
- 策略已废弃。
- 身份签名无效。
- 环境或租户未知。

---

### F02 请求建模

**目标**：把自然语言或业务调用转换成可校验动作请求。

**最小字段**：

| 字段 | 含义 |
|---|---|
| action_id | 本次动作标识 |
| requested_capability | 请求能力 |
| target_objects | 目标对象 |
| requested_effect | 准备产生的外部效果 |
| requested_scope | 数量、金额、租户、数据和时间范围 |
| reversibility | 是否可撤销、可回滚或可补偿 |
| urgency | 紧急程度 |
| source_refs | 输入事实和工件引用 |
| requested_by | 请求者 |

**输出**：标准动作请求。

**阻断条件**：能力、对象、效果或范围无法确定。

---

### F03 能力与范围识别

**目标**：确认本次任务具体使用哪项能力，防止用低风险能力的信誉替高风险能力背书。

**动作**：

1. 将动作映射到唯一或最小能力集合。
2. 为复合任务拆分多个能力检查。
3. 解析环境、租户、工具、数据和资源范围。
4. 检查是否存在能力定义冲突。

**输出**：能力范围请求。

**阻断条件**：

- 能力未注册。
- 一个动作同时命中互斥能力。
- 任务范围超出系统可描述能力。

---

### F04 风险与不可逆性分类

**目标**：确定本次任务应使用怎样的单次任务阶梯和控制强度。

**风险维度**：

- 外部效果大小。
- 是否可撤销。
- 涉及金额、人数、对象数或流量。
- 数据敏感度。
- 法律、人事、合规后果。
- 跨租户或跨环境影响。
- 工具副作用。
- 重试、并发和重复请求风险。
- 是否属于永久人工确认动作。

**输出**：风险等级、不可逆性等级和控制要求。

---

### F05 当前权限凭证解析

**目标**：取得当前主体对具体能力的有效凭证。

**必须检查**：

- 主体和版本匹配。
- 模型版本匹配。
- 策略版本匹配。
- 能力匹配。
- 环境和租户匹配。
- 凭证处于有效状态。
- 当前时间在有效期内。
- 凭证没有被替代或吊销。
- 请求范围不超过凭证范围。

**输出**：权限解析结果和凭证快照。

**拒绝时输出**：明确拒绝原因，不得退化为模糊的“权限不足”。

---

### F06 永久人工确认规则检查

**目标**：识别即使处于自主级也不能自动执行的动作。

**动作**：

1. 读取企业级永久人工确认清单。
2. 读取能力级、租户级和场景级例外清单。
3. 检查请求是否命中敏感对象、敏感字段或重大金额。
4. 若命中，生成审批请求并停止自动执行。

**输出**：

- 未命中：继续。
- 命中：人工确认需求和责任主体。

---

### F07 单次任务阶梯编排

**目标**：根据任务风险、凭证等级和能力性质，生成本次任务的推进阶梯。

**示例**：

```text
读取输入
→ 校验版本
→ 生成提案
→ 规则检查
→ 演练
→ 影子对照
→ 20 个对象真实执行
→ 当前凭证上限内扩大
```

每个阶梯步骤至少包含：

```text
step_id
输入契约
输出契约
进入条件
验收条件
允许副作用
最大影响范围
超时
幂等键规则
失败策略
补偿动作
```

**输出**：单次任务执行计划。

---

### F08 执行前组合闸

**目标**：在真实外部效果之前，将所有独立控制合并检查。

**组合闸至少包含**：

1. 渐进承诺凭证检查。
2. 审批门检查。
3. 爆炸半径或预算信封检查。
4. 工具许可检查。
5. 数据和租户隔离检查。
6. 幂等键检查。
7. 并发和重试限制。
8. 业务前置条件检查。
9. 回滚或补偿可用性检查。

组合闸采用“全部通过才放行”的原则。

**输出**：每一道闸的独立回执和组合结论。

---

### F09 低风险与可撤销动作执行

**目标**：优先完成成本低、可检查、可撤销的动作。

**典型动作**：

- 读取数据。
- 生成草稿。
- 计算差异。
- 执行静态检查。
- 运行测试。
- 生成模拟请求。
- 建立回滚点。

**要求**：

- 不得提前产生超出当前阶段的外部效果。
- 每个输出应形成可引用工件。
- 失败应在进入高风险步骤前被发现。

---

### F10 影子、演练或受限真实执行

**目标**：根据当前权限等级选择允许的最大执行形态。

| 当前等级 | 最大允许形态 |
|---|---|
| 观察级 | 只读和识别 |
| 建议级 | 提案和草稿 |
| 影子级 | 隔离输出的真实输入并行运行 |
| 受限级 | 凭证范围内的小批次真实执行 |
| 自主级 | 凭证范围内的常规真实执行 |

**关键要求**：

- 影子级不得因工具配置错误写入生产。
- 受限级必须在执行点再次检查人数、金额、对象数和工具范围。
- 自主级遇到例外条件必须转人工或退回受限步骤。
- 每次真实执行必须带幂等键和凭证标识。

---

### F11 业务结果核验

**目标**：确认业务是否真正完成，而不是只看工具调用状态。

**核验来源优先级**：

1. 权威业务终态。
2. 独立对账或回执。
3. 独立验证器。
4. 人工复核结果。
5. 受信监控和测试结果。
6. Agent 自报结果，仅作辅助。

**核验内容**：

- 对象是否正确。
- 金额或数据是否正确。
- 是否重复执行。
- 是否存在遗漏。
- 是否触发异常或回滚。
- 是否出现人工纠正。
- 是否超出当前范围。

**输出**：业务验收回执。

---

### F12 运行结果记账

**目标**：生成不可重复计数、可核验、可追溯的运行结果。

**动作**：

1. 生成 `RunOutcome`。
2. 对 `run_id`、`evidence_ref` 和内容摘要去重。
3. 记录成功、失败、阻断、事故和人工纠正。
4. 绑定运行时凭证、策略和版本。
5. 写入追加式证据账本。

**禁止事项**：

- 同一次成功多次计数。
- 删除失败记录以提高晋级率。
- 用不同描述包装同一证据重复提交。
- 用测试结果替代生产结果而不标记环境。

---

### F13 证据窗口评估

**目标**：判断当前证据是否足以支持下一档权限。

**评估维度**：

- 数量是否达到要求。
- 运行和证据是否唯一。
- 证据是否仍在有效期内。
- 是否产生于当前版本和当前策略下。
- 是否覆盖要求的任务切片。
- 是否覆盖目标范围、目标金额和目标风险。
- 是否经过受信验证器核验。
- 是否存在阻断性失败或未关闭事故。
- 放权后的人工纠正、回滚和事故是否增加。

**输出**：

- 继续积累。
- 已达到申请条件。
- 证据薄弱。
- 证据过期。
- 证据失配。
- 因失败或事故重置。

---

### F14 晋级、降级或冻结决策

**晋级路径**：

```text
锁定证据批次
→ 生成晋级申请
→ 审批者核对目标能力和范围
→ 批准或拒绝
→ 批准后再次核验证据摘要
```

**降级路径**：

- 轻微质量回退：限制范围、延长观察、暂停晋级。
- 持续人工纠正或回滚增加：降至前一等级。
- 严重事故：立即冻结相关能力，必要时降至观察级。
- 模型、策略或关键工具变化：旧证据按策略失效，权限回到安全基线。

**禁止事项**：

- 自动跨级晋升。
- 审批后证据变化仍沿用旧批准。
- 使用无权审批者的签名。
- 将一个能力的事故无差别扩散到全部能力，除非事故表明主体整体失控。

---

### F15 凭证签发、吊销与闭环

**晋级成功时**：

1. 签发新凭证。
2. 记录批准、证据批次和目标范围。
3. 将旧凭证标记为被替代。
4. 通知所有执行拦截点刷新权限缓存。
5. 开启新等级下的证据基线。

**降级或冻结时**：

1. 吊销相关凭证。
2. 发布吊销通知。
3. 阻断后续动作。
4. 标记新的证据基线时间。
5. 隔离事故前成绩，禁止直接用于恢复权限。

**闭环输出**：

- 最终运行报告。
- 权限状态变化。
- 业务验收回执。
- 组合闸回执。
- 证据窗口更新结果。
- 可观测事件包。

---

## 12. 晋级规则

### 12.1 基本晋级条件

一项晋级申请必须同时满足：

```text
目标等级与当前等级相邻
且
主体、能力、版本、环境、租户和策略一致
且
证据数量达到策略要求
且
运行编号与证据引用不重复
且
证据在有效期内
且
覆盖目标任务切片和目标风险
且
验证者受信
且
没有未关闭的阻断性失败或严重事故
且
证据批次已锁定
且
有权审批者批准
且
批准后证据摘要未变化
```

### 12.2 证据覆盖矩阵

准备开放多大权限，就必须先覆盖相应风险。

| 目标权限 | 最低应覆盖内容 |
|---|---|
| 建议级 | 对象识别、金额或参数计算、输入缺失阻断、提案完整性 |
| 影子级 | 真实输入、真实任务分布、人工结果对照、异常样本 |
| 受限级 | 写入、超时、并发、重试、重复请求、回滚、限额边界 |
| 自主级 | 扩大范围后的真实结果、长期稳定性、重大例外转人工、事故与恢复演练 |

### 12.3 证据窗口锁定

进入评审后，应保存：

```text
证据条目集合
条目顺序
每条内容摘要
窗口策略版本
目标权限范围
整个窗口摘要
```

等待审批期间发生下列任一情况，旧申请自动失效：

- 新增失败或事故。
- 证据条目被撤销。
- Agent、模型、工具或策略版本变化。
- 目标范围变化。
- 证据窗口过期。
- 审批者权限变化。

### 12.4 晋级审批只批准具体范围

审批对象不是“让 Agent 更聪明”，而是一份明确能力凭证：

```text
允许哪个主体
在什么版本下
使用哪项能力
在什么环境和租户中
调用哪些工具
处理什么对象
最多影响多少
有效多久
遇到哪些例外必须停下
```

## 13. 快速降级与事故收权

### 13.1 严重事故触发条件

可配置的严重事故包括：

- 未授权外部效果已经发生。
- 使用吊销、过期或被替代凭证成功执行。
- 跨租户、跨环境或跨能力越权。
- 永久人工确认动作被自动执行。
- 超出金额、人数、对象数或流量上限。
- 重复执行造成真实损失。
- 业务结果被篡改或证据被伪造。
- 无法停止的连续写入或连续发布。
- 造成重大法律、合规、人事或安全后果。

### 13.2 收权顺序

```text
发现或确认事故
  ↓
冻结相关能力
  ↓
吊销当前凭证
  ↓
通知执行拦截点
  ↓
阻断新请求
  ↓
取消、回滚或补偿在途动作
  ↓
确定受影响范围
  ↓
建立事故后新基线
  ↓
进入恢复验证
```

### 13.3 精准收权

默认只收回与事故相关的：

- 能力。
- 环境。
- 租户。
- 工具。
- 资源范围。
- 版本。

当事故表明主体整体失控、凭证系统失效或版本不可再信任时，才扩大到全局冻结。

### 13.4 恢复权限

事故前成绩不能直接用于恢复。恢复至少要求：

1. 问题原因已确认。
2. 修复版本或新策略已生效。
3. 旧凭证已经吊销。
4. 新基线之后重新产生证据。
5. 事故场景和相邻风险场景重新评测。
6. 恢复审批通过。
7. 从安全等级逐步晋级，不直接恢复原最高等级。

---

## 14. 执行点强制校验

每个产生外部效果的适配器必须执行下面的最小校验：

```text
主体是否匹配
主体版本是否匹配
能力是否匹配
环境和租户是否匹配
工具动作是否匹配
凭证是否有效
凭证是否被吊销或替代
策略是否仍然有效
请求范围是否在限额内
是否命中永久人工确认清单
审批门是否通过
爆炸半径或预算是否可用
幂等键是否有效
当前动作是否属于单次任务允许阶段
```

任何一个外部效果适配器缺少凭证校验，都视为边界泄漏。

禁止以下实现：

```text
if agent_trusted:
    execute()
```

推荐的判断对象是具体能力凭证，而不是笼统可信标记。

## 15. 共享事件契约

执行流程与探针交互时使用统一事件信封。执行流程独立运行时也应尽量输出同样结构，便于后续接入探针。

```yaml
event_id: EVT_唯一标识
trace_id: TRACE_链路标识
run_id: RUN_运行标识
task_id: TASK_业务任务标识
parent_event_id: 上游事件标识
pattern_id: PATTERN_GOVERNANCE_0003
skill_id: 当前执行技能标识
agent_id: Agent 标识
agent_version: Agent 版本
model_version: 模型版本
policy_version: 策略版本
credential_id: 实际使用的权限凭证
capability_id: 具体能力标识
environment: 运行环境
tenant_id: 租户或业务域
step_id: F01至F15
occurred_at: 业务发生时间
recorded_at: 事件记录时间
event_type: 事件类型
status: 事件状态
source_system: 来源系统
source_refs: []
evidence_refs: []
payload_digest: 内容摘要
data_quality:
  completeness: 完整度
  confidence: 置信等级
  verification: 已核验或待核验
```

### 15.1 必须输出的事件类型

| 事件类型 | 说明 |
|---|---|
| 运行初始化 | 版本、环境和策略已锁定 |
| 能力识别 | 本次任务对应能力和范围 |
| 风险分类 | 风险和不可逆性结果 |
| 凭证校验 | 凭证通过或拒绝及原因 |
| 永久人工确认命中 | 自动执行被转人工 |
| 阶梯计划生成 | 单次任务步骤和边界 |
| 组合闸结果 | 各独立控制的回执 |
| 动作开始 | 准备产生或已经产生外部效果 |
| 动作结束 | 工具调用机械终态 |
| 业务验收 | 权威业务结果 |
| 运行结果入账 | 证据窗口新增条目 |
| 晋级申请 | 锁定证据和目标权限 |
| 晋级决策 | 批准、拒绝或失效 |
| 凭证签发 | 新凭证生效 |
| 凭证吊销 | 旧凭证失效 |
| 事故触发 | 严重事件开始 |
| 降级完成 | 权限已收回 |
| 运行关闭 | 本次运行终态 |

## 16. 数据补全接口

工作流可观测性探针可以返回三类对象：

### 16.1 数据缺口单

用于说明执行流程缺少哪些可观测数据。

```yaml
gap_id: GAP_唯一标识
trace_id: 对应链路
run_id: 对应运行
missing_fields: []
missing_events: []
impact:
  - 无法重建权限判断
  - 无法确认业务终态
requested_sources: []
priority: 严重或高或中或低
```

### 16.2 证据补全包

用于附加来自权威来源、且已经核验的事实。

```yaml
completion_id: COMPLETION_唯一标识
run_id: 对应运行
source_system: 权威来源
source_refs: []
verified_by: 核验者
verified_at: 核验时间
fields:
  business_outcome: 业务终态
  evidence_ref: 证据引用
  occurred_at: 真实发生时间
content_digest: 内容摘要
verification_status: 已核验
```

### 16.3 治理建议

用于提出但不直接执行的建议，例如：

- 暂停晋级。
- 缩小受限级范围。
- 延长影子运行。
- 吊销疑似失效凭证。
- 增加某类任务切片。
- 对某一能力触发人工复核。

执行流程必须把建议转化为正式治理动作后才能改变权限状态。

## 17. 独立运行模式

在没有工作流可观测性探针时，本执行流程仍可独立运行。

### 17.1 最小依赖

- 能力注册表。
- 权限策略库。
- 权限凭证存储。
- 业务事实源。
- 审批服务或人工审批接口。
- 执行拦截点。
- 追加式运行结果账本。
- 事故冻结和凭证吊销能力。

### 17.2 最小输出

- 当前运行上下文。
- 能力和范围判断。
- 凭证校验回执。
- 组合闸回执。
- 业务验收回执。
- 运行结果。
- 证据窗口状态。
- 权限状态变化。

### 17.3 无探针时的限制

- 无法自动发现链路缺口和跨系统时钟问题。
- 无法完整计算跨运行趋势。
- 证据多样性、过期和重复问题更依赖执行侧内建检查。
- 事故还原和权限变化审计成本更高。

因此，独立运行不等于可以省略事件记录。

## 18. 与工作流可观测性探针交互

### 18.1 联动流程

```text
执行流程输出事件、工件、回执和权限变化
  ↓
探针旁路采集并重建运行史
  ↓
探针检查缺口、版本、证据、限额、晋级和降级
  ↓
探针输出指标、发现、数据缺口单和补全包
  ↓
执行流程验证补全包来源和完整性
  ↓
已核验事实进入观测账本或证据账本
  ↓
治理建议进入正式审批或事故流程
```

### 18.2 交互边界

探针可以：

- 补充缺失的事件关联。
- 从权威系统取回业务终态。
- 标记证据重复、过期或失配。
- 重建晋级和降级时间线。
- 建议暂停、降级或重新评审。

探针不能：

- 直接把观察级改为受限级。
- 直接签发权限凭证。
- 用推断结果覆盖真实业务结果。
- 删除失败记录。
- 绕过审批门、预算限制或执行拦截点。

### 18.3 补全事实的接纳等级

| 等级 | 含义 | 是否可用于权限判断 |
|---|---|---|
| 已核验事实 | 来自权威来源，引用可解析，经过受信验证 | 可以 |
| 待核验事实 | 来源存在但尚未独立验证 | 不可以直接用于晋级 |
| 推断事实 | 由日志关系或统计模型推断 | 只能用于调查和告警 |
| 不可用 | 来源冲突、内容摘要不一致或无法定位 | 不可以 |

## 19. 不同拓扑下的适配

### 19.1 链式

最适合本模式。每一步通过后才进入下一步，适用于付款、写库和发布。

### 19.2 路由

根据能力、风险、金额和异常类型，把请求路由到不同等级、不同审批者或人工处理队列。

### 19.3 并行

可以并行执行：

- 多个独立验证器。
- 多个业务切片评测。
- 多个只读检查。

最终权限决策必须收敛到单一、可审计的治理结论。

### 19.4 编排

由权限控制器协调审批门、预算、爆炸半径、幂等、执行适配器和证据记账。

### 19.5 循环

多次运行不断更新证据窗口；每次权限变化重新建立证据基线。

### 19.6 层级

父 Agent 只能把自己拥有的能力范围子集委派给子 Agent。禁止“父级没有权限，子级却获得更大权限”。

每次委派必须绑定：

- 父凭证。
- 子能力范围。
- 子任务目标。
- 有效时间。
- 最大外部效果。
- 结果回收和责任归属。

## 20. 场景适配模板

### 20.1 付款与结算

| 项目 | 建议设计 |
|---|---|
| 能力拆分 | 读取账本、计算金额、生成提案、提交小批次、提交整批 |
| 影子证据 | 与人工结算逐项比对人员、金额、异常和冲正 |
| 受限范围 | 部门、人数、总金额、单笔金额、银行账户集合 |
| 永久人工确认 | 变更收款账户、重大资金调拨、异常受益人 |
| 事故触发 | 重复付款、越额、错付、跨部门或使用失效凭证 |

### 20.2 发信与消息触达

| 项目 | 建议设计 |
|---|---|
| 能力拆分 | 生成草稿、选择收件人、发送单封、发送小批次、批量发送 |
| 影子证据 | 与人工发送清单和内容对照，不真正发出 |
| 受限范围 | 允许域名、收件人数、模板、发送时段、每日额度 |
| 永久人工确认 | 法律通知、重大舆情回应、全员公告 |
| 事故触发 | 发错对象、泄露敏感信息、重复群发、绕过退订规则 |

### 20.3 数据库写入

| 项目 | 建议设计 |
|---|---|
| 能力拆分 | 读库、生成变更集、测试库执行、预生产执行、生产小批次写入 |
| 影子证据 | 生成预计变更集并与真实人工变更对照 |
| 受限范围 | 表、字段、行数、租户、事务时长、时间窗口 |
| 永久人工确认 | 不可恢复删除、权限表修改、跨租户批量更新 |
| 事故触发 | 超行数、跨租户、无事务、回滚失败、重复写入 |

### 20.4 代码与发布

| 项目 | 建议设计 |
|---|---|
| 能力拆分 | 读取代码、生成补丁、运行测试、部署测试环境、小流量发布、扩大流量 |
| 影子证据 | 生成补丁和发布计划，不合并、不部署生产 |
| 受限范围 | 仓库、分支、服务、区域、流量比例、持续时间 |
| 永久人工确认 | 核心身份系统、不可逆迁移、重大安全策略变更 |
| 事故触发 | 测试绕过、错误版本、异常率突升、回滚失败 |

### 20.5 客服与退款

| 项目 | 建议设计 |
|---|---|
| 能力拆分 | 查询订单、生成回复、生成退款建议、小额退款、常规退款 |
| 影子证据 | 与人工客服处理结果对照 |
| 受限范围 | 单笔金额、日累计、客户等级、退款原因、商品类型 |
| 永久人工确认 | 关闭账户、重大赔偿、欺诈争议和法律投诉 |
| 事故触发 | 重复退款、错误账户、超过额度、跳过风控检查 |

## 21. 失败处理与补偿

| 失败类型 | 处理方式 |
|---|---|
| 输入缺失 | 停止推进，生成缺失信息清单 |
| 能力无法识别 | 路由人工或模式维护者，不猜测能力 |
| 无有效凭证 | 拒绝执行，输出所需权限和当前权限差异 |
| 凭证范围不足 | 缩小请求、拆批或转人工审批 |
| 组合闸失败 | 保留各闸回执，不得只输出统一失败码 |
| 演练失败 | 不进入真实执行，记录为运行结果 |
| 业务结果未知 | 标记待核验，不计入晋级成功 |
| 重复请求 | 通过幂等键返回原结果或安全拒绝 |
| 部分成功 | 冻结剩余动作，执行补偿并单独记录每个对象结果 |
| 严重事故 | 立即冻结、吊销、隔离和建立事故后基线 |
| 探针补全冲突 | 以权威事实源为准，保留冲突记录，进入人工核查 |

## 22. 反模式

### 22.1 统一可信等级

只保存“Agent 已可信”或“Agent 得分 92”，无法表达具体能力和范围。

### 22.2 一次试点后开放全部工具

从只能建议直接跳到生产写入、发信、付款和部署。

### 22.3 用调用成功代替业务成功

接口返回成功，但真实付款、写库或发送结果没有核验。

### 22.4 只计算成功，不保留失败

删除或忽略失败会使证据窗口失真。

### 22.5 同一结果重复计数

通过改写描述或复制引用凑够晋级次数。

### 22.6 单一简单样本刷成绩

只在同一部门、同一金额段或同一类型任务中重复成功。

### 22.7 晋级审批与证据不绑定

审批者只点“同意”，没有看到锁定证据批次和目标范围。

### 22.8 事故后继续使用旧凭证

降级只改数据库等级，没有让执行点拒绝旧凭证。

### 22.9 探针直接改权限

可观测系统发现风险后直接写入权限状态，绕过正式治理流程。

### 22.10 把渐进承诺做成纯人工表格

所有证据依赖人工填报，导致证据滞后、重复和无法验证，系统长期停在试点阶段。

## 23. 验收测试

### 23.1 基础权限测试

1. 观察级请求真实写入，必须拒绝。
2. 建议级可以生成提案，但不能触发外部效果。
3. 影子级使用真实输入时，输出必须进入隔离位置。
4. 受限级在人数、金额或对象数上限内允许通过授权检查。
5. 受限级超过任一上限必须拒绝。
6. 自主级命中永久人工确认清单时必须转人工。

### 23.2 证据测试

1. 相同 `run_id` 不得重复计数。
2. 相同 `evidence_ref` 不得重复计数。
3. 事故前证据不得直接用于事故后恢复。
4. 旧模型、旧策略或旧环境证据不得自动继承。
5. 单一任务切片不足以满足多样性要求。
6. 待核验和推断事实不得作为晋级成功证据。

### 23.3 晋级测试

1. 只能从相邻等级申请晋级，除非策略明确允许跨级。
2. 证据窗口锁定后新增失败，旧申请必须失效。
3. 无权审批者批准时，凭证签发必须拒绝。
4. 审批范围小于申请范围时，只能签发审批范围。
5. 策略版本变化后，旧晋级申请必须重新评估。

### 23.4 降级测试

1. 严重事故触发后，相关能力应立即冻结。
2. 吊销通知到达后，旧凭证请求必须被执行点拒绝。
3. 降级应优先影响相关能力和范围，不应无理由全局停机。
4. 恢复必须从新基线重新积累证据。

### 23.5 组合闸测试

1. 审批通过但权限范围不足，必须拒绝。
2. 权限足够但预算不足，必须拒绝。
3. 权限和预算都足够但永久人工确认命中，必须转人工。
4. 所有闸通过后，“允许”只代表可以进入执行，不代表业务已经成功。

### 23.6 探针联动测试

1. 探针提供已核验业务终态，可被执行流程附加到运行结果。
2. 探针提供推断结果，不得触发晋级。
3. 探针建议降级，不得直接改写权限状态。
4. 补全包摘要不一致时必须拒绝接纳。

## 26. 实施结论

渐进承诺不是一个“可信度分数”，而是一套围绕具体能力运行的权限状态机。

它要求系统同时维护两条链：

```text
单次任务链：低风险动作 → 高风险动作
跨任务权限链：低等级 → 高等级
```

两条链都必须绑定版本、范围、证据和执行点校验。晋级依赖锁定、可核验、覆盖目标风险的证据；严重事故则优先冻结和吊销，再讨论恢复。

执行流程可以单独运行；接入工作流可观测性探针后，可以获得更完整的运行史、证据质量检查、数据缺口补全和趋势发现。但任何补全、指标或建议都不能绕过正式权限控制和治理责任。
