# Approval Gate Shared Contract / 审批门共享契约

Name / 名称: Approval Gate Binding and Observation Contract / 审批绑定与观测契约。
Description / 描述: Source-aligned object fields and local integration constraints for execution and independent probes. / 对齐来源的执行与独立探针对象字段及本地接入约束。

## Usage and version boundary / 用法与版本边界

Use with [execution](approval-gate-execution-flow.md), [probes](approval-gate-observability-probes.md) and the [source map](approval-gate-source-map.json). Local specification `0.1.0` preserves source contract `1.0.0`. All artifacts remain `specification_only`; there is no executable validator for business records in this addition. / 与执行、探针及来源映射共同使用；本地规格保留来源契约版本，所有资产仍为规格，本次未增加业务记录可执行验证器。

`PATTERN_GOVERNANCE_APPROVAL_0001` and `PATTERN_OBSERVABILITY_APPROVAL_0001` are source aliases, not new registry patterns. Keep `PATTERN_0047` and `COG_GOVERNANCE__TOP_ROUTING`; other source coordinates describe supporting responsibilities. Source contract `1.0.0` is not the same protocol as `GOV_BOUNDARY_OBS 1.0.0`, Tool Dispatch schemas, or collaboration profile `3.0.0`. An adapter must explicitly map types, enums, identities and digests; matching version strings do not establish compatibility. / 来源模式标识只是别名，不新建注册模式；保持原编号与主坐标，其他坐标表示支撑职责。同名版本号不证明不同协议兼容，适配器须显式映射类型、枚举、身份及摘要。

## Object fields / 对象字段

The following inventory preserves **all nested fields** from source execution §8 and probe §9. These are source example field vocabularies, not schemas that make every field universally mandatory or authorize placeholder values. Set applicability, null reasons, type/enum rules and required fields per event/action in the adopting adapter. Repeated `supplement` shapes describe one object; different example targets do not permit cross-run merging. / 以下保留执行第 8 节与探针第 9 节全部嵌套字段；它们是来源示例词汇，不是让所有字段无条件必填或允许占位值的 Schema。采用适配器须逐动作事件定义适用性、空值原因、类型枚举及必填字段。两处补全包描述同一对象，不同示例目标不意味着允许跨运行合并。

## Binding and canonicalization / 绑定与规范化

- Preserve `trace_id`, `run_id`, `intent_id`, proposal ID/version/digest, policy ID/version/digest, request/decision/receipt/checkpoint/execution/effect IDs, `idempotency_key` and `supplement_id`. Bind tenant and environment at the authenticated boundary; a guessed missing ID is a gap, not a new correlation fact. / 保留链路运行意图、提案策略版本摘要、各生命周期对象标识、幂等键及补全标识；在认证边界绑定租户环境；猜测标识只能是缺口，不能成为关联事实。
- Hash a versioned canonical semantic projection: actor/delegation, action/tool/version/environment, expanded parameters, stable target manifest and versions, quantity/amount/currency, conditions/window/order, effect scope, impact and reversibility. Bind referenced evidence and scope to immutable content digests, not mutable URI names. Resolve referenced bytes again before use. / 对版本化语义投影求摘要，纳入主体委托、动作工具版本环境、展开参数、稳定对象清单版本、数量金额币种、条件窗口顺序、效果范围、影响及可逆性；证据与范围引用绑定不可变内容摘要，不能只绑定可变 URI，使用前再次核验引用字节。
- Fix key order, decimal precision/units and alias expansion; reject non-finite numbers, ambiguous timestamps and unknown canonicalization profiles. Distinguish null from absent. Sort sets deterministically, but preserve semantically ordered arrays. Exclude only the digest itself, signatures and explicitly declared display/transport fields; do not exclude execution windows merely because they are timestamps. / 固定键序、金额精度单位及别名展开；拒绝非有限数、含糊时间及未知规范化版本；区分空与缺失。集合稳定排序，有业务顺序的数组保序。只排除摘要自身、签名及明确展示传输字段；执行窗口虽是时间也不能排除。
- Verify issuer/signature and trusted storage independently of matching hashes. Bind request and decision to the exact proposal/policy, role and permitted scope. Store immutable signed receipt claims separately from the transactional usage/revocation ledger; source `usage_count` is an observed ledger value, never a caller-editable entitlement. / 摘要一致之外独立验证签发者签名与可信存储；请求决定绑定精确提案策略、角色与范围。不可变签名回执与事务性消费撤销账本分开；来源 `usage_count` 是账本观测值，不能由调用者编辑以增加许可。
- Effective expiry is the most restrictive applicable request, policy, delegated authority and receipt deadline; never extend authority by signing later. The adapter declares clock source/skew and a boundary convention (recommended: valid only while `now < expires_at`). Recheck current roles and revocation at consumption. / 有效截止时间取请求、策略、委托权限及回执适用期限的最严格值，不能晚签来延长授权。适配器声明可信时钟、偏差及边界约定，建议仅严格早于截止时间有效；消费时重检当前角色和撤销。

## Event contract and source differences / 事件契约与来源差异

Emit immutable events for preparation, routing, approval, checkpoint/resume, revalidation, consumption, execution/effect, compensation and probe exchange (source probe §7). Common fields are `event_id`, `event_type`, `event_version`, `occurred_at`, `recorded_at`, `trace_id`, `run_id`, `actor_ref`, `source_component`, `state_before`, `state_after`, `entity_version`, `payload_ref`, `payload_digest`, `causation_event_id`, `correlation_keys`, `sensitivity`, and `retention_class`. Add the applicable intent/proposal/policy/request/decision/receipt/checkpoint/execution/effect/supplement IDs and digests. / 各生命周期阶段均发不可变事件；公共字段及适用对象引用如上，保留发生与入库时间、因果、前后状态、负载摘要、敏感度与留存级别。

Identifiers for objects not yet created may be null with an explicit reason; a required missing binding remains a gap. Deduplicate on authenticated tenant/source and immutable event identity; identical replay is harmless, same-ID/different-payload is quarantined. Producer sequence and causal references determine order; arrival order and cross-system wall clocks alone do not. / 未创建对象标识可空但需原因，必要绑定缺失仍是缺口。按认证租户来源及不可变事件身份去重；同内容重放无害，同标识异内容隔离；依据生产者序号及因果判断顺序，不能只凭到达顺序或跨系统时钟。

## Supplement exchange / 补全交互

1. Execution or probe identifies a gap and creates a bounded request specifying authenticated tenant/run/target, expected entity version and proposal/policy digests, allowed fields/sources, freshness, deadline, query budget and retry limit. / 执行或探针发现缺口，创建有界请求，绑定认证租户运行目标、预期对象版本及提案策略摘要、字段来源白名单、时效期限、查询预算与重试上限。
2. Probe queries only authorized sources, preserving original fact time, retrieval time, source version/digest, conflicts, collection method and per-field kind: `observed`, `derived`, `confirmed`, `inferred`. A high confidence score never establishes authority. / 探针只查询获准来源，保留原事实时间、检索时间、来源版本摘要、冲突、采集方法及逐字段观测派生确认推断类别；高置信度不能授予权限。
3. The receiver authenticates the sender, validates content digest, request binding, current target revision, expiry, freshness, field allowlist and sources. Reject replay with different bytes and cross-scope/stale targets. Accept identical retries idempotently. `inferred` remains advisory. / 接收方认证发送者，验证内容摘要、请求绑定、当前目标修订、有效期新鲜度、字段白名单及来源；拒绝异内容重放、跨范围和旧版本，相同重试幂等；推断只作提示。
4. Append accepted fields to `observation_enrichment`; never overwrite original facts, signed receipt claims, proposal/policy, decision, usage, execution state or effect truth. Recovering an existing signed approval is an authority-system lookup, not probe-created approval. / 采纳字段只追加观测补全层，不覆盖原事实、签名回执、提案策略、决定、使用次数、执行状态或效果真值；找回既有签名批准属于授权系统查询，不是探针生成批准。
5. Record `accepted`, `partially_accepted` or `rejected` in a per-field adoption receipt with supplement ID/digest, target version, processor identity/time, accepted/rejected fields and reasons. A field conflict cannot be hidden by partial acceptance. Semantic changes require a new proposal/version and new routing. / 逐字段采纳回执记录接受、部分接受或拒绝，绑定补全标识摘要、目标版本、处理者时间及逐字段原因；部分接受不能隐藏冲突。改变语义须新提案版本及重新路由。
6. Supersede/revoke a supplement through a new audit record, retaining its original content and adoption history. Reassess downstream conclusions that depended on withdrawn evidence. / 用新审计记录替代或撤回补全包，保留原内容及采纳历史，重新评估依赖撤回证据的结论。

Trusted source priority is original systems, signed ledgers, same-run events, external queries, verified snapshots, authenticated human confirmation, reproducible derivations, then unverified leads. Priority never overrides conflicts, scope or freshness. / 来源优先级为源系统、签名账本、同运行事件、外部查询、核验快照、认证人工确认、可重算推导、未核验线索；优先级不能覆盖冲突、范围及时效限制。

## Constraints and adoption / 约束与采用

An optional offline/sidecar probe can be absent while execution retains complete local controls and minimum audit. If a host explicitly configures a mandatory synchronous data precheck, timeout/missing mandatory evidence blocks that affected action according to policy; it does not grant the probe approval authority. A control suggestion must be independently evaluated by an authorized service. / 可选离线或旁路探针缺席时，执行方仍维持全部本地控制及最小审计；若宿主显式配置必要同步数据检查，超时或必要证据缺失按策略阻断受影响动作，但不授予探针审批权。控制建议由有权服务独立核验。

Before claiming production readiness, implement and test actual authenticated identities, signed immutable bindings, role/quorum history, durable checkpoint restart, atomic receipt/idempotency admission, dispatch fencing, crash reconciliation, partial-effect compensation and append-only probe adoption. Document tests alone cannot promote this pattern or increment its business evidence counts. / 宣称生产就绪前，须实现并测试真实认证身份、签名不可变绑定、角色会签历史、检查点重启、原子回执幂等准入、派发约束、崩溃对账、部分效果补偿及只追加补全采纳；文档测试不能晋升模式或增加业务证据计数。
